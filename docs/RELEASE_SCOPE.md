# 첫 출시 범위

상태: 사용자 채택 완료 · 범위 확정. 아래 기능은 출시 목표이며 구현 완료를 의미하지 않는다.

## 확정한 접속 방식과 순서

- 사용자 PC에서 호스팅하고 사내 Wi-Fi를 통해 접속한다.
- username만 정하고 입장하며 계정 인증과 역할별 권한을 두지 않는다.
- 기본 설계·저장 기능을 완성한 이후 동시 편집과 복원을 추가한다.
- 확장 인증은 이후 필요에 따라 결정한다.

아래 기능 묶음을 첫 출시의 개발·검증 기준으로 채택한다. 기능을 추가하거나 후속 기능을 앞당길 때는 출시 범위 변경으로 기록한다.

## 첫 출시의 목표

사용자가 접속해 도메인 간 관계를 먼저 그리고, 각 도메인 안의 테이블을 설계한 뒤 저장하고 다시 열 수 있어야 한다. 새로 시작한 하나의 설계를 끝까지 작성할 수 있는 사용 흐름을 완성한다.

저장한 설계에 댓글과 @멘션으로 검토 대화를 남기는 기능도 첫 출시에 포함한다. 실시간 ERD 동시 편집·이력 복원의 후속 일정은 유지한다.

## 첫 출시 포함 기능

| 영역 | 첫 출시에서 할 수 있는 일 |
| --- | --- |
| 입장 | username 설정·변경, 브라우저에서 이름 기억 |
| 프로젝트 갤러리 | 프로젝트 생성·목록·검색·이름 수정·보관 |
| 도메인 맵 | 도메인 생성·수정·이동·삭제, 이름과 방향이 있는 관계 연결 |
| 자유 텍스트 | 텍스트 박스 삽입·편집·이동·크기 조절·삭제 |
| 캔버스 배경 | 도메인 맵과 내부 ERD에 밝은 배경의 작은 점 격자 적용 |
| 도메인 진입 | 클릭 시 확대 전환, 돌아갈 때 이전 화면 위치 유지 |
| 테이블 ERD | 테이블·컬럼 생성·수정·이동·삭제, 키와 관계 설정 |
| 논리·물리 특성 | 함께 / 논리 / 물리 보기, 적용 범위, 독립적인 이름·특성 편집 |
| 타입·추가 항목 | PostgreSQL 타입, 길이·정밀도, 필수 여부, 기본값·설명, 사용자 정의 메타데이터 |
| 도메인 간 참조 | 다른 도메인의 테이블을 원본 참조로 연결하고 소유 도메인 표시 |
| 저장 | 서버 저장, 저장 중·완료·실패 표시, 다시 열기 |
| 기본 DDL 내보내기 | 지원하는 물리 테이블·컬럼·PK·UNIQUE·FK 정의를 PostgreSQL 생성 SQL로 다운로드 |
| 검토 대화 | 캔버스 댓글 핀, 답글, @멘션, 앱 내 알림, 해결·다시 열기 |

## DDL 범위를 구분하는 이유

- **내보내기:** 앱에서 이미 구조화한 설계를 CREATE TABLE 등의 SQL로 생성하는 기능이다.
- **가져오기:** 기존 SQL 파일을 해석해 테이블과 관계를 복원하는 기능이다. 지원 SQL 문법, 기존 프로젝트 병합, 이름 충돌 처리까지 필요하므로 별도 기능으로 다룬다.
- **변경 SQL:** 이전 설계와 현재 설계를 비교해 ALTER TABLE 등을 생성하는 기능이다. 초기 생성 SQL보다 변경·데이터 보존 규칙이 많이 필요하다.

첫 출시는 생성 SQL 내보내기를 포함한다. 지원 타입·제약은 구현 시 목록으로 명시하고, 아직 처리하지 못하는 항목은 진단으로 알려준다. 자유 입력을 허용하는 것과 모든 PostgreSQL 문법을 내보낼 수 있다는 것은 구분한다.

논리 전용 객체와 도메인 업무 관계는 DDL에 포함하지 않는다. 논리 다대다 관계는 물리 연결 테이블을 직접 설계한 경우에만 그 테이블·FK를 출력한다. 복합 키·순환 참조 등 구조적으로 가능한 경우도 처리하거나 명확히 미지원으로 표시해야 한다.

## 첫 출시에서 제외하고 후속으로 진행할 기능

| 영역 | 기능 |
| --- | --- |
| 협업 | 실시간 공동 편집, 다른 사람의 커서와 선택, 변경 병합 |
| 복원 | 실행 취소·다시 실행, 변경 이력, 이전 버전 복원 |
| 기존 DB 활용 | DDL 가져오기, 실제 DB 연결과 역공학, 이전 설계 대비 변경 SQL 생성 |
| 큰 모델 탐색 | 모든 도메인의 전체 ERD, 자동 배치, 고급 필터 |
| 고급 PostgreSQL | 뷰·트리거·파티션·함수·복잡한 인덱스와 사용자 정의 타입 생성 |
| 운영 확장 | SSO, 역할별 권한, 외부 알림, 외부 공개 |

## 저장과 동시 편집의 차이

첫 출시에서도 서버에 저장한 설계를 다른 사람이 열어보고 댓글·답글·멘션을 남길 수 있다. 같은 ERD 화면에 설계 변경을 즉시 반영하고 충돌을 합치는 기능은 이후에 추가한다.

첫 버전에서는 같은 프로젝트를 여러 사람이 동시에 수정하는 작업을 지원 대상으로 두지 않는다. 저장 시 버전을 확인하여 오래된 화면이 최신 저장을 조용히 덮어쓰지 않게 하는 기본 장치는 구현 설계에서 별도 검토한다. 이는 실시간 변경 병합과 구분된다.

설계 저장과 다시 열기는 첫 출시의 기본 기능이다. 이전 편집 상태로 되돌리는 이력 복원은 후속 기능이다.

댓글·답글은 설계 문서 저장과 별도 API·레코드로 관리한다. 다른 사람이 추가한 댓글을 오래된 ERD 전체 저장으로 덮어쓰지 않는다. 댓글과 알림은 첫 버전의 조회·갱신 흐름으로 제공할 수 있으며, 실시간 ERD 협업 도입을 선행 조건으로 두지 않는다.

## 댓글·멘션의 첫 출시 범위

- 빈 공간에 핀을 놓거나 도메인·테이블에 댓글을 연결한다.
- 스레드에서 본문·작성자·작성 시각·답글을 확인하고 해결·다시 열기를 수행한다.
- 사이트에서 username을 설정한 사용자 목록에서 @멘션 대상을 선택한다. username과 별도로 내부 ID를 참조한다.
- 앱 내 알림에서 해당 프로젝트·화면·댓글 위치로 이동하고 읽음 상태를 표시한다.
- 객체 이동 시 댓글이 따라가고, 객체 삭제 시 댓글을 보존하여 '대상 삭제됨' 상태를 표시한다.
- 역할별 권한과 이메일·Slack 알림은 포함하지 않는다. 댓글 편집·삭제 및 일반 답글 알림의 세부 규칙은 구현 시 정한다.

## 출시 완료 기준

- [ ] 사내 Wi-Fi에서 호스팅 PC의 서비스 주소로 접속하고 username을 설정한다.
- [x] 프로젝트를 만들고 주문·결제 도메인 및 '결제 요청' 관계를 작성한다.
- [x] 업무 설명 텍스트를 배치하고 주문 도메인에 들어가 테이블과 컬럼을 만든다.
- [x] 논리명·물리명·타입을 설정하고 도메인 사이의 필요한 테이블 참조를 연결한다.
- [x] 저장 후 브라우저를 닫았다 열어도 모델과 배치가 유지된다.
- [x] 다른 브라우저에서 같은 저장 내용을 열 수 있다.
- [x] 도메인 맵과 내부 ERD의 점 격자가 이동·확대·축소 시 캔버스 좌표에 맞춰 표시된다.
- [x] 캔버스 댓글·답글·해결 상태가 저장되고 다른 사용자가 조회할 수 있다.
- [x] 다른 사용자를 멘션하면 대상의 앱 내 알림에 나타나며, 알림에서 댓글 위치로 이동한다.
- [x] 테이블 이동·삭제 뒤에도 연결된 댓글의 위치 또는 대상 삭제 상태가 올바르게 표시된다.
- [x] 지원 범위의 PostgreSQL DDL을 내보내고 검증용 DB에서 실행할 수 있다.

로컬 자동 테스트와 별도 브라우저 검증을 기준으로 기능 항목을 확인했다. 실제 사내 Wi-Fi의 다른 장치 접속은 실행 확인 후 체크한다. 검증 명령과 범위는 [구현 진행 기록](./IMPLEMENTATION_PROGRESS.md)에 있다.

위 흐름 외에도 포함 기능 표의 생성·수정·삭제·검색·보관·보기 전환·오류 표시를 검증한다. 체크 표시는 실제 검증 완료 후에만 갱신한다.

검증용 DB에서의 DDL 실행은 개발·테스트 절차이며, 앱이 사용자 DB에 직접 SQL을 적용하는 기능을 첫 출시에 포함한다는 의미는 아니다.
