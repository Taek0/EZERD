# 히스토리 패널 개선

작성일: 2026-09-15

## 구현

- `이력` 버튼과 제목을 `히스토리`로 바꾸고 주변 도구와 같은 공통 Button을 사용했다.
- native details 메뉴를 DialogTrigger, UntitledPopover, Dialog 구성으로 교체했다. 공통 팝오버의 열기·닫기 애니메이션, Escape 닫기, 포커스 복귀와 화면 경계 보정을 사용한다.
- 메뉴의 너비와 높이를 화면 및 사용 가능한 공간 안으로 제한하고 내부 스크롤을 허용했다.
- 변경·삭제·미반영 편집의 원시 경로와 JSON 미리보기를 히스토리 요약 함수에 연결했다. 안내·충돌 사유에도 메시지 정리를 적용했다.
- 변경자와 기존 한국어 짧은 날짜·시간 형식을 유지했다. 복원·재적용·폐기·변경 내용 복사의 기존 콜백과 데이터는 유지했다.
- SSR 회귀 테스트를 패널 내용과 실제 메뉴 트리거로 나누고 UUID 비노출 및 변경자·일시 보존을 검증하도록 확장했다.

## 검증

- 담당 TypeScript, CSS, 테스트 파일의 Prettier 검사 통과.
- `git diff --check` 통과.
- `sync-history-labels.ts`를 통합해 객체명·동작·속성·변경 전후 값을 설명한다. 현재 문서에 없는 삭제 객체는 삭제 당시 값과 다른 히스토리 항목에서 이름을 찾고, 이름을 찾을 수 없으면 UUID 대신 일반 명칭을 사용한다.
- 삭제 미리보기는 이름·설명·타입·NULL·comment 등 사용자가 이해할 값만 표시한다. 원시 JSON과 시스템 경로·UUID는 화면에 표시하지 않으며 복사용 원본 데이터는 유지한다.
- 선택 속성 제거를 객체 삭제로 분류하지 않도록 회귀 테스트 후 수정했다.
- 요약·패널·관계 라벨 관련 회귀 26개 통과. 전체 pnpm check의 포맷 검사·타입 검사·단위 테스트 230개·빌드 통과. 기본 검사에서 DB 연동 테스트 19개는 제외된다.
- 브라우저에서 1024×600 및 390×844 메뉴 배치·내부 스크롤·닫기, 열림/닫힘 애니메이션, UUID 비노출과 변경자·일시 포맷을 확인했다. 페이지 오류는 없었다.
