# 캔버스 성능 개선 제안 문서화

테이블 증가에 따른 성능 개선 후보 6개, 적용 원칙과 측정 순서를 planning 문서에 간단히 정리했다. 실제 병목 측정이나 코드 변경은 하지 않았다. 브라우저 자동화 없이 계산 계측부터 진행하는 방침을 명시했다.

## 측정·완료 기준 보완

- 계획 문서에 테이블 수·컬럼 수·관계 밀도를 조합한 12개 고정 데이터셋, 환경 기록, 준비 실행·반복 측정 방법을 추가했다.
- 동작별 시간·렌더·계산 횟수 지표와 중앙값·p95 기록 방법을 정리했다. 계산 계측과 수동 화면 측정을 구분하고 미측정 항목을 명시하도록 했다.
- 병목 계산 p95 20% 개선, 다른 시나리오 p95 10% 초과 악화 시 재확인 등 잠정 목표를 제안했다. 실제 측정 전의 목표이며 실측 성과가 아님을 명시했다.
- 기준 측정부터 종합 확인까지 단계별 완료 조건과 정확성 회귀 확인 항목, 결과 기록 양식을 추가했다.
- 실제 코드 변경, 벤치마크 실행, 브라우저 자동화 및 수동 화면 프로파일링은 수행하지 않았다.

## 검증

- `pnpm format` 실행 완료. 코드 파일의 추가 변경은 없었다.
- `pnpm format:check` 통과. 문서는 `.prettierignore`에 의해 검사 대상에서 제외되므로 문서 자체는 내용과 표 구조를 직접 검토했다.
- `git diff --check` 통과. 변경 범위는 계획 문서와 이 작업 기록뿐이며 `docs/EZERD.txt`는 수정하지 않았다.

## 현재 저장소 상태 반영

- 로컬 `main`의 `4b0091b`와 변경 없는 작업 트리를 기준으로 코드·최근 커밋·작업 기록을 검토했다. 원격 fetch는 수행하지 않았다.
- 카드 밀도·10% 축소·사이드바 스크롤·도메인 묶음 배치·관계 이름 충돌 회피의 기존 구현과 성능 계획의 미착수 단계를 구분했다.
- `Canvas.tsx`, `TableEditor.tsx`, `table-geometry.ts`, `TableRelations.tsx`의 반복 조회·치수·관계 입력 계산을 계측 후보로 구체화했다. 도메인 관계의 기존 Map과 경로 탐색의 호출 내부 캐시도 구분했다.
- 프레임 입력 병합, 화면 밖 카드 생략, 배율별 간소화, 목록 가상화는 현재 관련 구현에 없음을 확인했다. 실제 병목·렌더 횟수는 측정하지 않았다.
- PNG가 현재 DOM을 복제하며 관계선의 `visibleNodeIds`가 연결 및 장애물 필터에도 사용되는 점을 반영했다. 전체 뷰 데이터와 DOM 표시 대상을 분리하고 전체 상세 PNG를 보존하는 작업을 표시 제한의 선행 조건으로 추가했다.
- 최근 도메인 배치·관계 이름·타입별 기본값 편집을 측정 및 회귀 확인 범위에 반영했다. 기존 42개 테이블 fixture와 단위 테스트 결과를 성능 기준값으로 취급하지 않도록 명시했다.
- `pnpm format`, `pnpm format:check`, `git diff --check` 통과. 문서는 포맷 제외 대상이므로 내용과 참조 파일을 직접 대조했다. 코드 변경은 없으며 테스트·벤치마크·브라우저 실행은 수행하지 않았다.
