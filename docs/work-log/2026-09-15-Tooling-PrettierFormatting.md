# 워크스페이스 코드 포맷 정리 및 검증

작성일: 2026-09-15

Prettier 설정 도입 후 직접 관리하는 소스·테스트·스크립트·설정 157개를 포맷했다. 긴 JSX 속성, 한 줄 함수, 객체·조건식·CSS를 공통 형식으로 정리했다. 검사 대상 175개 중 이미 형식이 맞는 파일은 변경하지 않았다. 첫 포맷 후 두 파일은 추가 적용이 필요했으며 재적용 후 안정성과 format:check 통과를 확인했다.

검증 결과:

- pnpm format:check 통과.
- pnpm check 전체 통과: 포맷 검사, 워크스페이스 타입 검사, 단위 테스트 217개, 프로덕션 빌드.
- 명시적으로 실행해야 하는 DB 연동 테스트 19개는 기본 검사에서 제외됐다. 이번 포맷 작업으로 DB나 서비스 상태를 변경하지 않았다.
- 기존 대형 웹 번들 경고는 유지된다.
- 포맷 전후 JavaScript/TypeScript 145개를 실행 구문 기준으로 비교했다. 괄호·결합 가능한 논리 연산자 묶음·동일하게 렌더되는 인접 JSX 문자열 표현을 정규화한 비교에서 차이가 없었다. JSON 값도 동일했다.
- 포맷 전 기존 변경 19개를 보관해 비교했다. 문서 및 README는 바이트 단위로 유지했다. scripts/document-versions.mjs는 기존 경로 변경을 보존한 채 포맷했고, 커밋에는 HEAD 기준 포맷 결과만 넣어 기존 경로 수정 두 곳을 미커밋 상태로 남겼다.

사용법:

- pnpm format: 소스 형식 자동 정리.
- pnpm format:check: 변경 없이 형식 검사.
- pnpm check: 포맷을 포함한 기존 전체 검사.
- VS Code에서 추천된 Prettier 확장을 설치하면 지정 언어의 저장 시 포맷 설정을 사용할 수 있다.

문서, 생성된 마이그레이션·스냅샷, lockfile, 외부 자산·라이선스, 빌드·캐시·DB 및 산출물은 제외 규칙을 따른다. 일반 문자열 내부에 담긴 긴 HTML/JavaScript fixture는 의도적으로 재작성하지 않았다.
