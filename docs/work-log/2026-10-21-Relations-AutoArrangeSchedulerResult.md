# 관계선 자동 정리 스케줄러 개선 결과

계획: [관계선 자동 정리 탐색 비용 개선 계획](../planning/2026-10-21-Relations-SearchPerformancePlan.md)

## 변경

- 자동 정리에서 전체 관계의 유효한 저비용 후보를 먼저 확보한다. 카드 관통·직교·연결점·출발 방향 및 여유 공간을 검증한다. 교차가 남았다는 이유만으로 최초 후보를 그래프 탐색으로 대체하지 않는다.
- 모든 장애물을 포함한 공유 컨텍스트를 사용한다. 최초 유효성 탐색에는 기존 관계의 교차 비용과 보조 차선 좌표를 넣지 않는다. 이 비용과 좌표는 전체 유효 경로를 확보한 뒤 제한된 개선 단계에서 사용한다.
- 다른 관계의 연결점 위치를 예약하면서 최대 16개 대체 면 조합의 저비용 후보를 검사한다. 같은 면의 빈 구간 중 출발 직선이 장애물과 충돌하지 않는 구간을 우선 선택한다. 앞선 보류 관계가 연결점을 옮겼다면 실행 직전에 빈 구간을 다시 계산한다.
- 초기 그래프 탐색은 관계별 최대 1,000 상태로 제한한다. 보류된 관계를 모두 순회한 뒤 남은 상태를 다시 배분한다. 일시적인 관계별 한도 도달이 뒤 관계의 탐색을 막지 않도록 전체 한도와 구분한다. 기본 전체 상태 한도 300,000은 유지한다.
- `maxSearches`는 저비용 후보 검사가 아닌 비싼 라우터 호출 횟수를 센다. 0이면 저비용 경로만으로 완성 가능한 배치를 반환할 수 있다. 기존 호출자의 관계 수 이상의 예산도 계속 유효하다.
- 자동 정리 전용 `maxDurationMs` 기본값은 10,000ms이며 0이면 즉시 만료된다. 완성 전 한도 도달은 실패이며 일부 경로를 성공으로 반환하지 않는다. 모든 관계가 완성된 뒤 개선 예산이 소진되면 유효한 전체 결과와 한도 도달 지표를 반환한다.
- 선택적 `diagnostics`는 탐색 횟수·상태·보류 수·기한·완성 수를 제공한다. 실패 시 비교용 부분 경로와 지표를 진단 필드에만 제공한다. 저장 및 네트워크 프로토콜은 변경하지 않는다.

## 검증

- 자동 정리 집중 회귀 테스트 23개 통과. 기존 밀집 배치, 연결점 간격, 직접 연결, 짧은 출발 직선, 자기 참조, 장애물 비관통, 렌더러 재생, 개선 점수 검사를 유지한다.
- 추가 검사: 그래프 예산 0인 완성 배치, 이미 만료된 기한의 원자적 실패, 개선 도중 기한 만료 시 전체 성공, 초기 관계별 한도 이후 다른 관계 및 잔여 예산 재시도, 최소 상태 예산의 원자적 실패, 공유 카드의 복수 보류 관계에서 연결점 중복 방지, 호출 예산이 정확히 마지막 시도에서 소진된 경우의 실패 분류.
- 고정 version 407 입력의 전체 238개 관계가 기본 300,000 상태 한도에서 완성된다. 부모 작업의 재빌드 측정은 약 1.01초, 152,284 상태, 라우터 106회였고 카드 관통·비직교·출발 방향·저장 경로 재생 위반은 모두 0이었다. 최종 반복 측정값은 통합 결과 문서를 따른다.
- 기존 구현은 동일 입력에서 191개 완료 후 실패했다. 같은 191개 관계만 비교하면 교차 1,094→1,200, 겹침 길이 261,102→215,094, 간격 위반 17→10, 꺾임 428→421, 길이 1,504,886→1,393,088이었다. 교차 수는 증가하고 겹침·간격·꺾임·길이는 감소하는 절충이 있다. 기존 실패 191개와 신규 전체 238개의 지표를 직접 비교하지 않는다.

일반 캔버스 라우팅은 자동 정리 API를 호출하지 않으며 신규 스케줄링 옵션을 적용하지 않는다. 이번 단위는 커밋하지 않고 부모 작업에서 관련 변경과 함께 검토·커밋한다.
