# 관계 준비 조회·카드 경계 재사용

작성일: 2026-09-28
기준: `4b7e4ae`, 브랜치 `feat/performance-measurement`.

## 구현

- 준비 호출당 table/column/view node/route 조회 인덱스, visible/domain Set, 관계 쌍의 lane 인덱스를 한 번 생성한다.
- 카드 경계는 NodeLayout 객체별 Map에 지연 저장한다. 관계 끝점과 장애물에서 같은 노드를 사용하면 치수 계산 결과를 재사용한다. 유효 관계가 없으면 경계를 계산하지 않는다.
- label 함수는 선택적인 컬럼 인덱스를 받을 수 있고 기존 호출자의 배열 검색 동작도 유지한다.
- 인덱스는 기존 find의 첫 일치 항목과 관계 쌍의 원래 순서를 보존한다. 노드 객체를 키로 사용하므로 ID가 중복된 비정상 입력의 서로 다른 배치도 합쳐 버리지 않는다.
- 전역 캐시나 문서 간 캐시는 추가하지 않았다. 문서 변경마다 준비 결과를 갱신하는 기존 정책은 유지한다. 관계마다 장애물 배열을 필터링하고 경로를 탐색하는 비용은 여전히 남는다.

## 검증

- 기존 준비 함수를 테스트 전용 reference로 보존했다. 앱에서는 import하지 않는다. 6개 변형 × 3개 뷰 × 3개 scope × 2개 visible 조건에서 전체 결과 동등성을 비교했다.
- self/parallel/reverse/draft 관계, 수동 앵커·waypoint, 노드 크기·위치 변경, 여러 뷰, 중복 ID의 first-match 의미와 문서 불변을 확인했다.
- spy 검증에서 10개 노드의 전체 관계 준비는 tableCardSize 10회, visible 노드2개는 2회, 관계 없음은0회였다. 각 노드의 실제 치수 계산이 호출당 한 번 이하임을 확인했다.
- `pnpm check` 통과: 381개 통과, DB 관련25개 skip, 타입·포맷·일반 빌드 통과. 성능 빌드도 통과했다. 기존 큰 청크 경고는 유지된다.
