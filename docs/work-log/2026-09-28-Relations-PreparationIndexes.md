# 관계 준비 조회·카드 경계 재사용

작성일: 2026-09-28
기준: `4b7e4ae`, 브랜치 `feat/performance-measurement`.

## 구현

- 준비 호출당 table/column/view node/route 조회 인덱스, visible/domain Set, 관계 쌍의 lane 인덱스를 한 번 생성한다.
- 카드 경계는 NodeLayout 객체별 Map에 지연 저장한다. 관계 끝점과 장애물에서 같은 노드를 사용하면 치수 계산 결과를 재사용한다. 유효 관계가 없으면 경계를 계산하지 않는다.
- label 함수는 선택적인 컬럼 인덱스를 받을 수 있고 기존 호출자의 배열 검색 동작도 유지한다.
- 인덱스는 기존 find의 첫 일치 항목과 관계 쌍의 원래 순서를 보존한다. 노드 객체를 키로 사용하므로 ID가 중복된 비정상 입력의 서로 다른 배치도 합쳐 버리지 않는다.
- 전역 캐시나 문서 간 캐시는 추가하지 않았다. 문서 변경마다 준비 결과를 갱신하는 기존 정책은 유지한다. 관계마다 장애물 배열을 필터링하고 경로를 탐색하는 비용은 여전히 남는다.

## 검증

- 기존 준비 함수를 테스트 전용 reference로 보존했다. 앱에서는 import하지 않는다. 6개 변형 × 3개 뷰 × 3개 scope × 2개 visible 조건에서 전체 결과 동등성을 비교했다.
- self/parallel/reverse/draft 관계, 수동 앵커·waypoint, 노드 크기·위치 변경, 여러 뷰, 중복 ID의 first-match 의미와 문서 불변을 확인했다.
- spy 검증에서 10개 노드의 전체 관계 준비는 tableCardSize 10회, visible 노드2개는 2회, 관계 없음은0회였다. 각 노드의 실제 치수 계산이 호출당 한 번 이하임을 확인했다.
- `pnpm check` 통과: 381개 통과, DB 관련25개 skip, 타입·포맷·일반 빌드 통과. 성능 빌드도 통과했다. 기존 큰 청크 경고는 유지된다.
- 고정 커밋 기준 브라우저 편집/이동·팬 비교는 아래에 후속 기록한다.

## 고정 빌드 결과

실험 커밋 `fc9bda2`, dirty=false. 기준은 이전 공유 geometry 빌드 `5f6479a`다. 같은 Windows 장비의 in-app browser, viewport1440×900, locale ko, zoom1, 동일 fixture·입력 이벤트로 비교했다. 10개/컬럼5개는 준비1+반복3회씩, 50개/컬럼10개는 준비1+반복5회씩 수행했다.

| 시나리오 | 카드 치수 호출 전→후 | 관계 경로 호출 전→후 |
| --- | --- | --- |
| EDIT, 테이블10·컬럼5 | 120→30 | 10→10 |
| MOVE, 테이블10·컬럼5 | 480→120 | 40→40 |
| EDIT, 테이블50·컬럼10 | 2,600→150 | 50→50 |
| MOVE, 테이블50·컬럼10 | 10,400→600 | 200→200 |

50개에서 새 문서당 치수150회는 Canvas 노드 경계50회, 관계 준비50회, 카드 콘텐츠50회로 해석된다. 이번 범위는 관계 준비 내부 재사용이며 이 세 소비자 간 치수 공유는 아직 하지 않았다.

50개 반복5회에서 함수 inclusive 누적 시간의 중앙값은 다음과 같다.

| 시나리오 | 카드 치수 전→후 | 경로 탐색 전→후 |
| --- | --- | --- |
| EDIT | 49.6→3.2ms | 22.0→20.1ms |
| MOVE | 190.7→14.4ms | 86.7→92.8ms |

카드 치수 호출 감소는 모든 반복에서 동일했다. 경로 알고리즘은 바꾸지 않았으며 MOVE의 경로 시간은 오히려 소폭 증가했다. 기준/실험을 교차 실행한 ABBA가 아니고 계측·기기 변동이 있으므로 이 차이로 경로 성능 개선이나 악화를 확정하지 않는다. 전체 화면 응답 시간·FPS 개선율도 주장하지 않는다.

## 정확성·회귀와 재현

- `compare-edit-move.mjs`에서 16개 유효 반복 쌍의 fixture·환경·입력 이벤트, 최종 문서 fingerprint, 전체 SVG path가 일치했다. 준비 실행은 비교 통계에서 제외했다.
- PAN은 문서 불변이며 카드 치수·관계·도메인 geometry 호출0회를 유지했다. `assertCameraReuse` 통과, 브라우저 error 로그 없음.
- 변경 전 결과: `artifacts/performance/5f6479a/`
- 변경 후 결과: `artifacts/performance/fc9bda2/`
- 비교 요약은 변경 후 폴더의 `comparison.json`, 팬 결과는 `pan-regression.json`, 화면 증거는 `indexed-geometry.png`다. 이 원시 산출물 폴더는 Git 제외 대상이다.

```powershell
node scripts/performance/compare-edit-move.mjs artifacts/performance/5f6479a artifacts/performance/fc9bda2
```

## 남은 범위

- 모든 관계에 대한 경로 탐색과 관계별 장애물 필터링은 계속 실행된다. 다음에는 전체 재계산 정확성 기준을 유지하며 영향받는 관계 범위를 조사하거나 100·300개 확장 측정으로 남은 병목을 확인할 수 있다.
- 메모리 실측, 실제 input-to-present, 전체 undo/실시간 동기화/PNG의 수동 회귀는 이번에 추가 수행하지 않았다. 변경된 doc마다 새 인덱스를 생성하므로 문서 간 캐시 무효화 문제를 새로 도입하지 않았다.
- 로컬 별도 브랜치에 구현·결과를 커밋하며 원격 push·main 병합은 수행하지 않는다. 테스트 탭과 이번 서버는 종료한다.
