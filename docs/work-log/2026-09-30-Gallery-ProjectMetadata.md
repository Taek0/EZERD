# 갤러리 프로젝트 메타데이터와 자동 이름 구현

- 이름 생략 또는 공백으로 생성하면 서버가 워크스페이스의 활성/보관 프로젝트 이름을 함께 확인해 `새 프로젝트`, `새 프로젝트 1`, … 을 지정한다. 기존 최대 번호 다음을 사용하며 수동 중복 이름 정책은 유지한다.
- 생성 권한 검사 시 워크스페이스 행을 처음부터 UPDATE 잠금으로 획득해 동시 자동 생성의 중복을 방지한다. 다른 쓰기는 기존 SHARE 잠금을 유지한다.
- 프로젝트 `databaseKind`에 PostgreSQL/MySQL/SQLite 선택 메타데이터를 저장한다. 기존 행과 생략 입력은 PostgreSQL이다. 이 선택은 물리 타입이나 DDL 생성 방언을 변환하지 않는다.
- HTTP/MCP 생성·수정·조회 및 파일 내보내기/가져오기에서 메타데이터를 보존하며 기존 전송 파일도 허용한다. 보관 프로젝트 편집 제한과 버전 검사를 유지한다.
- 실제 문서의 물리 테이블/관계 수와 테이블 2개 × 컬럼 3개의 미리보기를 응답에 포함한다.
- 마이그레이션 `0013_faulty_devos.sql`과 스냅샷을 생성했고, 루트 통합 검증 단계에서 `pnpm db:migrate`로 현재 설정된 DB에 적용했다. 기존 프로젝트는 PostgreSQL 기본값으로 유지되며 데이터 삭제는 없다.

## 검증

- 계약 빌드와 서버 typecheck 통과.
- 자동 이름/전송/계약 입력 경계 테스트 16개 통과.
- 신규 임시 PostgreSQL DB에서 마이그레이션 후 실제 동시 생성 4개, 보관 이름 충돌, 워크스페이스 범위, 수동 중복 유지, DB 종류 수정과 가져오기/내보내기, 구버전 파일, 보관 수정 제한 통합 테스트 2개 통과.
- 서버/계약 전체 테스트: 26개 파일, 131개 테스트 통과(별도 DB 통합 40개는 기본 실행에서 제외). MCP 응답 기본 필드에 따른 기존 fixture도 갱신했다.
- 테스트 DB는 기존 격리 실행기의 생성/제거 절차로 정리했다.
