# 관계 흐름 자동 배치 구현 결과

작성일: 2026-09-14

## 변경
- `autoLayoutView(document, viewId)`를 공유 모델에서 제공한다. UI의 명시적 명령에서만 호출한다.
- 도메인 개요는 도메인 관계, 테이블 뷰는 현재 배치된 테이블 관계를 기준으로 출발지에서 목적지로 왼쪽부터 배치한다.
- 강하게 연결된 순환 그룹을 먼저 구하고 그룹 간 최장 경로 순위로 열을 배정한다. 양방향·중복·자기 참조·독립 카드도 처리한다.
- 실제 카드 너비와 높이를 사용해 겹침을 방지한다. 입력 배열 순서에 영향을 받지 않는 결정적 배치이며 기존 카드 영역의 기준점은 유지한다.
- 현재 뷰의 외부 참조 카드도 포함하지만 원본 소유권, 다른 뷰 배치, 뷰포트, 메모는 그대로 유지한다. 메모가 차지한 높이 아래에 카드를 배치해 메모를 가리지 않는다.
- 반복형 그래프 탐색으로 긴 관계 흐름에서도 재귀 스택 한계를 피한다.

## 검증
- RED: 구현 전 `pnpm exec vitest run packages/model/src/layout.test.ts`가 모듈 부재로 실패함을 확인했다.
- GREEN: 같은 명령 5개 테스트 모두 통과했다.
- 분기 흐름과 실제 크기, 순환·양방향·중복·자기 관계, 순서 독립성과 재실행, 외부 참조·메모·다른 뷰 보존, 빈 뷰 및 알 수 없는 뷰, 3,000개 관계 체인을 검증했다.
- `pnpm --filter @ezerd/model typecheck` 통과.

계획: `../planning/2026-09-14-Editor-Implementation.md`의 관계 흐름 자동 배치 단위.

## 브라우저 회귀 보완
- 브라우저 검증에서 저장된 도메인 카드 높이 140과 화면 최소 높이 210이 달라 배치 후 카드가 겹치는 문제를 발견했다.
- 도메인 240×210, 테이블 280×220, 메모 높이 110의 실제 렌더링 최소값을 배치 계산에 적용했다. 기존 저장 크기는 변경하지 않는다.
- 회귀 테스트가 실제 겹침으로 실패함을 확인한 뒤 수정했다. 레이아웃 6개 테스트와 모델 빌드 통과.

## 이동한 캔버스의 배치 기준점 보완
- 현재 뷰를 멀리 이동한 상태에서 원점 부근으로 재배치되어 카드가 화면 밖으로 사라지는 문제를 검토에서 발견했다.
- 기존 카드들의 최소 X/Y를 기준점으로 유지한다. 메모 하단을 고려한 Y 보정도 재실행 시 누적 이동하지 않는다.
- 5,000/3,200 부근 카드와 이동된 뷰포트 회귀 테스트 RED→GREEN, 전체 7개 테스트 및 타입 검사 통과.
