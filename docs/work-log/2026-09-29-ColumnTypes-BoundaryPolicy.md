# 타입 정규화 및 저장 경계 검증 결과

## 구현

- 모델의 `normalizePhysicalType`, `normalizeDocumentPhysicalTypes`, `validatePhysicalType`을 공통화했다. DDL과 계약이 같은 매개변수 규칙을 사용한다.
- 별칭·대소문자·공백은 대표 타입으로 정규화한다. REAL·DOUBLE PRECISION·NUMERIC은 그대로 지원하고 ENUM 이름은 정규화하지 않는다.
- 길이는 VARCHAR/CHAR, 정밀도는 NUMERIC 또는 시간 타입, scale은 정밀도가 있는 NUMERIC에만 허용한다. 범위는 기존 PostgreSQL DDL 정책을 유지하며 NUMERIC의 음수 scale과 precision보다 큰 scale도 허용한다. SERIAL 배열과 ENUM의 길이·정밀도·scale은 거부한다.
- 저장/가져오기와 조회용 계약을 분리했다. 기존의 잘못된 매개변수 조합은 조회·동기화 기준점에서 읽어 수정할 수 있지만 새 문서 저장은 엄격하게 검사한다. 과거에 columns가 생략된 문서는 그 형태를 유지한다.
- MCP는 부분 명령 병합 후 전체 문서를 검증·정규화한 결과로 변경 목록을 만든다. 복원 경계에서도 파싱 결과를 실제 후보에 반영한다.
- 동기화는 원본 변경 목록을 검증한 후 기준/후보/저장 문서 타입을 정규화한다. 관련 없는 수정에 별칭 변환 이력이 추가되지 않으며 변조된 원본 변경 목록은 거부한다.
- Zod의 동일 형태 정규화에 overwrite를 사용해 MCP JSON Schema 도구 목록 생성과 호환되도록 했다. contracts의 model workspace 의존성을 추가하고 오프라인 설치로 lockfile을 갱신했다.

## 검증

- `pnpm check` 통과: 포맷, 전체 타입 검사, 테스트 481개 통과(25개 제외), 전체 빌드.
- 모델/DDL/계약 규칙 일치, legacy 별칭·잘못된 조합의 읽기 및 수정, ENUM 보존, 가져오기 전 검증, MCP 부분 수정, 실제 SyncService의 저장 및 변조 거부를 회귀 테스트로 확인했다.
- MCP 도구 목록 조회의 변환 스키마 호환성 실패를 재현하고 해결한 뒤 전체 검사를 다시 통과했다.
- 운영 DB 변환·마이그레이션·일괄 데이터 수정은 수행하지 않았다. DB 통합 테스트는 이번에 실행하지 않았다.
- 기존 Vite 번들 크기 경고는 남아 있다.

## 호환성

- 기존 별칭은 조회 결과에서 대표 표기로 제공되고 다음 정상 저장 시 반영된다.
- 잘못된 기존 타입 조합은 수정 후 저장해야 한다. 가져오기는 새 저장이므로 잘못된 조합을 거부한다.
- 미완성 설계의 알 수 없는 타입명은 기존처럼 보존한다. 따라서 지원하지 않는 타입명, 잘못된 참조·기본값 등 DDL의 모든 진단까지 저장 단계에서 금지하는 변경은 아니다.
