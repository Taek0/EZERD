# 관계선 자동 배치 순수 알고리즘

## 구현

- 직렬화 가능한 테이블·메모 경계와 관계 입력에서 관계별 네 면 앵커와 직교 경유점을 일괄 계산한다. 내부 source는 FK, target은 피참조 PK/UNIQUE 의미를 유지한다.
- 상대 카드 위치, 면의 사용량·길이·장애물을 고려해 면을 선택한다. 면별 연결점은 모서리 여백 안에서 상대 카드 순서대로 균등 배치하고, 공간이 부족한 면은 다른 면으로 분산한다.
- 기존 경로 계산기의 장애물 판정과 우회 탐색을 사용한다. 같은 카드 쌍에 대한 장애물 인덱스를 재사용하고, 이미 배치된 선 주변의 여유 통로를 후보 격자에 추가한다. 선 간 교차·중첩·간격을 경로 비용에 반영하고, 문제가 큰 경로만 제한된 후보와 A* 탐색으로 다시 계산한다. 후보 평가에는 해당 경로와 다른 경로 사이의 변화분만 계산한다.
- 카드 직후의 고정 길이 출구를 가능한 경우 줄인다. 줄인 결과가 다른 선과 충돌을 늘리면 기존 유효 통로를 유지한다. 저장 경유점을 기존 렌더러로 다시 계산했을 때 경로가 그대로 재생되는지 검사했다.
- 첫 버전의 계산 상한은 테이블·메모 합계 256개, 관계 1,000개, 관계별 경로 계산 총 2,048회, 격자 탐색 노드 총 300,000개다. 개선 단계는 기본 1회, 최대 3회다. 유효 경로가 없거나 입력이 잘못되면 일부 결과를 반환하지 않는다. `crowdedTableIds`는 실제 포트 간격이 12 미만인 카드에만 부여하고, 탐색 상한은 별도 지표로 보고한다.

## 검증

- `@ezerd/model` 타입 검사와 알고리즘 집중 테스트 7개를 통과했다. 균등 간격, 면 분산, 자기참조, 메모 회피, 저장 경로 재생, 입력 순서 독립성, 실패 시 일괄 거절, 121개 관계와 품질 점수 비악화를 확인한다. 기존 경로 테스트도 통과했다.
- 저장된 실제 문서의 물리 모드 전체 화면 경계(43개 테이블, 15개 메모, 61개 표시 관계)를 사용한 로컬 측정에서 자동 초기 해는 약 0.7초, 기본 개선 해는 약 1.8초였다. 측정 환경의 실행 간 변동이 있으므로 예산값으로 확정하지 않는다.
- 같은 측정에서 자동 초기 해의 교차 118개·중첩 길이 1,553·간격 위반 1개는 개선 후 교차 91개·중첩 길이 99·간격 위반 0개로 줄었다. 기존 저장 경로는 교차 53개·중첩 0·간격 위반 24개였다. 자동 결과는 선 간격과 길이·꺾임 수에서 이점이 있으나 교차 수는 기존 수동 조정 경로보다 많다. 최종 61개 경로 모두 기존 렌더러에서 경유점이 그대로 재생됐고 카드·메모 내부를 통과하지 않았다.
- 합성 121개 관계와 자기참조 1개를 포함한 테스트는 약 72 ms였다. 이는 초기 해만 계산한 값이고 실제 문서의 전체 품질·UI·저장 시간과 별개다.

## 남은 한계

- 면 선택은 결정적 탐욕 방식이다. 촘촘한 문서에서 모든 교차·중첩을 제거하지 못하며, 경로 개선 후보도 제한되어 있다. 실제 문서의 기존 수동 경로보다 교차가 늘어나는 사례가 확인됐다.
- 탐색 노드 한도나 시도 횟수에 도달해도 기존 유효 경로가 있으면 반환한다. `searchLimitReached`는 공간 부족을 뜻하지 않는다.
- Worker 메시지 복사와 화면 반영·서버 저장 시간은 이 순수 알고리즘 측정에 포함되지 않는다.
