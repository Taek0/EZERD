# UI 전체 구성 검토 결과

## 2026-10-12 사용자 결정 반영

- 모바일은 사용 플랫폼에서 제외한다. 이전에 관찰한 모바일 속성 패널 잘림은 수정 우선순위에서 제거한다. 데스크톱 결함으로 확대 해석하지 않는다.
- 논리 설계와 검증 항목의 기존 메뉴 위치를 유지한다. 해당 기능을 외부로 이동하거나 새로운 상시 배지로 노출하는 제안은 철회한다.
- 현재 우선순위는 데스크톱 시각 디자인이다. [데스크톱 디자인 검토](2026-10-12-UI-DesktopVisualReview.md)가 이 문서와 이전 보고서의 구현 순서 제안을 대체한다.
- 제품 UI 코드는 변경하지 않았다.

## 유지할 기본 구조

캔버스를 중심에 두고 우측에서 속성을 편집하며 필요할 때 핀 패널을 여는 구조를 유지한다. 갤러리도 별도 진입 화면으로 유지한다. 위치와 동작을 크게 바꾸기보다 색상·강조·정렬·여백을 먼저 정돈한다.

데스크톱에서 확인된 장점은 다음과 같다.

- 패널을 닫거나 너비를 조절해 작업 공간을 확보할 수 있다.
- 현재 보기와 선택 대상이 표시되며 기본 정보·컬럼·고급 옵션을 접어 볼 수 있다.
- 캔버스 도구와 배율 조작이 캔버스 가까이에 있다.
- 이전 1440×900 fixture에서 속성과 핀을 함께 열어도 캔버스 폭 약794px가 남았다.

## 현재 디자인 과제

1. 기존 입체 버튼 스타일 안에서 일반 동작·선택 상태·주요 동작의 시각적 강약을 구분한다.
2. 속성과 핀 패널의 헤더·여백·구분선을 같은 규칙으로 맞춘다.
3. 작은 보조 텍스트의 대비와 글자 크기를 정돈한다.
4. 캔버스 격자와 비선택 카드의 시각적 무게를 줄여 선택 대상과 관계선에 집중하게 한다.
5. 갤러리의 제목·미리보기·프로젝트 메타데이터 간 정보 밀도를 조정한다.

구체적인 근거와 후보 수치는 새 데스크톱 디자인 보고서에 기록했다. 기능을 메뉴 밖으로 이동하지 않아도 먼저 적용 가능한 과제들이다.

## 보류한 기능·구조 제안

- 목록에서 테이블을 선택하면 속성 탭으로 이동하는 동작은 2026-10-11 실제 컴포넌트에서 확인했다. 연속 탐색 개선과 포커스 처리는 별도 UX 과제로 남기되 디자인 우선 작업의 선행 조건으로 삼지 않는다.
- 새 프로젝트 생성 버튼의 상단 고정과 추가 목록 보기 도입도 별도 구조 변경이다. 현재 디자인 검토에서는 기존 갤러리의 제목·카드·새 프로젝트 카드 표현 개선을 먼저 다룬다.
- 알림 닫힘 중 재열기 입력 누락은 기존 동작 결함 기록으로 유지한다. [이전 검토](2026-10-11-UI-AppleDesignReview.md)를 참고하며 이번 시각 디자인 순위와 분리한다.

## 이전 검증 기록과 한계

- 최초 검토 브랜치: codex/apple-ui-review. 기존 결과 커밋: da79d1c.
- 실제 NativeProjectView에 두 테이블·한 도메인의 테스트 데이터를 공급한 격리 화면을 사용했다. 제품 서버 대신 가짜 세션과 조회 응답을 사용했다.
- 전역 헤더는 축약한 테스트용이며 내보내기 영역은 App의 공유 메뉴 대신 PNG fallback이었다. 절대 높이와 여백을 전체 운영 앱의 수치로 일반화하지 않는다.
- 1440×900, 1024×768과 당시 검토 범위였던 390×844를 확인했다. 390px에서 부모 grid 행보다 inspector 고정 높이가 커 본문이 잘렸으나 현재 지원 범위 밖으로 분류한다. 이는 현재 수정 제안이 아니다.
- 실제 스타일 로딩 순서를 맞추기 전 발생한 제목·저장 상태 겹침은 제품 결함으로 집계하지 않았다. fixture의 카드 겹침도 제품 결함으로 집계하지 않았다.
- 기존 패널 테스트 3개 파일, 10개 테스트 통과. 이전 UI 테스트 73개와 포맷 검사도 통과했다. 이 결과는 2026-10-11 검증 기록이며 이번에 재실행한 결과가 아니다.
- 최신 검토는 [계획](../planning/2026-10-12-UI-CompositionReviewPlan.md) 및 [새 디자인 계획](../planning/2026-10-12-UI-DesktopVisualReviewPlan.md)을 따른다.
