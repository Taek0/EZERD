# ERD 즉시 편집 UX 개선 결과

- [계획](../planning/2026-10-08-Editor-ImmediateEditingPlan.md)에 따라 UI 구현은 모두 gpt-6-astra/low 워커가 수행했다. 세션 오너는 파일별 범위 지정, 통합 검토, 전체 검사와 커밋을 담당했다.

## 변경

- 저장 요청·입력 초기화 버튼과 수동 처리기, 미사용 reset helper를 제거했다. 유효한 사용자 입력은 300ms debounce로 저장하며 포커스를 옮기거나 별도 저장 버튼을 누를 필요가 없다.
- IME 조합 중 입력, 미완성 입력, 복구 초안은 보존한다. 저장 실패는 무한 재시도하지 않으며 ACK가 최신 입력을 지우지 않는다. 삭제 등 파괴적 작업의 명시 확인과 외부 busy·권한·DB revision 보호는 유지한다.
- 생성 후 후속 입력은 같은 객체의 patch로 전환한다. ACK와 문서 갱신 순서 차이, 선택 이탈 및 저장 대기 중 추가 입력을 검증했다.
- 정상 컬럼 상태에도 무조건 표시되던 미검증 안내를 제거하고 일반 입력 오류와 실제 DB 기능 제한을 구분했다. 미지원 기능 정책 자체는 우회하지 않는다.
- 테이블 기본 정보의 소속 이동 버튼을 소속 도메인 드롭다운으로 교체하고 일반 필드 스타일을 적용했다.
- 카드 +는 빈 컬럼을 즉시 추가하고 이름 입력에 포커스를 준다. DB별 기본 타입·scope 계약을 유지한다.
- 카드 타입 검색어와 선택 ID를 분리하고 표시에서 DB 접두어를 제거했다. 브라우저에서 발견한 첫 글자 재선택과 portal 옵션 클릭의 캔버스 제스처 간섭도 수정했다.
- 컬럼명 → 타입과 파라미터 → 설명 순서로 정리했다. NULL → 기본값 → 배열 차원 옵션은 기본 접힘이다.
- 고급 인덱스·식 편집은 생성할 항목, 선택한 항목 편집, 생성할 식 종류를 계층화했다.

- 브라우저는 별도 로컬 PostgreSQL 임시 DB와 QA 서버에서 확인했다. [브라우저 QA 기록](2026-10-08-Editor-BrowserQAResult.md)과 [타입 검색 후속 검증](2026-10-08-TypePicker-BrowserFixResult.md)을 참조한다.
- 브라우저 검증은 Chrome/PostgreSQL 문맥이다. MySQL·SQLite 및 IME 조합의 모든 실제 환경을 수동 검증했다는 의미는 아니다.
- 기존 Vite 대형 청크 경고와 테스트 실행기의 Node shell 경고는 남아 있으나 검사 실패는 없다.
- 사용자 DB와 docs/EZERD.txt는 변경하지 않았다. 병렬로 들어온 Monya 파일 변환 기록은 별도 작업의 커밋이다.
- 브라우저 QA용 서버 프로세스와 해당 임시 DB는 검증 후 정리했다. 통합 회귀 DB는 기존 실행기가 정리했다.
- 실제 운영 배포는 이번 작업 범위에 포함하지 않았다.
