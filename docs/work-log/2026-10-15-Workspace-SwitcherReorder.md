# 워크스페이스 선택 및 순서 저장

## 변경

- 선택 목록을 메뉴 항목 안의 복합 입력에서 Dialog/Popover 및 선택 버튼·별도 드래그 핸들로 구성했다. 마우스 텍스트 선택과 잔류 포커스 장식을 정리하고 키보드 focus-visible을 유지한다.
- 오른쪽 핸들을 드래그하면 인접 항목이 스프링 모션으로 이동한다. 실제 브라우저 검증에서 이동하는 li의 포인터 캡처가 끊기는 문제를 재현하여 고정된 ol에 캡처와 이동/종료 처리를 배치했다.
- 키보드 Space/Enter로 이동 시작·확정, 방향키/Home/End로 순서 변경, Escape 취소를 지원한다. 드래그는 워크스페이스 선택으로 처리하지 않는다.
- PATCH /api/workspaces/order는 인증된 사용자 멤버십의 순서만 저장한다. 사용자 및 멤버십 행 잠금과 단일 CASE UPDATE로 원자적으로 변경하며 다른 사용자의 순서는 유지한다.
- 중복·유효하지 않은 ID와 타인 ID, 목록이 바뀐 오래된 요청은 거부한다. 저장 후 본인에게만 workspaces 변경 이벤트를 보내 다른 탭을 갱신한다.
- user_workspaces.sort_order를 추가하는 0018_workspace_order 마이그레이션을 작성했다. 저장되지 않은 새 멤버십은 뒤에 표시한다. 기존 사용자의 미정렬 목록은 기존 이름 정렬을 유지한다.
- 팝오버를 닫아도 이미 보낸 순서 저장 요청은 계속 처리한다. 오래된 응답은 새 목록에 덮어쓰지 않는다. 실패 시 기존 순서를 복원하고 오류를 표시한다.

## 검증

- 미구현 실패부터 재현한 계약·서비스 테스트 5개 통과. 새 임시 PostgreSQL DB를 생성해 마이그레이션·실제 저장·재조회·사용자 격리·새 공간 추가를 검증한 7개 테스트가 통과했고 임시 DB만 삭제했다. 사용자 DB는 수정하지 않았다.
- 헤드리스 Chromium의 실제 포인터로 첫 항목을 마지막으로 드래그해 PATCH 1회 및 순서 변경, 선택 이벤트 0회를 확인했다. 클릭으로 팝오버가 닫힌 뒤 outline:none, focus-visible 없음, 텍스트 선택 없음도 확인했다.
- 실제 키보드 순서 변경 및 가짜 API 오류에 따른 목록 복구·오류 표시를 확인했다. 임시 UI는 사용자 API에 연결하지 않았으며 검증 페이지·브라우저·서버를 정리했다.
- 최종 전체 검사 2,930개 통과, 환경 의존 496개 건너뜀. 타입 검사(계약·서버·도구·웹), Vite 빌드, Prettier 통과. 기존 번들 크기 경고는 남아 있다.
- 운영 환경에서는 새 빌드 사용 전 0018 마이그레이션을 적용해야 한다. 이 작업에서 운영 마이그레이션과 푸시는 수행하지 않았다.
