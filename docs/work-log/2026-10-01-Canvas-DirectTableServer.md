# 전체 테이블 캔버스 서버 통합 결과

## 범위

[구현 계획](../planning/2026-10-01-Canvas-DirectTableImplementation.md)에 따라 서버 MCP·동기화·프로젝트 입출력·개인 상태·리뷰 핀을 대응했다. 모델·계약·웹은 주 작업과 다른 에이전트가 담당한다. 이 작업에서는 커밋하지 않으며 주 작업에서 변경을 검토하고 커밋한다.

## 변경

- MCP 화면 목록에 `__tables__`와 `kind: tables`를 제공한다. 테이블 목록의 `domainId` 생략은 전체, 명시적 `null`은 미소속 필터다. 테이블 요약은 직접 색상을 포함하며 미소속 테이블 상세의 `domain`은 `null`이다.
- MCP 테이블 생성은 미소속이면 전체 배치를 지정하고, 소속이 있으면 기존 도메인 배치를 지정한다. 전체 배치 수정은 기존 `update_node_layout` 명령으로 수행한다. 전체 관계 배치 명령도 유지한다.
- `patch_table`에 nullable 도메인과 색상을 지원한다. `color: null`은 모델에 `color: undefined`를 전달하여 직접 색상을 제거한다. 소속 변경과 해제는 모델의 전체 배치 유지 정책을 따른다.
- `normalizeServerDocument()`가 물리 타입 정규화와 결정적인 전체 테이블 배치 보완을 연결한다. 프로젝트 조회·내보내기·가져오기·동기화 발급 기준·현재 서버 문서·ACK·reset 스냅샷·개인 상태·리뷰 대상 검증에 같은 전체 배치를 사용한다.
- 동기화는 원본 문서 차이와 claimed changes를 먼저 비교하고, 이후 양쪽 문서와 현재 문서를 정규화한다. 전체 카드가 저장되지 않은 기존 문서에서도 발급 기준의 전체 카드 좌표를 첫 작업에서 수정할 수 있다. 자동 보완 자체는 기존 문서의 일반 속성 변경에 별도 변경 경로를 추가하지 않는다.
- 삭제 복원은 `__tables__`를 예약 참조로 인정한다. 기존 owner-only 삭제 스냅샷은 후보 문서에 전체 배치를 보완한 뒤 실제 변경 목록을 산출한다. 새 글로벌 배치 스냅샷도 참조 오류 없이 복원한다.
- 가져오기는 정규화 이후 `designDocumentSchema`를 다시 확인한다. 원본이 제한 안에 있어도 전체 배치 추가로 노드 수·UTF-8 JSON 용량 제한을 넘으면 DB 삽입 전에 거부한다.
- 전체 캔버스의 리뷰 핀과 개인 viewport를 허용한다. 개인 상태 저장 시 정규화된 공유 문서끼리 비교하여 전체 배치 보완을 개인 요청의 공유 변경으로 오인하지 않는다. 프로젝트 갤러리 프리뷰는 기존 구현이 미소속 테이블을 포함하므로 테스트로 검증했다.

## 검증

- `pnpm --filter @ezerd/server typecheck`: 서버와 도구 타입 검사 통과.
- `pnpm exec vitest run apps/server/test`: 19개 파일·103개 테스트 통과, DB 통합 테스트 5개 파일·40개 테스트 건너뜀.
- 저장 기준·조회·내보내기·reset 배치 일치, 위조 변경 목록 거부, 기존 문서 첫 글로벌 좌표 동기화, owner-only/글로벌 삭제 복원, 미소속 MCP 생성·지정·해제·색상 초기화·전체 배치 수정, 전체 리뷰 핀과 viewport, 버전 1 입출력과 정규화 후 크기 제한을 테스트했다.
- 루트 Prettier 설정을 사용하여 담당 파일만 포맷하고 검사했다. 전역 포맷은 다른 에이전트 변경과 겹치므로 주 작업에서 실행한다.

## 제한 및 통합 검토 사항

- DB 통합 테스트는 `EZERD_DB_TEST=1`과 별도 PostgreSQL 환경이 필요하여 이 작업에서는 실행하지 않았다. 수행한 동기화·복원 경계 테스트는 서비스와 트랜잭션 저장소 모형을 사용한다.
- 기존 문서가 12,000 노드·1.5 MB 한계에 가까우면 전체 배치 추가로 현재 계약을 초과할 수 있다. 가져오기는 이를 명시적으로 거부하며 기존 저장 문서는 조회만으로 수정하지 않는다. 이미 저장된 한계 문서의 조회·baseline 발급과 예산 확장 정책은 모델/계약 통합 단계에서 검토해야 한다.
- 버전은 1을 유지하며 서버와 웹을 함께 배포하는 기존 구현 계획의 지원 경계를 따른다.
