# 반응형 패널 및 통합 검증 상태

작성일: 2026-09-16

## 변경

상단/도구 모음의 크기는 responsive-shell.css의 CSS viewport 기반 토큰으로 조절한다. DPR이나 OS로 전체 UI를 축소하지 않으며 카드 글꼴과 캔버스 배율은 변경하지 않는다.

속성 패널은 가로 배치 시 캔버스에 최소 420 CSS px를 남긴다. 작업 영역이 700 px보다 좁으면 아래로 배치한다. 핀 패널은 가로 배치에서 나머지 작업 영역에 840 px를 남기며 1120 px 이하에서는 아래 행으로 이동한다. 저장된 너비는 화면 변경으로 덮어쓰지 않고 실제 표시 너비만 제한한다. 핀 너비 조절기의 키보드·ARIA 범위도 가용 공간을 따른다.

작은 창에서는 페이지 높이가 콘텐츠에 맞춰 늘어나도록 해 캔버스·속성·핀 패널이 고정 높이를 나눠 가지다 겹치지 않도록 구성했다. 패널 본문은 독립 스크롤을 유지한다.

## 검증

- 단위 테스트 280개 통과(별도 실행 DB 테스트 20개 제외).
- 웹 TypeScript 및 Vite 프로덕션 빌드 통과.
- 수정 코드 Prettier 적용.
- 패널 계산 테스트에서 700/840/877/1024/1172/1280/1366/1512/1580/1920 등 너비와 저장된 선호값 보존을 확인했다.

사용자 승인 후 실제 브라우저 시각·조작 검증을 완료했다. 이전 자동 승인 검토의 429 오류는 재개 후 해소됐다. 1512×827에서 기본 두 패널을 열면 캔버스 852×650.5px, 상단 헤더 약 60px, 프로젝트 바 약 64px를 확인했다. 1366×768, 1280×720, 1024×768, 877×827, 390×844, 1920×1080에서도 가로 넘침이 없었다. 작은 창에서는 패널이 아래 행으로 이동하고 필요한 세로 스크롤이 제공된다. 화면 전환 애니메이션 종료 후 큰 창의 배치가 정상 복원됨을 확인했다.

패널 최대 너비/Home·End 조절, 핀·속성 패널 열기/닫기, 390px 창에서 ENUM 팝업의 화면 내 배치, 테이블 드래그 및 리사이즈, 관계선 드래그를 확인했다. 1512px에서 패널을 최대로 늘렸을 때도 캔버스가 432px로 최소 공간을 유지했다. 브라우저 콘솔 오류는 없었다. 실제 Mac 하드웨어/Safari 및 DPR 2 렌더링 자체는 이 Windows 호스트 QA 범위 밖이며 CSS viewport 대응을 검증했다.

## 재개 방법

scripts/prepare-responsive-qa.mjs는 실제 App과 메모리 API/WS 응답만 사용하는 임시 /__responsive-qa.html을 만든다. DB 계정·프로젝트 생성은 하지 않는다. 1512×827, 1366×768, 1280×720, 1024×768, 877×827, 390×844, 1920×1080에서 핀 열기/닫기, 속성 패널, 테이블/관계 드래그, ENUM 팝업과 가로 넘침을 확인한다. 인증 폼에는 fixture 전용 임의 이름과 네 자리 값을 사용한다. DPR 2 실제 Retina 렌더링은 별도 Mac 확인 대상이다.

QA는 메모리 응답을 사용해 실제 DB 데이터 변경이 없다. 상단 변경은 7351c49에 커밋되어 있으며 패널 변경과 본 검증 기록을 별도 커밋한다. 임시 HTML과 QA 서버는 작업 종료 시 정리한다.
