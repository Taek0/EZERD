# Klassboard 자동 관계선 정리 한도 진단

- MCP klassboard-backend version 407 문서를 실제 `nativeCanvasScene`의 전체 테이블 물리 보기와 라벨 폭으로 재현했다.
- 테이블 134개, 메모 26개, 관계 238개. 장애물 합계 160개로 입력 제한 256개 및 관계 제한 1,000개 이내다.
- 기본 예산 300,000 탐색 상태에서 `search-limit` 실패. 관계 `fk_whiteboard_group_membership_attendee` (`tbl_whiteboard_group_memberships` → `tbl_class_attendees`) 처리 중 반환되었다. 로컬 계산 약 6.4초.
- 동일 입력에 탐색 상태 예산만 1,000,000으로 늘려도 다른 관계(`erd21-6d305e5bcf84a9fc1494`)에서 `search-limit` 실패. 약 22.6초. 실행 시간은 이 로컬 테스트 환경의 측정치다.
- 해당 오류 분기는 공유 예산의 `limitReached`를 확인하므로, 실패 관계 하나가 전체 예산을 썼다는 의미는 아니다. 앞선 관계들의 누적 탐색 비용도 포함한다.
- 서버 저장 전에 실패하여 저장 페이로드 제한은 이번 실패 원인이 아니다. 추가 방향 재탐색도 같은 탐색 상태 예산을 공유한다.
- 한도를 단순 증대하기보다 장애물·경로 탐색 공간 축소와 예산 소진 시 저비용 우회 재시도 전략을 검토해야 한다.
- 임시 Vitest 진단 파일 제거. 제품 코드 및 실제 프로젝트 배치는 변경하지 않았다.
