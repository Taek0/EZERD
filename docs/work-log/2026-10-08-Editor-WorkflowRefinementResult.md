## 저장과 데이터 보호

- 이동 중 화면 state는 바로 갱신하고 비싼 archive 기록은 120ms quiet window/최대 1000ms checkpoint로 합친다. 이동 종료·선택 변경·이탈 때 최종 입력을 보관한다.
- 테스트 드라이버에서 100회 이동은 최종 archive 호출 1회와 save 호출 1회로 처리했다. 100ms 간격 입력 12회는 마지막 값 save 1회였다. 이는 프레임 속도나 실제 HTTP 전송량의 전후 벤치마크가 아니다.
- 한 enqueue 내부의 연속 안전 patch만 operationId 생성 전에 합친다. 구조·삭제·이름·타입·범위 변경 경계와 서로 다른 요청은 유지한다. 이미 저장·전송·claim한 요청은 변경하지 않는다.
- 화면과 초안의 상태는 동기로 유지하되 구독 알림을 microtask로 모아 render 중 부모 상태 갱신과 중복 알림을 줄였다.
- 개인 뷰는 기존 CAS·미확인 요청 잠금을 유지한다. 모든 저장 지연 환경에서 모든 조작이 무제한 가능하다고 보장하지 않는다.

## 브라우저에서 발견해 함께 수정한 문제

- ENUM 생성 ACK 때 구조 폼이 version/sequence key로 재마운트되어 입력이 초기화되던 문제.
- ENUM 값 목록이 압축되던 레이아웃과 미완성 값의 원시 검증 JSON 노출.
- 서버 GET은 누락된 테이블 배치를 보충하지만 ACK 반영은 원본만 사용해 카드가 사라지던 문제. 원본 저장 문서를 보존하고 화면용 정규화를 맞췄다.

## 최종 자동 검증

| 검증 | 결과 |
| --- | --- |
| pnpm check | 포맷·타입·전체 테스트·프로덕션 빌드 통과 |
| 전체 테스트 | 223개 파일, 2,764개 통과; opt-in 25개 파일/496개 건너뜀 |
| Native/API 격리 DB | 23개 스위트, 482개 통과 |
| Workspace 격리 DB | 3개 스위트, 15개 통과 |
| DB 통합 합계 | 26개 스위트, 497개 통과 |

- 실제 Chrome UI 확인은 [20항목 브라우저 QA 기록](2026-10-08-Editor-WorkflowBrowserQAResult.md)을 참조한다. 임시 PostgreSQL DB와 native-sync POST에 800ms 지연을 주는 QA 서버를 사용했다.
- 20항목 모두 실사용 확인을 마쳤다. 저장 중 입력·이동, ENUM 생성·수정·삭제, 논리 ON/OFF, 타입 선택, 도메인 색상점·필터, 우클릭·H/V, 리사이즈·고정 배율을 확인했다. 최종 새로고침 후 이름·컬럼·이동 좌표가 유지되고 해당 구간 console warn/error는 0건이었다.
- 엄밀한 800ms 이전 입력 시점과 HTTP 요청 수는 브라우저에서 측정하지 않았다. ACK 이전 편집·실패 rollback은 별도 deferred transport 회귀로 검증했다.
- 임시 브라우저 QA 서버·DB와 통합 회귀 DB는 종료 후 정리했다. 작업 문서의 상대 링크 26개 문서 범위 검사와 git diff --check도 통과했다.
- 기존 Vite 청크 크기 및 테스트 실행기의 Node shell 경고는 남아 있다. 실제 운영 배포와 사용자 데이터 변경은 수행하지 않았다.
