# 관계선 통로 중앙 정렬 결과

작성일: 2026-10-16

계획: [통로 중앙 정렬 계획](../planning/2026-10-16-Relation-CorridorCenteringPlan.md)

## 구현

명시적 `arrangeRelationRoutes`의 기존 개선 단계 뒤에 `centerRelationRouteCorridors`를 추가했다. 일반 `relationGeometry`와 라우터 기본값은 변경하지 않았다.

카드·메모의 18px 확장 경계를 한 번 준비하고 수평·수직 축별로 정렬한다. 경로당 가장 긴 64px 이상 내부 구간 하나를 선택하며, 그 구간 전체 길이와 겹치는 장애물로 양쪽 통로 경계를 구한다. 공통으로 열린 통로에 속하는 구간들을 한 번 그룹화하고 선의 기존 순서를 유지하는 16px 간격 묶음으로 배치한다. 묶음 중심이 통로 중심에 가장 가까운 유효 후보를 선택한다.

끝점과 앵커는 바꾸지 않는다. 기존 구간의 진행 방향, 꺾임 수, 최대 28px의 기존 출발·도착 보호 길이를 유지한다. 장애물 침범·반복 점·자기 교차·자기 중첩을 거부하고, 영향을 받는 관계선 쌍마다 기존보다 교차·중첩 길이·좁은 간격 수가 늘지 않는지 검사한다. 이상적인 중앙 위치가 막혀도 기존 묶음보다 중앙에서 멀어지는 후보를 채택하지 않는다.

기존 구간 캐시를 재사용하고 변경 경로만 다시 계산한다. 추가 그래프 탐색은 수행하지 않는다. 구간 1,024개, 전체 후보 512개, 그룹별 경계 후보 2,048개, 경로 쌍 검사 100,000개와 공통 기본 검사 1,000,000개의 상한을 둔다. 기본 검사 예산은 통로 탐색·그룹 비교·후보 경계 수집·장애물 및 구간 쌍 검사에 적용한다. 각 그룹에서는 중앙에 가까운 후보 최대 8개만 평가한다. 상한에 도달하면 현재 그룹 전체와 나머지 그룹을 기존 상태로 유지한다.

## HWP 확인

MCP에서 읽은 sequence 20 DTO의 `input`은 기존 `2026-10-16-route-quality/hwp-view.json` sequence 19 DTO의 `input`과 일치했다. 쓰기 작업은 하지 않았다.

Queue·Reply 오른쪽 면 2,400과 Session·Snapshot·Document·Paragraph 왼쪽 면 2,750에 의해 전체 세로 구간의 공통 확장 통로는 2,418~2,732이고 중심은 2,575다.

| 관계선 | 이전 세로 x | 이후 세로 x |
| --- | ---: | ---: |
| session-package | 2,418 | 2,559 |
| session-save | 2,434 | 2,575 |
| session-document | 기존 인접 통로 구간 | 2,591 |

세 선 묶음의 중심은 2,575이고 간격은 각각 16px이다. package와 save의 출발·도착 y 좌표 및 앵커는 그대로다. package의 y 범위는 551.2~3,165, save는 746.4~3,623.6666666666665로, 화면 일부가 아닌 전체 구간의 장애물을 검사했다.

## 측정

동일한 현재 v2 소스를 수정 전 기준으로 복사했다. HWP DTO와 `2026-10-14-actual-document/snapshot.json`을 사용했고, 각 조합은 준비 실행 뒤 수정 전·후 순서를 교대로 바꾸어 5회 측정했다. 아래 값은 전체 검증 완료 후 다른 에이전트의 빌드·측정을 중지한 창에서 다시 실행한 최종 중앙값이다. 다른 작업과 공유하는 로컬 PC의 전체 작업 시간은 변동이 커서 속도 개선 근거로 해석하지 않는다.

| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |

최종 HWP 기본 결과에서 후처리 함수만 100회 따로 측정한 중앙값은 1.77ms, 95백분위수는 2.53ms다. 전체 정렬 측정에서는 원래의 그래프 탐색과 시스템 실행 편차가 대부분을 차지한다.

모든 데이터·pass·전후 조합의 저장 경로 재생 실패와 실제 카드·메모 침범은 0건이었다. 기본 pass 1에서 전체 길이는 실제 문서 255,942.77→257,243.78, HWP 199,090.40→201,083.40으로 늘었다. 통로 중앙에 묶음을 배치하면서 일부 인접 수평·수직 구간이 길어졌으며 꺾임 수와 교차·중첩 제약은 유지했다.

전체 검증과 겹친 이전 실행은 `paired-concurrent-fullcheck.json`에 별도로 보존했다. 검증이 끝난 뒤에도 전체 작업 시간의 변동이 남아 있어 후처리 단독 측정을 비용 판단의 보조 근거로 사용한다.

원시 기준 소스는 `artifacts/performance/2026-10-16-route-quality/auto-arrange-baseline.ts`, 최종 비교와 집중 측정은 `artifacts/performance/2026-10-16-corridor-center/paired.json`, `focus.json`에 있다. 원시 산출물은 브랜치 지침에 따라 Git 제외 대상이다.
