# 갤러리·핀 피드백 반영

## 구현
- 전역 ConfirmProvider/useConfirm을 도입하고 네이티브 dialog의 모달 초점 제어, Escape 취소, 취소 초기 초점, 원래 버튼으로 초점 복귀를 구성했다. 기존 공통 Button과 디자인 토큰을 사용한다.
- App의 모든 window.confirm 호출을 공통 확인 팝업으로 전환했다. 프로젝트 보관은 확인 후 실행하며, 보관함의 영구 삭제는 삭제 범위를 고지한 뒤 expectedVersion을 포함해 DELETE 요청한다.
- 대시보드 상태 탭과 카드 테두리를 강화하고, 보관 및 삭제 버튼을 오른쪽으로 배치했다. 마우스 오버 시 빨간 배경을 표시한다.
- 검토 대화 명칭을 핀으로 변경했다. 프로젝트 전체 핀을 기본 표시하며, 모든 참여자의 핀을 주기적으로 갱신한다. 빈 공간 연결을 기본값으로 하고, Canvas onCreatePin의 좌표를 작성 대상에 보존한다.
- 답글을 들여쓰기와 세로 선으로 구분하고 답글 열기 버튼을 추가했다. 핀·알림 글자 크기를 14–16px 기준으로 맞췄다.
- 버튼과 토글 요소의 빠른 반복 클릭으로 텍스트가 선택되지 않도록 user-select를 적용했다.

## 검증
- 초기 타입 검사는 동시 작업 중 오류로 중단되었으나, 이후 담당 파일의 타입 오류가 없음을 확인했다. 최종 통합 검사는 전체 작업 기록을 따른다.
- 브라우저 연결 도구가 두 차례 실패하여 기존 프로젝트 Playwright 검증 방식을 사용했다. `scripts/browser-project-feedback-smoke.mjs`가 실제 앱에서 통과했다. 우클릭 빈 핀 좌표, 등록 후 다음 클릭 좌표 사용(초안 해제), 다른 작성자 핀 목록, 답글 스레드, 보관 Escape·취소·확인, 취소 초기 초점 및 원래 버튼 초점 복귀, 영구 삭제 취소·확인, 브라우저 기본 대화상자 0건을 검증했다.
- 확인 팝업과 핀 화면 스크린샷은 `.cache/verification/project-feedback-confirm.png`, `.cache/verification/project-feedback-pins.png`에 저장했다.
- 테스트가 생성한 임시 프로젝트·사용자만 사용했고 종료 시 정리했다. 기존 데이터의 보관·삭제 작업은 실행하지 않았다.
- 알림의 “핀로 이동” 문구를 “핀으로 이동”으로 수정했다.
