# 웹 자동 동기화 구현 기록

작성일: 2026-09-15

## 구현 결과

- 프로젝트 편집을 서버 동기화 작업과 IndexedDB 영속 대기열에 연결했다.
- 텍스트 입력은 500ms 지연 저장하고 IME 조합 중 저장을 보류하며, blur와 일반 편집 동작은 즉시 반영한다.
- 시작 중 편집 의도를 서버 기준 문서에 재적용하고, 늦은 ACK와 종료 후 비동기 실패가 최신 화면을 덮지 않도록 했다.
- 연속 의존 작업의 기준선 계보를 후속 작업에 영속화해 ACK 직후 새로고침 후에도 올바르게 rebase한다.
- 브라우저 기본 `fetch`를 전역 객체에 바인딩해 Chromium의 `Illegal invocation`으로 기준선 요청이 누락되던 문제를 수정했다.
- 관계선과 노드 드래그는 미리보기와 최종 작업을 분리하고, 종료 시 최신 원격 문서에 마지막 이동 의도만 반영한다.
- 통합 이력에서 미반영 편집의 재적용·복사·폐기, 삭제 내용 미리보기·복원, 복원 시 제외한 관계와 배치 안내를 제공한다.
- 승인된 내 작업의 실행 취소와 다시 실행은 서버의 충돌 보호 명령을 사용한다. 전송 중 실행 취소와 저장소 상태 전환 중 취소 경합도 직렬화하고 전송 직전에 재확인한다.
- 개인 카메라와 조합뷰 배치는 공유 문서 동기화에서 제외하며, 조합뷰에서는 공유 배치 편집을 제한한다.

## 검증

- `node node_modules/vitest/vitest.mjs run apps/web/src`: 26개 파일, 114개 테스트 통과.
- `pnpm --filter @ezerd/web typecheck`: 통과.
- 주요 회귀 검증에는 3개 연속 의존 작업과 새로고침, 시작 중 편집, 종료 후 실패 콜백, 기본 브라우저 fetch receiver, 원격 변경을 보존하는 드래그 종료, 미반영 편집 처리, 제외 관계 안내, 서버 보호 undo/redo, 동일 필드 충돌, 전송·취소 경합이 포함된다.

실제 5개 브라우저 통합 검증은 서버 기준선 식별자 검증 문제의 후속 수정 이후 계속한다.
