# Hwp 자동 관계선 정리 진단

- MCP에서 읽은 Hwp version 29: 전체 테이블 논리 화면에 카드 71개, 관계 114개.
- 실제 `nativeCanvasScene`과 라벨 폭을 사용하여 `arrangeRelationRoutes`를 실행했다. 카드 중첩은 0건이다.
- 전체 계산은 `hwp-r-parkedtab-position` (ParkedTab → TextPosition)에서 `no-valid-route`로 실패한다. 서버 저장 이전의 계산 실패다.
- 같은 카드 배치에서 해당 관계만 계산하면 6개 굴절의 정상 우회 경로를 찾는다.
- 탐색 노드 예산을 기본 300,000에서 1,000,000으로 늘려도 같은 관계에서 실패한다. 단순 예산 부족으로 설명되지 않는다.
- 전체 계산에서는 다른 관계에 따른 포트 배분과 기존 경로 비용이 달라진다. 현재 알고리즘은 한 관계의 경로 계산이 실패하면 전체 결과를 반환하지 않는다. 실패 시 다른 포트/방향으로 재시도하는 보완이 필요하다. 정확히 어느 후보가 탈락하는지는 추가 계측이 필요하다.
- UI 실행 조건은 전체 테이블 화면, 도메인 필터 없음, 편집 가능, 표시 관계 1개 이상이다. 도메인 맵은 지원 대상이 아니다.
- 임시 Vitest 재현 검사 통과 후 검사 파일 제거. 프로젝트 데이터와 제품 코드는 변경하지 않았다.

권장 후속 작업: 실패 관계의 포트 방향 대체 탐색, 보수적 우회 경로 재시도, 실패 관계명을 포함한 안내와 전체 실패 처리 개선.
