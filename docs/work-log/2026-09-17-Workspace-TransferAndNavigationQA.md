# 갤러리 전송 및 이동 UI 통합 QA

사용자 선택 A안으로 이동·편집·보기·협업·변경기록을 그룹화했다. 도메인 뷰 버튼은 도메인 맵에서 숨기고 테이블 화면에서 표시한다. 갤러리 이동은 자체 확인창을 사용하며 취소시 현재 프로젝트를 유지한다. 브레드크럼 글꼴은 13px로 일치하는 것을 확인했다.

QA에서 review-workspace의 flex-wrap이 속성 패널을 콘텐츠 높이만큼 늘리는 문제를 확인했다. 단일 행과 명확한 작업영역 높이를 지정한 후 패널 clientHeight 622 / scrollHeight 1098, scrollTop 476으로 스크롤되고 마지막 삭제 버튼이 화면 하단 720px 안에 노출되는 것을 확인했다.

갤러리에 프로젝트 가져오기 버튼과 카드별 내보내기 버튼을 연결했다. 가져오기는 검증된 JSON을 미리보고 새 이름으로 새 프로젝트를 만든 뒤 목록을 갱신한다. 브라우저 파일 선택·미리보기·새 카드 생성 확인. 내보내기 버튼 오류는 없었으나 도구의 download 이벤트 대기가 만료돼 다운로드 완료 이벤트는 확인하지 못했다. 파일 구조와 데이터 왕복은 실제 격리 DB 통합 테스트로 확인했다.

전체 단위 313개, 타입·빌드·Prettier 및 격리 통합 23개 통과. 통합에는 설계/관계/ENUM/배치 왕복, 미인증 차단, 실패시 행 미생성, 반복 가져오기 독립성과 새 프로젝트 동기화 편집을 포함한다. QA는 메모리 fixture와 임시 DB에서만 수행했다. 이번 작업에서는 429 오류가 없어 워크스페이스 포크가 필요하지 않았다.
