# 테이블 자동 배치 Undo 및 성능 fixture 이력 검증

[계획](../planning/2026-10-15-Canvas-TableUndoFixtureParity.md)에 따라 테이블 배치 저장과 이력 표시를 조사했다.

- `arrangeVisibleNodes`는 보이는 테이블의 좌표 명령을 한 번의 `saveCommands` 호출에 담는다. 서버 Native 저장은 이 명령 배열을 하나의 작업으로 기록하고 `native-history.undo`는 해당 작업의 변경 경로 전체를 되돌린다.
- 실제 snapshot 브라우저 재현에서 자동 배치 한 번은 43개 경로를 저장했고 첫 Undo는 같은 43개 경로를 되돌려 표시된 58개 노드 좌표를 모두 원래대로 복원했다. 사용자가 보고한 최초의 간헐적 부분 복원은 이 조건에서 재현되지 않았다.
- 별도로 성능 fixture의 확정된 결함을 발견했다. 첫 Undo 후에도 이력 응답에 보상 작업 메타데이터가 없어 Undo 버튼이 남고, 다시 누르면 43개 배치가 재적용되었다. fixture 이력에 서버와 같은 `deletionSnapshot.nativeHistory`를 기록하고, 이미 보상한 원본 작업을 다시 보상하지 않도록 했다. 페이지 커서도 남은 항목이 있을 때 반환한다. 이 수정은 로컬 성능 fixture에만 영향을 준다.
- 제품 회귀 테스트는 테이블 배치 명령이 하나의 저장 작업에 들어가며 한 번의 역변경으로 모든 노드가 복원됨을 확인한다. fixture 회귀 테스트는 실제로 반환하는 이력 행을 Undo 후보 로직에 전달해 첫 Undo 이후 후보가 비고 Redo 이후 새 후보가 생기는지, 25개 초과 이력의 다음 페이지가 있는지 확인한다.

검증: 대상 Vitest 3개 파일 9개 테스트 통과, 웹 타입 검사 통과. 브라우저에서 수정된 fixture의 Undo/Redo는 성능 빌드 재생성 후 별도 확인한다.
