# C2b native 문서·전송 계약 구현 결과

- 날짜: 2026-10-01
- 계획: [C2 native 문서](../planning/2026-10-01-Database-NativeDocumentImplementation.md)
- 선행: C1 `d7d8ddd`, C2a `bf3d835`.

## 변경

- DB별 native 타입·파라미터·값 목록, 생성 옵션, 구조화 기본값/식, namespace/table/column 옵션, indexes/checks의 Zod 구조 계약을 추가했다.
- 타입 규칙은 모델 카탈로그를 사용하고 기존 프로젝트 DB enum도 모델의 databaseKinds에서 생성한다. known 옵션이라도 해당 타입이 허용하지 않으면 거부하며 DB 종류/프로필 불일치도 거부한다.
- read/candidate 스키마는 기존 legacy 값을 원문 그대로 보존하고 native 신규 값 스키마는 legacy 입력을 받지 않는다. 서버 최종 쓰기 정책은 다음 C3에서 기존 원본 비교를 추가해야 한다.
- 구조화 식은 Zod의 재귀 파싱 전에 깊이/노드 한도를 검사해 심한 중첩 및 cycle 입력을 거부한다. 숫자 문자열/JSON 원문은 값을 바꾸지 않는다.
- v1/v2 문서/JSON 전송 reader와 v2 전송 계약을 추가했다. v1 별칭을 정규화해 원본을 바꾸지 않으며 v2 프로젝트 메타데이터와 문서의 DB/profile 일치를 확인한다.
- 새 컬렉션을 포함한 전역 ID, 예약 ID, 배치/뷰/관계 경로 중복 및 기존 1.5 MB 문서/2 MB 파일 한도를 검사한다.
- 기존 live 제품의 v1 조회/저장/import 경로는 아직 전환하지 않았다. 프로젝트 저장 profile/revision, 원자 업그레이드와 UI 전환이 남아 있다.

## 검증

- 새 계약 테스트 11개 통과. DB별 파라미터/옵션 거부, ENUM/SET 조건, 신규 legacy 거부와 읽기 원본 보존, 큰 숫자/불법 리터럴, 깊이 1500/cycle 식, 전송 버전/문맥/크기/ID 사례 확인.
- 모델+계약 회귀: 27개 파일 212개 통과.
- `pnpm check`: 포맷/전체 타입 검사/테스트/빌드 통과. 전체 테스트 678개 통과, 43개 건너뜀(실제 DB 통합 실행은 이번에 별도로 수행하지 않음).
- 마지막 DB enum 소유 위치 정리는 공유 빌드 및 해당 계약 테스트 18개 통과로 추가 검증했다. enum의 실제 값/기존 동작은 동일하다.
- 제품 기능을 verified로 활성화하거나 DDL/브라우저 실제 DB 실행을 완료한 것으로 표시하지 않는다.
