## 구현

기존 우측 목록의 검색·도메인 필터·테이블·도메인·관계 목록을 좌측 독립 탐색 영역으로 옮겼다. NativeNavigatorTable은 이름·타입·선택만 담당하며, 편집은 기존 NativePropertyEditor와 구조/관계 에디터가 계속 담당한다.

- 테이블 아래 컬럼을 접고 펼칠 수 있다. 물리명·논리명으로 테이블/컬럼을 검색한다.
- 컬럼 선택 시 기존 우측 컬럼 폼을 열고 검색어를 유지한다. 선택만으로 문서나 저장 큐를 변경하지 않는다.
- 기존 목록 버튼은 좌측 탐색을 열고 검색창으로 포커스를 이동하는 진입점으로 유지한다.
- 탐색 패널은 툴바와 패널 헤더에서 접을 수 있다. 헤더로 닫으면 툴바 버튼으로 포커스를 돌려준다.
- 권한·자동 저장·복구·기본값·배열·키·제약·고급 설정·히스토리·핀·단축키 로직은 유지한다.
- 논리 설계와 설계 확인 항목은 기존 더 보기 위치를 유지한다.
- 핀과 속성은 기존처럼 동시에 표시할 수 있다. 목업의 상호 배타 전환이나 임시 SQL 탭을 제품에 추가하지 않았다.
- 탐색 컬럼 매핑은 한 번의 순회로 만들고, 접힌 테이블의 컬럼 버튼은 렌더링하지 않아 불필요한 반복 검색과 DOM 증가를 피했다.

## 검증

- pnpm format 적용 및 pnpm format:check 통과.
- 전체 패키지 타입 검사 통과.
- 기존 UI 컴포넌트 테스트 6개, 탐색·선택·폼 관련 선행 테스트 81개 통과.
- 최종 pnpm check: 233개 테스트 파일 통과, 26개 파일 건너뜀; 2,861개 테스트 통과, 499개 건너뜀. 전체 패키지와 웹 프로덕션 빌드 통과.
- 첫 전체 검사에서는 독립 워크트리에 DATABASE_URL이 없어 서버 설정 테스트 5개가 실패했다. 실제 DB에 연결되지 않는 loopback 포트 1의 테스트 URL을 해당 프로세스에만 제공하고 EZERD_DB_TEST=0으로 재실행해 통과했다. .env나 실제 DB를 변경하지 않았다.
- DB 통합 테스트는 실행하지 않았다. Vite는 500kB 초과 번들에 대한 크기 경고를 표시했으며 빌드는 성공했다.
- 새 회귀 테스트로 컬럼 검색, 탐색 선택 후 기존 컬럼 폼 열기, 검색 상태 유지, 선택 시 저장 큐/문서 불변을 확인했다.

## 실제 컴포넌트 브라우저 검증

- Vite의 임시 격리 화면에서 실제 NativeProjectView와 Button을 렌더링했다. 목업 HTML을 제품 구현 검증으로 대신하지 않았다.
- 현재 화면 검색에 copy 입력 → audit의 copy 컬럼 선택 → 검색어 유지와 우측 기존 컬럼명·타입·설명·PK·NULL/기본값/배열·삭제 항목 표시 확인.
- 도메인 맵 전환 시 좌측 도메인 및 도메인 관계 목록 유지 확인.
- 탐색 닫기 → 기존 목록 버튼 클릭 시 다시 열리고 실제 검색 input이 포커스를 받는 것 확인.
- 실제 1440px iframe에서 탐색 232px, 속성 320px, 핀 320px를 동시에 표시할 때 캔버스 562px 확보 확인.
- Button의 클릭, 선택, loading/disabled, 그라데이션·그림자 제거를 계산된 스타일과 실제 화면으로 확인했다.
- iframe 재로드 중 MutationObserver 대상 오류가 검증 도구 로그에 관찰됐다. 제품이 없는 정적 iframe에서도 같은 오류를 재현했고, 직접 연 편집기에서는 error 로그가 없었다. 제품 회귀로 판단하지 않았다.

## 범위와 주의점

- 원본 main 작업 디렉터리와 그곳의 미커밋 스킬·기존 문서는 변경하지 않았다. merge/push하지 않았다.
- 브라우저 검증은 테스트 데이터·가짜 조회 응답과 축약한 전역 헤더를 사용했다. 실제 백엔드 저장/공동 편집/DB 통합 검증을 수행했다는 뜻은 아니다.
- 샘플 카드 겹침은 원래 테스트 fixture의 배치이며 새 레이아웃 엔진 변경이 아니다.
- 입력 컴포넌트의 기능이나 필드 순서를 재설계하지 않았다. 추가 대규모 디자인 변경보다 현재 범위의 기능 보존과 안정성을 우선했다.
