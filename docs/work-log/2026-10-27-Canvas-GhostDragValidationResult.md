# 고스트 카드 드래그 검증 결론

[계획](../planning/2026-10-27-Canvas-GhostDragValidationPlan.md), [장면 측정](2026-10-27-Canvas-GhostSceneMeasurement.md), [프로토타입 검사](2026-10-27-Canvas-GhostPrototypeValidation.md)를 기준으로 고스트 방식의 적용 타당성을 검증했다. 제품 UI에는 적용하지 않았다.

## 판단

이동 중 장면·관계선 계산을 생략할 수 있어 적용 가치가 크다. 다만 큰 문서는 drop 한 번의 동기 계산도 길어서 고스트만 연결하는 것으로 끝내지 않는 것을 권장한다.

| 입력 | 현행 20회 장면 합계 중앙값 | 고스트 최종 1회 중앙값 |
| --- | ---: | ---: |
| 43테이블 단일 | 91.28ms | 6.98ms |
| version407 134테이블 단일 | 3,678.16ms | 182.04ms |
| version407 134테이블 5개 그룹 | 6,361.30ms | 389.66ms |

저장된 자동 정리 경로를 적용한 같은 134테이블 복제본에서도 drop은 단일 65.02ms, 그룹 273.46ms였다. 이 시간은 직접 실행한 순수 장면 함수이며 실제 사용자 드래그 시간이나 FPS가 아니다. 반복 포인터 이벤트를 React/브라우저가 병합하는 효과, draft 준비/저장, 추가 낙관적 갱신과 ACK, paint/compositing은 제외했다. 실제 drop 통합 비용의 하한 비교다.

현행 최종 장면, 고스트 최종 장면, 같은 위치를 직접 적용한 장면은 모두 정확히 같았다. 134테이블의 관계 계산은 실험 조건에서 20×238=4,760회에서 238회로 줄었다. 이를 FPS 20배 개선으로 해석하지 않는다.

## 제품 적용 권장안

- 단순 제목·색상·크기의 고스트만 이동하고 편집 가능한 카드 하위 트리는 복제하지 않는다. 이동 중 원본 좌표와 관계선은 유지한다.
- drop 후 최종 고스트를 남겨두고, 순수 geometry 계산을 Worker 등으로 분리한 뒤 최종 결과를 한 번에 교체한다. 로딩 표시만 띄우고 동일 스레드에서 동기 계산하면 182~390ms의 정지가 남을 수 있다.
- 현재 savePlacement는 단일 카드에서 drawn.nodes를 읽는다. 제품 연결 때는 마지막 고스트 placements/commands를 직접 전달하고 추가 장면 재계산·저장 횟수를 통합 검증해야 한다.
- 기존 100개 배치 저장 제한, 읽기 전용/원격 변경/삭제/뷰·사용자·줌 변경의 취소, 저장 실패 복구, 한 번의 undo/redo, 키보드 이동/리사이즈를 유지한다. 이는 이번 프로토타입에서 실제 저장 파이프라인까지 검증한 내용은 아니다.
- 낮은 배율의 GPU 화면 깨짐 이력 때문에 world 강제 승격은 재도입하지 않는다. 고스트를 viewport 안에서 잘라 그리는 방식을 검토하고 실제 Chrome 10~15% 확대율에서도 확인한다.

## 검증·반영 상태

lab 전용 프로토타입 13테스트와 웹 타입 검사가 통과했다. 임시 장면 측정 테스트는 원본/라우팅 계측/저장 경로 보조 입력 실행 모두 통과 후 제거했다. 원시 결과와 재현 코드는 ignored artifacts/performance/2026-10-27-ghost-drag/에 보존했다. 제품 소스·main·실제 문서·실행 서버·원격 브랜치는 수정하지 않았다. 추가된 prototype은 performance 경로에만 있으며 제품 진입점에서 import하지 않는다.
