# 서버 속성 단위 동시 편집

- Native 명령은 같은 DB revision에서 이전 version/sequence를 허용하고 프로젝트 잠금 아래 최신 문서에 적용한다.
- 서로 다른 속성은 병합하고 명시적으로 지정된 같은 속성은 서버에서 나중 처리한 값이 우선한다. 기기 시각은 순서를 결정하지 않는다.
- 미래 버전, DB 설정 변경, 권한 위반, 삭제된 대상, 유효하지 않은 구조는 계속 거부한다. 명령 묶음은 원자적으로 처리한다.
- 기존 operationId 재전송은 원래 결과를 반환한다. 원시 동기화 프로토콜과 히스토리 복원 충돌 검사는 그대로 유지한다.
- 타입·옵션 및 관계선 경로처럼 하나의 값으로 받는 속성은 전체 값 단위로 교체된다. MCP 안내에도 변경할 속성만 전송하도록 명시했다.

## 검증

- 수정 전 실제 격리 DB에서 비중첩 명령이 거부되는 회귀 테스트 실패를 확인했다.
- 캔버스, 지연 제약, WebSocket, 히스토리, 재전송·접근 권한, 취소 관련 격리 DB 통합 테스트 130개 통과.
- 관련 단위 테스트 71개 및 서버 빌드 통과.
- 테스트는 임시 DB를 생성·정리하는 기존 도구로 수행했다. 제품 DB 마이그레이션은 필요하지 않다.
