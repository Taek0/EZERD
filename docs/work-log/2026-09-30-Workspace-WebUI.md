# 워크스페이스 웹 UI 구현

## 구현

- 갤러리에 워크스페이스 생성·선택·목록을 연결하고 선택한 공간으로 프로젝트 조회·생성·가져오기를 제한했다. 파일 내보내기 형식에는 공간 정보가 추가되지 않는다.
- 초대함의 수락·거절, 소유자의 멤버 역할 변경·제거·초대·취소, 공간 이름 변경·보관·복원·빈 공간 삭제 화면을 구현했다. 마지막 소유자 변경을 UI에서도 막는다.
- 한국어·영어 및 기존 공통 버튼 스타일을 유지하고 빈 공간·뷰어·보관 상태를 안내한다.
- 설계 쓰기와 개인 상태 쓰기를 분리했다. 활성 공간의 뷰어는 공유 설계·공유 배치를 변경할 수 없지만 개인 통합뷰 관계선과 핀·댓글은 사용할 수 있다. 보관 공간에서는 개인 상태와 리뷰 쓰기도 막는다.
- 댓글 멘션 후보를 현재 공간 멤버로 제한했다. 프로젝트 영구 삭제는 소유자에게만 허용한다.
- 권한 변경 WebSocket 이벤트를 받으면 동기화를 중단하고 임시 편집을 정리한 뒤 공간 권한을 다시 조회한다. 멤버십이 사라진 프로젝트는 닫는다. 주기적 조회와 창 포커스 시 갱신도 적용했다.
- 뷰어의 동기화 대기열 자동 재전송을 막고 개인 상태 저장만 허용한다. 보관 상태에서는 개인 저장도 막는다. 기존 미전송 기록은 복구 가능하도록 보존한다.

## 검증

- 웹 타입 검사 통과.
- 웹 프로덕션 빌드 통과. 기존 단일 번들의 500 kB 초과 안내는 남아 있다.
- 공간 정책·다국어 렌더링·Canvas·관계선·히스토리 대상 테스트 38개 통과.
- 동기화 런타임 테스트 23개 통과. 권한 변경 즉시 중단, 뷰어 대기열 전송 차단, 개인 저장 허용/차단을 포함한다.
- 격리 서버 http://127.0.0.1:3401의 실제 브라우저 로그인 화면 렌더링을 확인했다. 자동 승인 검토가 테스트 소유자 로그인에 대한 명시적 사용자 승인 근거 부족을 사유로 로그인을 거절하여 인증 후 브라우저 검증은 아직 수행하지 못했다. 우회하지 않았다.

- 새 일회성 데이터베이스·직접 생성한 테스트 계정·사용자가 요청한 격리 검증 범위를 근거로 한 재심사도 거절됐다. 사유는 새 사용자 승인 없이 제한된 로그인을 재시도했으며 일회성 계정이라는 설명으로는 특정 로그인 승인 요건을 충족하지 못한다는 것이다. 추가 로그인 시도는 중단했다.

- 사용자가 테스트 로그인을 명시적으로 승인했다. 재개 시 기존 Browser 연결이 사라졌고 연결 가능한 브라우저 목록도 비어 있어 화면 검증을 위한 연결 복구를 시도했다. 앱에서 preview 패널을 다시 열도록 요청한 뒤 한 번 재확인해도 브라우저 목록이 비어 있었다. 인증 후 실제 브라우저 검증은 도구 연결 부재로 완료하지 못했으며 추가 승인이 부족한 상태는 아니다.
- 보관 공간의 런타임 시작과 기준점 갱신에서 POST /sync-baseline을 생략한다. 이벤트 GET과 조회용 동기화는 유지한다. 전송 회귀 테스트와 최신 웹 빌드가 통과했다.

## 계정 전환을 위한 로그아웃

- 사용자 메뉴에 한국어/영어 로그아웃을 추가했다. 현재 서버 세션 종료를 요청하고, 동기화·임시 편집을 중지하며, 화면과 브라우저 로그인 정보를 정리해 다른 계정으로 로그인할 수 있다.
- 서버 세션 종료가 실패해도 로컬 로그아웃은 수행하고 실패 상태를 알린다. 계정별 내구성 편집 대기열과 언어·화면 설정은 지우지 않는다.
- 세션 종료 순서, 원격 실패 시 로컬 정리, 한 저장소 실패 시 다른 저장소 정리를 검증했다.

## 최종 실제 화면 검증

- 테스트 로그인과 격리 UI 테스트 전체에 대한 사용자 승인을 받은 뒤 루트의 연결된 브라우저에서 검증을 완료했다. 앞서 기록한 연결 제한은 해소됐다.
- owner 로그인, 공간 생성/선택, 공간 소속 프로젝트 생성, viewer 초대, 로그아웃/계정 전환, 받은 초대 수락을 실제 화면에서 확인했다.
- viewer의 가져오기/이름 변경/보관/도메인·공유 메모·관계·삭제 비활성화와 내보내기/조회 유지, 실제 핀 및 댓글 작성을 확인했다.
- owner의 viewer↔editor 역할 변경, 마지막 owner의 강등/제거 비활성화, 공간 보관 시 프로젝트 쓰기 비활성화와 복원을 확인했다. 보관 중에도 owner의 멤버 관리가 유지된다.
- 한국어/영어의 공간·계정·역할·핀·댓글·보관 메시지와 기존 파란색 버튼을 확인했다. 검증 화면은 .data/workspace-viewer-qa-2026-09-30.png에 저장했다.
- 캐시 사용자/세션 불일치 및 401 이후 토큰 재사용도 이 과정에서 발견하여 보완했다. 최종 일반 테스트 530개 및 격리 PostgreSQL 39개 테스트가 통과했다.

## 저장된 세션 복구 수정

- 서버가 저장된 로그인 정보를 401/403/404로 거절하면 캐시된 사용자·세션을 정리한다. 서버 사용자 확인이 성공하기 전에는 저장된 세션을 앱 상태에 넣지 않는다.
- 새로 확인한 사용자가 이전 로그인 사용자와 다르거나 이전 사용자가 없으면 PIN으로 새 세션을 발급한다.
- 브라우저 세션에 사용자 ID를 함께 저장해 탭별 세션 토큰과 공용 localStorage 사용자 ID가 뒤섞이지 않도록 했다. 사용자 연결 정보가 없는 기존 브라우저 세션은 PIN 재로그인이 필요하다.
- 이전 사용자가 없는 잔여 토큰, 다른 사용자 토큰, 만료·손상·연결 정보 없는 캐시를 거부하는 회귀 테스트를 추가했다.
