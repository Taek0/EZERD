# 자동 정리 전용 공유 장애물 인덱스와 제한 탐색

## 변경 내용

- `createAutoRelationRoutingContext`를 명시적으로 사용하는 자동 정리에서만 전체 카드/노트의 원본·18px 확장 장애물 인덱스와 전역 좌표를 공유한다.
- 원본/확장 인덱스는 축별 구간 트리와 열린 구간 병합·이진 탐색으로 점 및 직교 선분의 충돌을 검사한다. 좌표별 캐시는 방향별 최대 512개이며 자동 정리 실행의 컨텍스트 수명으로 제한한다.
- A*의 좌표 집합은 두 연결점 주변 128px, 512px, 전체 장애물 순서로 확대한다. 각 단계에서도 충돌 검사는 항상 전체 장애물을 대상으로 수행한다.
- 개별 탐색의 기본 상한은 12,000 상태이며 스케줄러가 남은 전역 예산 안에서 별도 상한을 지정할 수 있다. 전역 상태 예산과 단조 시계의 마감 시각을 함께 준수한다.
- 선택적인 진단은 graph 호출 수, 탐색 상태 수, 확대 재시도 수, 시간 한도 도달 여부를 기록한다.
- 자동 정리 전용 후보 생략 옵션을 추가하고 자동 탐색에서 연결점의 출발/도착 직선 구간을 거슬러 돌아가는 첫/마지막 간선을 제외했다. 최종 원본 충돌 검사·재추적 검사·저장 경로 재생 의미는 유지한다.
- 일반 `relationGeometry`와 기존 `createRelationRoutingContext`는 기존 탐색 정책을 사용한다. 자동 정리 컨텍스트를 만들지 않으며 신규 인덱스·전역 좌표·시간 검사를 준비하지 않는다.

## 검증

- `pnpm.cmd --filter @ezerd/model typecheck` 통과.
- `pnpm.cmd exec vitest run packages/model/src/relation-auto-routing.test.ts packages/model/src/relation-auto-arrange.test.ts`: 23개 통과.
- 고정된 기존 라우터와 일반 호출의 결과 전체를 96개 조합(자기 참조 포함 4개 대상, 2개 lane, 3개 bend, 연결점·유효/무효 저장 경로 포함 4개 옵션)에서 비교했다. 준비 컨텍스트 유무도 일치했다.
- 700개의 서로 다른 좌표에서 점/수평/수직 쿼리를 선형 충돌 검사와 비교하고 캐시 축출 및 맞닿은 열린 경계를 확인했다.
- 공유 컨텍스트의 서로 다른 두 대상 경로가 전체 장애물을 관통하지 않으며 저장 경로를 일반 라우터로 재생했을 때 점 배열이 일치함을 확인했다.
- 개별 상태 상한, 전역 상태 계수와 진단 계수 일치, 이미 지난 시간 한도에서 탐색 상태 0을 확인했다.
- version 407 실제 장면의 일반 라우팅 238개 결과가 보존한 이전 빌드와 완전히 일치했다. 이전/현재 빌드를 번갈아 6회 측정한 중앙값은 각각 453.09ms/459.06ms였으며 범위는 421-495ms/428-487ms로 겹친다. 원시 결과는 Git 제외 대상 `artifacts/performance/2026-10-21-relation-search/ordinary-parity.json`에 보관한다.

실제 version 407 고정 장면의 자동 정리 전후 시간·완료 수·품질 지표는 상위 성능 검증 작업에서 별도로 기록한다. 이 변경은 전역 기본 300,000 상태 예산을 늘리지 않는다.
