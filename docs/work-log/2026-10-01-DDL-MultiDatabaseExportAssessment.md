# DB 종류별 프로젝트 전체 DDL 내보내기 조사 결과

- 작성일: 2026-10-01
- 계획: [다중 DB 내보내기 계획](../planning/2026-10-01-DDL-MultiDatabaseExportPlan.md)
- 선행 조사: [기존 DDL 코드 및 공유 메뉴](2026-10-01-Canvas-DDLExportAssessment.md)

## 확인한 내용

- 사용자가 내보내기 대상을 프로젝트 전체 물리 설계로 지정했다. 선택된 PostgreSQL/MySQL/SQLite 종류에 맞는 출력의 작업 방법을 요청했다.
- 프로젝트 DB 종류 선택·저장·조회·JSON 전송은 이미 구현되어 있다. 기존 API로 동일 스냅샷의 DB 종류와 설계를 조회할 수 있다.
- 생성기뿐 아니라 편집기 후보 타입, 별칭 및 계약 파라미터 검증도 PostgreSQL 중심임을 확인했다. 따라서 새 두 생성기를 추가하는 작업과 DB 고유 타입 편집기를 확장하는 작업을 구분했다.
- DB 공식 문서를 확인하고 자동 증가, ENUM, FK, 스키마, 기본값, 정확한 수치·시간대 등 의미 차이를 계획에 기록했다. 변환 가능/경고/차단 정책은 제품 설계 제안이며 아직 구현되지 않았다.
- 권장 구현 순서는 공용 진입점/정책 → MySQL → SQLite → 공유 메뉴/진단/다운로드 → 실제 DB 실행 및 브라우저 QA의 다섯 단위다.
- 첫 범위는 현재 문서 모델 유지 + DB별 export 및 진단이다. MySQL/SQLite 고유 타입·옵션의 편집기 입력까지 지원하는 범위는 별도 계획으로 분리했다.

## 검증 및 변경 범위

- 현재 코드와 기존 제거 이력 조사 결과를 재사용하고 DB별 공식 문서와 대조했다.
- 이번 작업은 문서 두 파일만 추가했다. 제품 코드, 미커밋·동시 작업 변경 및 `docs/EZERD.txt`는 수정하지 않았다.
- 제품 구현이 없으므로 단위 테스트/빌드/실제 DB 실행/브라우저 테스트는 이번에 수행하지 않았다. 선행 조사에서 통과한 71개 테스트를 이번 실행 결과로 재표기하지 않는다.
- 문서는 루트 Prettier 제외 대상이다. 전체 포맷 쓰기는 실행하지 않으며 상대 문서 링크 및 이번 변경의 diff 공백 오류를 확인한다.
