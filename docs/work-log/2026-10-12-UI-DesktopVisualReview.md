# 데스크톱 시각 디자인 검토

## 결론과 범위

- 날짜: 2026-10-12. 브랜치: codex/apple-ui-review. 제품 코드 기준: d5e46e1, 검토 문서 기준: da79d1c.
- 사용자 요청에 따라 모바일 대응과 논리 설계·검증 항목의 위치 변경을 우선순위에서 제거했다.
- 기존 레이아웃과 입체 버튼의 방향을 유지하면서 강조를 줄 곳과 배경으로 물러날 곳을 구분하는 것이 우선이다. 새로운 유리 효과·애니메이션·사이드바 추가는 이번 핵심 제안이 아니다.
- 이 문서는 디자인 제안이며 버그 심각도 목록이 아니다. 아래 순서는 시각 디자인의 적용 순서다.
- [계획](../planning/2026-10-12-UI-DesktopVisualReviewPlan.md), [갱신된 구성 검토](2026-10-12-UI-CompositionReview.md).

## 1순위: 버튼과 선택 상태의 강조를 분리한다

데스크톱 캡처에서는 상단 동작 버튼, 선택된 보기, 속성 탭, 하단 카메라 도구가 모두 밝은 테두리·그림자·푸른 표면을 사용한다. 화면은 통일되어 있지만 기능의 우선순위보다 모든 조작부의 입체감이 먼저 읽힌다.

근거: [tokens.css](../../apps/web/src/styles/tokens.css)의 승인된 버튼 proposal A 토큰, [untitled.css](../../apps/web/src/components/ui/untitled.css) 690–753행, [editor-topbar.css](../../apps/web/src/styles/editor-topbar.css) 10–19행의 더 진한 상단 버튼 표면.

제안:

- 일반 동작은 기존 입체감을 약하게 유지한다. 그림자 강도를 전부 없애는 일괄 평면화는 피한다.
- 주요 생성 동작은 같은 형태 안에서 글자 굵기와 테두리 대비를 높여 한 단계 강조한다. 현재 제품의 동작 우선순위를 확인하기 전 모든 추가 버튼을 강한 파랑으로 바꾸지 않는다.
- 지속되는 선택 상태는 옅은 파란 면과 명확한 테두리/텍스트로 표시한다. 눌림은 짧은 inset 변화, hover는 표면 변화, 키보드 포커스는 독립된 외곽선으로 구분한다.
- 보기 전환과 동작 버튼을 이동시키지 않고도 그룹 간 여백과 배경 처리로 구별할 수 있다. 논리 설계와 검증 메뉴는 유지한다.

완료 판단: 상단·속성·카메라 도구에서 기본/hover/pressed/selected/focus를 나란히 비교해 겹치지 않는 역할로 읽히는지 확인한다.

## 2순위: 속성·핀 패널을 같은 시각 체계로 정돈한다

속성은 회색 바탕 위에 선택 요약·탭·여러 카드가 겹치고, 핀은 밝은 단일 면에 헤더·필터·본문이 이어진다. 기능 차이는 타당하지만 두 패널의 제목 시작선과 표면 단계가 달라 서로 다른 UI 묶음처럼 보인다.

근거: [native-project-view.css](../../apps/web/src/features/projects/native-project-view.css) 70–91행, [inspector.css](../../apps/web/src/styles/inspector.css) 28행 이후 헤더와 127행 이후 섹션, [comments.css](../../apps/web/src/features/comments/comments.css) 330행 이후.

제안:

- 같은 바깥 패널에 공통 배경·세로 경계·제목 패딩을 적용하고, 제목/도구/스크롤 본문이라는 상위 정렬 규칙을 맞춘다.
- 속성의 기본 정보·컬럼 구분은 유지하되 배경색, 테두리, 그림자를 동시에 강하게 쓰지 않는다. 이미 내부 중첩 섹션을 왼쪽 선으로 표현하는 규칙은 유지한다.
- 선택 객체 요약만 눈에 띄게 두고, VIEW 같은 보조 캡션과 반복된 위치 정보는 더 조용한 계층으로 둔다. 약하게 만든다는 것은 읽기 어려운 대비로 낮춘다는 뜻이 아니다.
- 반경 후보는 컨트롤 8px, 섹션 10px, 떠 있는 패널 12px처럼 역할별로 정리한다. 같은 반경을 모든 객체에 강제하지 않는다.

완료 판단: 두 패널 동시 표시 시 제목·내용 시작선과 경계 강도가 일관되고, 어느 객체를 편집하는지 즉시 구별된다.

## 3순위: 작은 글자를 보완하고 타이포그래피 단계를 줄인다

코드에는 9–12px의 보조 정보부터 26px 캔버스 테이블 제목까지 여러 크기가 존재한다. 줌 100% 캡처에서 테이블 제목은 강하게 보이는 반면 DB 정보와 일부 버튼 라벨은 상대적으로 작다. 캔버스 글자는 줌의 영향을 받으므로 문서 바와 같은 크기로 맞추는 일괄 수정은 적절하지 않다.

근거: [native-project-view.css](../../apps/web/src/features/projects/native-project-view.css) 134–145행의 11px 문맥 정보, 같은 파일 369행 이후의 12px 주요 도구, [NativeERDCanvas.css](../../apps/web/src/features/projects/NativeERDCanvas.css) 625–635행의 26px 테이블 제목. 이전 갤러리 대비 측정은 [기존 보고서](2026-10-11-UI-AppleDesignReview.md)에 있다.

제안 시작값(확정 사양 아님):

| 역할 | 후보 크기·굵기 | 적용 주의 |
| --- | --- | --- |
| 본문·입력 | 14px / 400–500 | 현재 폼 밀도 유지 |
| 도구·라벨 | 13px / 500–600 | 영어 라벨과 긴 이름도 확인 |
| 보조 정보 | 12px / 400–500 | 크기보다 충분한 대비를 먼저 확보 |
| 패널 제목 | 14–16px / 600 | 역할마다 범위를 확정 |
| 캔버스 테이블명 | 현재 26px과 22–24px 후보 비교 | 75/100/125% 줌과 긴 이름으로 비교 |

보조 텍스트는 기존 `--muted`를 후보로 삼되 각 실제 배경에서 대비를 재측정한다. 작은 글자를 더 옅게 해서 위계를 만드는 방식을 피하고 굵기·간격을 함께 사용한다. 캔버스 제목 축소는 후보일 뿐 확정 변경이 아니다.

## 4순위: 배경 격자와 비선택 카드의 시각적 무게를 낮춘다

캡처에서 빈 캔버스 전역의 점 패턴이 지속적으로 눈에 들어온다. 카드와 선택 테두리만큼 배경 점도 또렷하면 실제 테이블이 많아졌을 때 관계선과 내용에 집중하기 어려울 수 있다. 현재 표본은 테이블 두 개이므로 대형 ERD에서의 피로도는 검증된 사실이 아닌 가설이다.

근거: [tokens.css](../../apps/web/src/styles/tokens.css) 5–8행의 캔버스·격자 토큰과 [NativeERDCanvas.css](../../apps/web/src/features/projects/NativeERDCanvas.css) 604–618행의 테이블 표면·선택 그림자.

- 격자색 `#818894`보다 밝은 중립색 후보 `#b8c0ca`를 비교한다. 실제 opacity와 확대율을 함께 확인한 뒤 정한다.
- 비선택 카드의 그림자는 약하게 유지하고 선택 테두리와 포커스는 더 분명하게 둔다.
- 도메인 색상과 관계선은 정보 전달용이므로 배경을 약하게 만들 때 같이 흐리게 하지 않는다.
- 배치 동작·노드 좌표·관성은 변경하지 않는다.

완료 판단: 20개 이상 테이블의 실제 문서에서 관계선, 선택 객체, 컬럼 내용이 격자보다 먼저 읽힌다. 해당 큰 문서 검증은 아직 수행하지 않았다.

## 5순위: 갤러리의 장식 여백과 정보 밀도를 맞춘다

소스 기준 갤러리는 바깥 세로 패딩 40px, hero 패딩 40/30px, 제목 44px, 미리보기 높이 196px를 사용한다. 여유 있는 분위기는 유지하되 반복 방문 화면에서는 소개보다 프로젝트명·DB·수정 정보가 빨리 읽히게 할 수 있다.

근거: [project-gallery.css](../../apps/web/src/features/projects/project-gallery.css) 1–24, 173–175, 192–217행.

- 프로젝트가 있는 상태에서 hero 높이와 미리보기 높이를 각각 약 20% 줄인 후보를 비교한다. 빈 상태는 현재의 여유를 유지할 수 있다.
- 카드 이름·보조 정보·날짜의 기준선과 세로 간격을 정돈하고, 카드 내 메타데이터 대비를 높인다.
- 기존 새 프로젝트 카드의 텍스트·아이콘 강도를 조정한다. 상단으로 옮기거나 목록 보기를 추가하는 구조 변경을 이번 시각 개선에 묶지 않는다.
- 갤러리와 편집기의 공통 컨트롤은 같은 폰트·반경·포커스 규칙을 사용한다.

## 통합된 디자인 방향

| 요소 | 유지 | 개선 |
| --- | --- | --- |
| 브랜드 | 차분한 회색·블루, 기존 입체 버튼 | 블루와 그림자에 역할 부여 |
| 레이아웃 | 갤러리 / 캔버스 / 우측 패널 | 정렬과 표면 계층 정돈 |
| 메뉴 | 논리 설계·검증 항목의 현재 위치 | 위치 변경 없음 |
| 정보 | 현재 보기·선택 객체·저장 상태 | 글자 크기와 대비 체계화 |
| 여백 | 읽기 편한 기본 간격 | 그룹 안은 좁게, 그룹 사이는 넓게 |

간격 후보는 4/8/12/16/24px를 기본 단위로 삼아 같은 역할끼리 정리한다. 기존 10/14px 등을 기계적으로 치환하거나 승인된 모든 버튼 폭을 동시에 바꾸지는 않는다.

## 근거·검증·한계

- 기존 데스크톱 캡처 `ui-composition-desktop.png`를 직접 다시 확인하고 실제 CSS 정의와 대조했다. 캡처 경로: `C:\Users\TY\.codex\visualizations\2026\10\10\01a12667-c321-7f80-be51-c759af309fa6\ui-composition-desktop.png`.
- 캡처는 축약한 헤더와 테스트 데이터를 사용하는 fixture다. 전역 헤더의 절대 여백과 fixture 카드 겹침은 평가 대상에서 제외했다.
- 이전 갤러리 저장 이미지에는 캡처 크기 문제가 있어 데스크톱 디자인 판단의 이미지 근거로 사용하지 않았다. 갤러리 관련 의견은 CSS 구조와 이전 검토 기록에 근거한 제안으로 제한했다.
- 이번에 여러 프로젝트를 넣은 임시 갤러리 화면을 준비했으나 브라우저 연결을 사용할 수 없어 신규 렌더링 검증은 완료하지 못했다. 후보 색상·간격·타이포그래피를 실제 적용한 결과나 개선 효과를 검증했다고 주장하지 않는다.
- 제품 구현 변경이 없는 문서 검토이므로 코드 테스트는 재실행하지 않았다. 변경 문서의 상대 링크, 오래된 문서 경로, diff 공백과 커밋 범위를 확인한다.
- 모바일 항목은 지원 범위 밖, 메뉴 위치는 사용자 결정으로 유지한다. 둘 다 후속 수정 목록에 포함하지 않는다.
