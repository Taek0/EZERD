# 테이블·관계·사용자명 피드백 통합 QA

작성일: 2026-09-15

## 구현

- 컬럼 편집 타입/ENUM 순서 교환, NULL/comment 숨김 시 현재 뷰 카드 실제 너비 축소 및 수동 여백 보존.
- 카드 제목 28px/본문 20px, 컬럼명에서 Tab으로 타입 검색 자동 진입.
- ENUM 팝업 애니메이션 및 reduced-motion, FK ON DELETE/ON UPDATE 기본 편집 영역 노출.
- 관계 끝점 표시를 작은 채운 점으로 변경하고 포인터 영역 유지.
- 도메인 관계 필드 즉시 반영, 수정 버튼 제거. 무효 이름은 기존 값 보존.
- 도메인 뷰의 카드 고정 상태에서 개인 관계 경로 조절 허용. 개인 경로는 현재 프로젝트 세션에 유지되고 공유 전송에서 제외된다.
- 사용자명 trim/소문자 정규화와 이름 단독 고유성. 같은 이름+PIN 재접속, 다른 PIN 거부.

## 검증

pnpm check 통과: 단위 테스트 278개, 타입 검사, Prettier, 전체 빌드. 기본 검사에서 제외된 DB 테스트 20개는 별도 임시 PostgreSQL DB에서 모두 통과했다. QA에서 발견한 온라인 FK 구조 의존성 충돌을 별도 수정했다.

browser-direct-editing-smoke.mjs에서 컬럼명 Tab→타입 검색, 카드 타입/NULL/PK 편집, FK 생성 및 관계선 이동/취소/저장을 확인했다. browser-table-feedback-smoke.mjs에서 도메인 관계 즉시 저장, 타입/ENUM 위치, 숨김 너비 감소, 제목 폰트, ENUM 애니메이션, FK 액션 노출, 작은 끝점, 도메인 뷰 카드 고정과 선 이동을 확인했다.

## 미완료: 실제 DB 사용자 초기화 및 마이그레이션

실제 DB 기존 사용자 16개, 정규화 충돌 2그룹, 프로젝트 1개를 확인했다. QA DB는 실행 후 삭제했다.

reset-users.ts는 명시적 실행 플래그와 로컬 DB 제한, 트랜잭션, 프로젝트 문서 해시/버전/동기화 순서 보존 검증을 갖춘 검토용 스크립트다. 현재 FK 참조 때문에 사용자 삭제 전에 핀 대화와 사용자 동기화 히스토리를 삭제하도록 준비했다.

자동 승인 검토가 이 범위를 사용자 정보 삭제의 명시적 허용 범위 밖으로 판단해 실행을 거부했다. 실제 데이터 삭제 및 실제 DB 마이그레이션은 수행하지 않았다. 핀/히스토리 삭제까지의 추가 허용 또는 내용 보존·작성자 익명화 방향 결정이 필요하다. 승인 없이 우회 실행하지 않는다. QA 서버는 종료했고, 미적용 DB 제약과 새 코드의 충돌을 막기 위해 개발 API도 중지했다.
