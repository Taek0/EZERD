# 사용자 이름 + PIN 복합 키 적용 및 DB 검증

작성일: 2026-09-15

사용자 이름 단독 UNIQUE를 (username, pin_hash) 복합 UNIQUE로 바꿨다. 등록시 숫자 4자리 PIN을 필수로 받으며 앞자리 0을 보존한다. 같은 이름이라도 PIN이 다르면 등록 가능하고 같은 조합은 409로 거부한다. 이름 변경은 기존 PIN 해시를 유지한다. PIN은 SHA-256 해시로 저장하며 사용자 응답에는 원문과 해시 모두 포함하지 않는다. 기존 사용자 ID 기반 흐름을 유지한다.

users.color는 기본값 #4169e1인 HEX 색상으로 저장한다. 이름 또는 색상의 부분 변경을 허용하고 잘못된 색상·빈 변경을 거부한다. PIN은 등록 전용 입력이며 프로필 부분 변경에서는 받지 않는다.

0004_cool_sentry를 생성·적용했다. 사용자 초기화는 승인 범위에 따라 관련 테이블, 프로젝트, 마이그레이션 저널을 잠근 SERIALIZABLE 트랜잭션에서 백업·리뷰/사용자 삭제·스키마 적용·프로젝트 전체 행 불변을 검증한 뒤 커밋했다. 실행 직전 사용자·핀·메시지·알림은 이미 모두 0건이었다. 프로젝트 2개는 그대로 유지했다. 새 마이그레이션이 정확히 하나 미적용인 경우만 허용하므로 초기화 재실행을 방지한다.

- 비공개 백업: .cache/backups/identity-pin-reset-2026-09-15T03-43-30.632Z.json
- 실행 기록: .cache/backups/identity-pin-reset-receipt.json
- 테스트 종료 후 검증: .cache/backups/identity-pin-final-verification.json
- 최종 상태: 프로젝트 2개, 사용자·핀·메시지·알림 각 0건, 프로젝트 전체 행 해시 동일, 마이그레이션 5개, API HTTP 200.

DB 시작 전 Docker 4.83.0의 dockerInference 잔존 소켓 오류가 재발했다. 종료된 런타임 폴더만 run.ezerd-backup-20260915-123931 및 docker-secrets-engine.ezerd-backup-20260915-123931로 보관하고 엔진과 기존 Compose PostgreSQL을 시작했다. .data/postgres 및 127.0.0.1:15432 설정을 그대로 사용했다.

검증: 계약 테스트의 실패를 먼저 확인한 뒤 구현했다. 별도 임시 DB 스키마에서 통합 테스트 12개, 실제 DB에서 통합 테스트 12개가 통과했다. 동일 이름/다른 PIN, 동일 조합 중복, 동시 등록 충돌, 앞자리 0, PIN 비노출, 색상 변경과 이름 변경시 색상 유지가 포함된다. pnpm db:migrate 재실행은 추가 변경 없이 성공했다. 전체 pnpm check의 타입 검사·149개 단위 테스트·프로덕션 빌드도 통과했다.

다른 DB에 0004를 적용할 때 기존 사용자가 있으면 PIN 해시를 임의로 만들 수 없으므로 별도의 사용자 이관 또는 초기화 정책이 필요하다. 이번 초기화는 로컬 EZERD DB에만 실행했다.
