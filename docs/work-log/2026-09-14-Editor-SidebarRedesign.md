# 편집기 사이드바 재구성 작업 기록

기록일: 2026-09-14

계획: [편집기 사이드바 재구성 계획](../planning/2026-09-14-Editor-SidebarRedesign.md)

프로젝트를 연 이후의 편집기 화면에서 오른쪽 속성 패널의 정보 구조를 다시 짰다. 기능을 제거하지 않고 위치와 구성만 바꿨다. 랜딩 화면과 프로젝트 갤러리는 건드리지 않았다.

## 1. 바뀐 것

### 패널 뼈대

선택 상태에 따라 패널 전체를 교체하던 구조를 **고정 머리말 + 스크롤 본문**으로 바꿨다. 머리말에는 현재 뷰 이름, 선택한 항목의 종류·이름과 선택 해제 버튼, 그리고 `속성` / `목록` 탭이 항상 남는다. 선택이 바뀌어도 이 영역은 사라지지 않는다.

장식용 `02 / INSPECTOR` 표기를 제거하고 그 자리를 현재 위치 표시로 바꿨다.

### 탭 분리

| 탭 | 내용 |
| --- | --- |
| 속성 | 선택한 도메인·텍스트·테이블의 편집 항목. 선택이 없으면 현재 뷰 요약과 생성 폼 |
| 목록 | 검색 입력과 현재 화면의 객체 목록. 도메인 맵은 도메인·도메인 관계, 도메인 내부는 테이블·테이블 관계·다른 도메인 테이블 |

목록에서 항목을 고르면 선택이 바뀌면서 속성 탭으로 이동한다. 다른 도메인 테이블 행을 고르면 이 화면에 원본 참조로 추가한다.

### 접기 UI 통일

`Accordion`, `DisclosureButton` + `Collapse`, 일반 섹션이 섞여 있던 것을 `PanelSection` 하나로 통일했다. 새 파일 `apps/web/src/panel.tsx`에 `PanelSection` · `PanelList` · `PanelRow` · `PanelNote`를 두고 캔버스와 테이블 편집기가 함께 쓴다.

`PanelSection`은 접힌 상태에서도 내용을 DOM에 유지한다. 제목 옆의 개수 표시와 접근성 이름이 열고 닫는 것과 무관하게 일정하다. 필요한 곳에서는 `open`과 `onOpenChange`로 외부 상태와 동기화한다.

### 테이블 속성의 중첩 완화

아코디언 7개를 한 화면에 쌓던 구성을 다음 다섯 구역으로 정리했다.

| 구역 | 내용 |
| --- | --- |
| 기본 정보 | 적용 범위, 논리·물리 이름, 스키마, 정의, 주석 |
| 컬럼 | 컬럼 목록, 선택한 컬럼의 편집 영역, 컬럼 추가 |
| 키 · PK / UNIQUE | 키 편집과 추가 |
| 테이블 관계 | FK 출발 컬럼, 관계 편집과 추가 |
| 사용자 정의 메타데이터 | 공통·논리·물리 JSON |

컬럼은 아코디언 안의 아코디언이 아니라 **목록에서 고르면 바로 아래에 편집 영역이 열리는 방식**으로 바꿨다. 접기 중첩은 최대 2단이다.

### 툴바

생성 동작을 사이드바 아코디언에서 캔버스 툴바로 옮겼다.

```text
도메인 맵    도메인 맵 | ＋ 도메인  ＋ 텍스트  [패널 토글]
도메인 내부  도메인 맵 / 결제 | 논리+물리·논리·물리 | ＋ 테이블  ＋ 텍스트  ENUM  [패널 토글]
```

툴바 아래 별도 줄이던 표시 모드 선택은 세그먼트 버튼 한 벌로 합쳤다. 프로젝트 공통 ENUM은 사이드바 아코디언에서 대화상자로 옮겼다.

자동 배치는 [편집 워크플로우 결정 사항](../planning/EDITOR_WORKFLOW_DECISIONS.md)대로 빈 캔버스 우클릭 메뉴에만 남겼다. 툴바 버튼을 추가하지 않았고 회귀 테스트로 고정했다.

### 그 밖의 정리

- 설계 확인 알림을 패널 상단 고정 블록에서 개수가 붙은 접기 구역으로 바꿨다.
- 위치·크기 숫자 입력 4개를 접힌 `위치와 크기` 구역으로 옮겼다.
- 삭제 동작을 각 패널 하단의 구분된 영역으로 모았다.
- 컬럼 추가 표의 `min-width: 570px`를 없애고 패널 폭에 맞춰 접히는 격자로 바꿨다. 사이드바 안 가로 스크롤이 사라졌다.
- 도메인 색상 입력을 44px 전폭 컨트롤에서 38px 색상 견본으로 줄였다.

## 2. 기능 이동 결과

| 기존 위치 | 현재 위치 |
| --- | --- |
| 사이드바 새 도메인 생성 | 툴바 `＋ 도메인`, 속성 탭 `새 도메인 만들기` |
| 사이드바 새 테이블 생성 | 툴바 `＋ 테이블`, 속성 탭 `새 테이블 만들기` |
| 사이드바 프로젝트 ENUM | 툴바 `ENUM` 대화상자 |
| 사이드바 테이블 검색 | 목록 탭 검색과 `이 화면의 테이블` |
| 사이드바 외부 테이블 참조 | 목록 탭 `다른 도메인 테이블` |
| 사이드바 연결된 관계 검색 | 목록 탭 검색과 `연결 강조` |
| 사이드바 도메인 관계 목록 | 목록 탭 `도메인 관계` |
| 툴바 아래 표시 모드 줄 | 툴바 세그먼트 |

없앤 기능은 없다.

## 4. 검증

- `pnpm check` 통과. 타입 검사, 테스트 96건 통과·9건 건너뜀, 전체 빌드 성공.
- 새 테스트 4건으로 다음을 고정했다.
  - 패널 머리말과 두 탭이 항상 렌더링된다.
  - 속성 탭이 열려 있을 때 목록 탭 내용이 함께 렌더링되지 않는다.
  - 툴바에 생성 동작이 있고 자동 배치는 없다.
  - 보관한 프로젝트에서도 같은 뼈대를 유지하며 생성 버튼이 비활성화된다.
- 기존 테이블 편집기 회귀 테스트(소유 도메인 표시, 논리 전용 컬럼 가시성, 읽기 전용 `fieldset`, 모델 보기 선택, 까마귀발 표기)는 그대로 통과한다.

### 하지 못한 검증

이번 세션에서는 브라우저 자동화를 실행할 수 없었다. 도구가 쓰는 Node 커널이 Windows 샌드박스 준비 오류로 기동하지 않았다. 그래서 실제 브라우저 화면 캡처 대신 서버 렌더링 마크업 검사로 구조를 확인했다. 다음 항목은 화면에서 직접 확인하는 것이 남아 있다.

- 280px 최소 폭과 520px 최대 폭에서의 줄바꿈과 여백.
- 좁은 작업 영역에서 패널이 아래로 배치될 때의 높이.
- ENUM 대화상자의 포커스 이동과 배경 스크롤.

## 5. 이어서 볼 것

- 목록 탭의 검색이 현재 뷰 안에서만 동작한다. 프로젝트 전체 검색이 필요한지 확인이 필요하다.
- 컬럼 편집 영역이 목록 아래에 열리므로 컬럼이 많으면 스크롤 이동이 생긴다. 선택 시 스크롤 위치를 맞출지 결정이 필요하다.
- `.table-edit-card`, `.inspector .relation-list` 등 더 이상 쓰지 않는 규칙이 `table-editor.css`와 `styles.css`에 남아 있다. 정리 시점을 따로 잡는다.
