# 테이블 편집 워크플로 구현 결과

- 작업일: 2026-09-14
- 계획: `../planning/2026-09-14-Editor-Implementation.md` 및 기존 편집 의사결정 문서

## 구현

- 함께 보기에서 물리 테이블명을 위에 표시하고 논리명을 아래에 표시한다. 제목과 컬럼 속성은 더블클릭으로 편집하며 Enter/blur 저장, Escape 취소를 지원한다.
- 컬럼 행은 PK/FK/UQ, 속성, 타입, NULL 여부, 주석으로 구성하고 동시 PK/FK 표시를 지원한다. 좁은 카드에서는 내부 스크롤로 충돌을 방지한다.
- 카드의 + 버튼과 표 형태 컬럼 생성 폼을 제공한다. 새 컬럼만 NOT NULL을 기본값으로 사용하고, PK는 기본 미선택이며 선택 시 기존 복합 PK에 추가한다. 새 컬럼은 소유 테이블의 모델 범위를 따른다.
- 속성·컬럼·키·관계 패널을 독립적인 접기/펼치기로 구성한다. 프로젝트 ENUM 생성/편집/삭제 및 컬럼 ENUM 선택을 제공한다. 빈 ENUM 레이블도 보존한다.
- UNIQUE 체크박스의 선택 순서로 하나의 복합 키를 만든다.
- 컬럼 우클릭 또는 사이드바의 출발 컬럼 선택 후 대상 테이블을 클릭하면 FK 확인 대화상자를 연다. 대상 PK/UNIQUE와 순서별 출발 컬럼 대응, 양쪽 끝점 카디널리티와 설명을 확인한 후 생성한다.
- FK 생성 전에 기존 PostgreSQL 내보내기 검증기의 해당 관계 진단을 사용한다. 물리 전용 테이블에서는 물리 전용 관계를 생성하며 컬럼·키를 자동 생성하지 않는다.
- 양쪽 끝점 까마귀발과 0/1/N 표기를 제공한다. 관계 라벨은 물리 테이블·출발 속성·대상 테이블로 구성하고 설명은 툴팁에 표시한다. 관계 우클릭으로 삭제할 수 있다.
- 동일 테이블 쌍 관계의 선과 라벨은 별도 경로를 사용한다.

## 검증

- `pnpm --filter @ezerd/web typecheck` 통과.
- `pnpm exec vitest run apps/web/src/TableEditor.test.ts` 9개 테스트 통과 (명시적 끝점 라벨과 까마귀발 일치 검증 포함). 까마귀발 도입에 따른 양쪽 marker 기대값 갱신. SSR 환경의 document 접근 회귀도 수정했다.
- `scripts/browser-table-workflow-smoke.mjs` 로컬 Vite + 별도 Headless Chrome 테스트 통과: 물리명 우선, Enter 저장/Escape 취소, 신규 컬럼 NOT NULL, FK 확인 전 미생성 및 확인 후 대응 저장, 복합 UNIQUE, ENUM 생성, 표형 폼의 PK/NOT NULL 기본값, FK 양쪽 카디널리티 선택 저장, 관계 우클릭 삭제.
- `.cache/table-workflow.png` 캡처를 직접 검토하고 좁은 속성 패널의 폼 넘침을 수정했다.
- 기존 갤러리 스타일과 사용자 변경 문서는 수정하지 않았다.

- 실제 Canvas 통합에서 포인터 캡처가 더블클릭을 가로채는 회귀를 발견하여, 카드 선택 후 인라인 셀에서는 드래그 캡처를 건너뛰도록 Canvas 담당자와 수정했다.

- FK 확인 대화상자를 열기 전 활성 요소를 저장하여 취소/확인 후 연결된 이전 컨트롤로 포커스를 복원하도록 순서를 수정했다.
