# MCP 조회 비용 절감과 관계선 진단

## 조회 경로

- 목록·요약·화면·관계·상세·배치 진단은 별도 Native 공유 조회를 사용한다. 전체 문서 preview 및 DB 진단을 반복 구성하지 않는다.
- 공유 화면·도메인 필터 조회는 개인 상태를 읽지 않는다. 개인 뷰 ID를 요청한 경우만 자신의 개인 상태를 합친다.
- 요약과 테이블 상세의 개인 상태는 `includePersonal: true`로 명시한다. 기본값은 false다.
- 개인 상태와 공유 문서의 version/sequence/DB revision이 다르면 한 번 재조회한 뒤 계속 다를 경우 충돌을 반환한다. 서로 다른 시점의 문서를 섞지 않는다.
- 전체 원본이 필요하지 않으면 작업 후 화면·관계 조회와 배치 진단을 사용하도록 MCP 지침도 수정했다.

## 관계선 진단

- `diagnose_layout`에 물리/논리 mode를 추가했다. MCP 기본값은 physical이다.
- 테이블 자동·수동 경로를 웹과 같은 라우터로 재구성하고 카드 내부 관통, 선분 겹침, 교차/접촉을 관계 ID·선분 인덱스·좌표와 함께 반환한다.
- `coverage.complete`, `checkedRoutes`, `skippedRoutes`, `comparisons`, `modes`, `limitations`로 검사 범위를 표시한다.
- 저장 노드와 선분 중심선이 대상이다. 임시 초안·화면 필터·생성 preview 노드 및 도메인 곡선은 완전 검증 대상으로 간주하지 않는다. 도메인 관계는 미검증으로 표시한다.
- 경로 재구성은 뷰당 카드·관계 각각 200개, 교차 후보 비교는 100,000회로 제한한다. 제한·결과 건수 초과 시 검증 완료로 보고하지 않는다.
- 배치를 자동으로 수정하지 않는다. 일괄 상세 조회·페이지 버전 고정·변경분 조회는 후속 범위다.

## 검증

- 전체 `pnpm check` 통과: 테스트 2,818개 통과(498개 조건부 건너뜀), 타입·포맷·빌드 성공. 기존 번들 크기 경고는 남아 있다.
- 격리 PostgreSQL DB 마이그레이션 및 MCP 통합 시나리오 8개 통과. 운영 DB 변경은 하지 않았다.
- 권한 캐시 경계·원본 보존·공유/개인 읽기 분리·버전 불일치 및 경로 계산 회귀 테스트를 추가했다. 전체 응답 시간의 실제 환경 벤치마크는 수행하지 않았다.
