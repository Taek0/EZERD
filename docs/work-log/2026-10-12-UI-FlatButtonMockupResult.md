## 반영 방향

사용자가 선호한 좌측 독립 탐색 구조와 기존 메뉴 위치를 유지했다. 기존 목업 파일을 보존하고 버튼 변경만 비교 가능한 별도 버전을 만들었다.

| 역할 | 표현 | 사용 예 |
| --- | --- | --- |
| 주요 동작 | 차콜 단색 #263347, 흰 글자 | 테이블 추가, 답글 등록 |
| 보조 동작 | 흰색 면, 얇은 중립 테두리 | 내보내기, ENUM |
| 텍스트·아이콘 동작 | 투명 배경, hover에서만 옅은 면 | 히스토리, 뒤로, 더 보기 |
| 지속 선택 | 옅은 회청색 #E8EDF5, 명확한 경계 | 도구, 패널 토글 |
| 위험 동작 | 붉은 텍스트와 옅은 경계 | 상태표의 삭제 예시 |

- 버튼 그라데이션과 입체 그림자를 제거했다.
- 기본 / hover / pressed / disabled를 역할별로 비교하는 상태표를 추가했다.
- 키보드 focus는 2px 외곽선, loading은 spinner·aria-busy·일시 비활성으로 분리했다.
- 일반 컨트롤 높이는 32px, 반경은 역할에 따라 6–8px를 기준으로 한다. 작은 캔버스 내부 동작은 기존 밀도를 유지한다.
- 상단 비교 컨트롤은 버튼 표현만 전환한다. 이전 레이아웃으로 되돌리지 않는다.
- 상태표는 비교용 예시이며 삭제 등 실제 데이터 동작은 하지 않는다.

## 브라우저 검증

- 제안 모드의 #app button 계산된 스타일 검사: background-image가 none이 아닌 버튼 0개, box-shadow가 none이 아닌 버튼 0개.
- 주요 버튼의 실제 배경색 rgb(38, 51, 71) 확인.
- 이전 버튼 비교 시 주요 버튼 background-image가 linear-gradient로 바뀌고, 좌측 탐색 너비 214px가 유지되는 것을 확인.
- 비활성 선택 버튼의 글자색 rgb(163, 175, 191)과 상태 우선순위 확인.
- 로딩 예시 클릭 → aria-busy=true / disabled=true → 완료·재시도 표시 확인.
- 실제 Tab 키 이동으로 메모 버튼에 focus-visible=true, rgb(82,120,183) solid 2px 외곽선 표시 확인.
- 전체 적용 화면과 버튼 전용 화면의 실제 렌더링 확인. 관찰한 콘솔 error 로그 없음.
- Node vm.Script로 5개 스크립트 블록 문법 검사 통과.
- 뷰포트 override가 실제 탭에 적용되지 않은 상태도 관찰했으므로 요청한 1440px로 검증했다는 주장은 하지 않는다. 연결된 탭과 데스크톱 최소 폭 레이아웃에서 확인했다.
- 제품 코드 변경이 없는 목업이므로 제품 테스트는 재실행하지 않았다. docs는 Prettier 제외 대상이다.
