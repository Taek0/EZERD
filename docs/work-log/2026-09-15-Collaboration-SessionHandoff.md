## 새 세션 시작 지시

D:\ChatGPT\ERD에서 기존 미커밋 작업을 보존하고 자동 저장 동기화 구현을 중단 지점부터 완료한다. 사용자 요청은 새 세션 생성과 전체 인수인계였다. 새 세션 생성 도구가 실패했으므로 생성 성공을 가정하지 않는다. 원본 디렉터리를 직접 사용하거나 현재 작업 트리를 포함해 시작하고 미추적 파일까지 있는지 확인한다.

구현 서브에이전트는 gpt-5.6-sol medium, 리뷰는 gpt-6-astra low로 지정한다. 사용자는 이후 짧은 작업부터 주 에이전트가 직접 수행하는 것도 허용했다. AGENTS.md에 따라 계획·결과 문서와 작은 독립 커밋을 남긴다. 승인된 정책이나 네 파일 커밋 승인을 다시 묻지 않는다.

## 확정 정책 요약

저장 버튼 제거, 입력 약 500ms 정지/blur·드래그 종료·선택 확정 시 자동 저장, IME 중 전송 금지. 객체·속성 묶음 기반 병합과 서버 마지막 승인 우선, 삭제 우선, 구조 작업 원자성. 서버가 검증한 마지막 성공 동기화 후 24시간 이내의 충돌 없는 오프라인 작업만 자동 적용한다. 작업 생성 시각을 기준으로 삼지 않는다.

변경·삭제 이력 7일, 중복 결과·삭제 표식 최소 7일, 미저장 로컬 편집 7일 및 만료 예고. 별도 복구함 대신 변경·삭제·미반영 편집 통합 이력과 새 ID 복원, 유효한 종속 관계만 복원하고 누락 안내. 모든 사용자 동일 권한과 서버 세션. 단일 Nest/PostgreSQL/ws, 최대 동시 수정 5명과 전송 후 반영 1초 목표. 조합뷰 내용 편집 허용, 카드 위치·관계선 배치는 공유 원본 뷰에서만 편집하고 개인 배치는 저장하지 않는다. 개인 줌·선택·뷰는 공유에서 제외한다. undo/redo는 다른 사람의 후속 변경을 보호한다.

## 마지막 리뷰와 다음 순서

1. 서버 sync.service.ts의 삭제 undo 재시도에서 restore/undo 명령 지문 불일치로 409가 발생하는 문제와, 누락 참조로 제외한 관계의 배치 정보 정리를 수정·회귀 검증한다.
2. 웹 sync-client.ts 재작성 중 중단됐다. 타입 오류, 불변 baseline/작업 나이, 의존 작업 순서, 늦은 ACK의 최신 문서 보호, 시작 전 편집과 종료 후 콜백을 확인한다.
3. IndexedDB 트랜잭션 완료 이후 전송, 만료 판정 전에 승인 불명확 작업 결과 조회, 실제 오프라인 새로고침 복원과 로컬 사용자 분리를 검증한다.
4. IME·debounce·blur·드래그 저장, 작업 단위 undo/redo, 이력 복원·재적용·복사·폐기, 조합뷰 내용/배치 제약 및 원본 갱신을 확인한다.
5. 실제 PostgreSQL의 동시 중복 요청, 24시간/7일 경계, 복원 그래프·삭제 undo 재시도·타인 undo 차단, 인증 적용 기존 API 회귀와 마이그레이션 재실행을 검증한다.
6. 기존 scripts/browser-*는 저장 버튼/전체 PUT에 의존한다. 새 흐름에 맞추고 실제 5개 컨텍스트의 수렴·마지막 이벤트 유실·핀 이벤트·오프라인·입력 동작을 검증한다.
7. 검증된 단위마다 Astra low 리뷰, 작업 기록, 범위를 지정한 커밋을 수행한다.

## 검증 한계

서버 담당 보고 기준 타입 검사와 실제 PostgreSQL autosync/auth 2파일 4테스트 통과, migration 0005 적용. 웹 22파일 88테스트 통과 보고는 runtime 재작성 전이며 당시 타입 오류 3개가 남았다. sync-client 테스트는 주로 helper를 검사해 runtime 경합을 입증하지 못했다. 전체 최신 통합 검사와 실제 5브라우저 검증은 미완료다. 새 세션은 과거 통과를 현재 결과로 주장하지 않는다.

## 실행 환경과 오류

Windows PowerShell, Node 24.18.1, pnpm 11.24.0. 일반 shell/apply_patch는 정상이나 Git 인덱스 쓰기는 sandbox 접근 거부였다. require_escalated 커밋은 자동 승인 검토 서비스가 429로 실패했다. Sol 및 Astra 서브에이전트를 여러 번 재시도했으나 모두 즉시 429였다. 이번 새 작업 생성도 동일한 자동 승인 검토 429로 실패했다. 세션 자체 문제인지는 확정되지 않았다. 재개 시 한 번 확인하되 반복 재시도나 승인 차단 우회는 하지 않는다.
