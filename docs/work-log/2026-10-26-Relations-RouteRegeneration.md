# 기존 관계의 경로 재생성 수정

- 삭제 이력이 있는 __tables__ 관계선 경로도 현재 서버 문서에 해당 관계, 양쪽 테이블 및 배치가 존재하면 재생성할 수 있다.
- 경로 스키마·경로 쌍 식별자·좌표 검증을 적용한다. 제출된 후보가 아니라 현재 저장 문서로 대상 존재를 확인한다.
- 테이블·컬럼·관계·노드 등 실제 객체의 삭제 식별자 재사용 방어는 유지한다. 같은 요청에서 객체를 되살려 경로 재생성 조건을 우회할 수 없다.
- 새 경로의 관계·테이블 존재 의존성을 기존 시퀀스 충돌 검사에 전달하여 더 최신 관계 변경·테이블 삭제를 보호한다. 별도 시간 비교나 잠금 체계는 추가하지 않았다.
- 기존 relation history 복원 경로는 유지한다. 일반 경로 재생성 후 실행취소도 정상 동작한다.
- 단위 테스트 33개, 임시 PostgreSQL의 이력·배치 저장 통합 테스트 36개 및 서버 빌드 통과.
- Klassboard version 458 / sequence 469 문서와 기존 경로 버전 기록으로 로컬 재현: 이전 sync.identity-retired 대신 prepared, 관계선 247개 통과. 실제 프로젝트에 저장하지 않았다.
- 호스팅 재빌드·서버 재시작 후 자동 관계선 정리를 다시 실행하면 된다. DB 마이그레이션이나 삭제 이력 초기화는 필요하지 않다.
