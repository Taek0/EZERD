[계획](../planning/2026-10-21-Relations-SearchPerformancePlan.md)에 따라 격리된 codex/performance-lab에서 구현했다. 원격 main 기준은 880f9bc이며 이전 HWP 대체 연결면 수정도 포함한다. 실제 프로젝트와 실행 서버는 변경하지 않았다.

## 고정 입력과 비교 방법

- 인계받은 klassboard-backend version 407 원본 D:/ChatGPT/ERD/.data/klass-route.json을 복제했다. 원본 SHA-256: A187D48256E95C7A4A50A488B16CE290C3E0DBC4E25996310AE29679A8E6C177.
- nativeCanvasScene의 전체 테이블 물리 화면과 nativeRelationLabelWidth로 입력을 생성했다. 테이블 134개·메모 26개·관계 238개이며 최신 실문서와 혼합하지 않았다.
- 변경 전 dist 전체를 ignored baseline-model에 보존했다. 동일 Node 프로세스에서 같은 입력/예산으로 이전·이후를 교대하여 각각 3회 실행했다. 아래 시간은 모델 호출이며 Worker 기동·전달·UI 렌더링·서버 저장을 제외한다.

## 경로 품질

완료된 전체 238개 관계에 대해 카드/메모 관통 0, 비직교 구간 0, 출발 직선/방향 위반 0, 기존 일반 renderer로 저장 경로를 재생했을 때 좌표 불일치 0을 확인했다. 중복 연결점 0이며 같은 면의 최소 연결점 간격은 부동소수 오차 범위에서 12다. 경로 배열 JSON은 57,453bytes다.

기존 구현은 기본 예산에서 191개 경로를 찾은 뒤 실패하여 완성 배치를 반환하지 않는다. 보존한 baseline 사본에 진단 관측만 추가해 이 191개의 중간 경로를 수집했다. 다음 표는 두 구현에서 동일한 관계 ID 191개만 비교한 참고 지표이며, 기존 완성 배치와의 비교가 아니다.

## 일반 캔버스 영향

- 신규 공유 인덱스·지역 탐색 정책은 createAutoRelationRoutingContext로 명시적으로 켠 자동 정리에서만 사용한다. 일반 relationGeometry 호출은 기존 후보·장애물·저장 경로 처리 규칙을 유지한다.
- 기존 참조 구현과 96개 조건(자기 참조·굽힘·명시 앵커·유효/무효 저장 경로)의 정확한 결과 일치를 검사했다. version 407의 238개 일반 경로도 변경 전 dist와 전체 결과가 일치했다.
- 일반 경로 238개 반복 계산을 두 번 예열한 뒤 6회 교대 측정했다. 기록된 상위 중앙 표본은 이전 453.09ms, 이후 459.06ms이며 범위는 각각 421–495ms, 428–487ms다. 관측 변동 내에서 겹치며 성능 향상을 주장하지 않는다. 브라우저 실제 드래그 FPS는 이번에 측정하지 않았다.

## 구현과 한계

[탐색 엔진](2026-10-21-Relations-IndexedAutoRoutingResult.md)과 [스케줄러](2026-10-21-Relations-AutoArrangeSchedulerResult.md)를 분리해 커밋했다. 유효 경로 확보에 선 겹침 페널티/차선 좌표를 넣지 않고, 완성 후 남은 예산으로 개선한다. 대체 연결점은 현재 예약 상태로 다시 검증한다. 기본 경과 시간 중단 기준은 10초이며 완성 전 예산 소진은 실패, 완성 후 미관 개선 소진은 유효 전체 결과와 제한 지표를 반환한다.

저장/ACK/API/DB schema는 변경하지 않았다. 원격 push와 PR은 이번 요청에 포함하지 않았다. 원시 입력·baseline·비교 스크립트·측정 JSON은 artifacts/performance/2026-10-21-relation-search/에 보존하며 Git 제외 대상이다.
