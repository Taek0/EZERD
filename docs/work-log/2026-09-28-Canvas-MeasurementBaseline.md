# 최소 계측의 첫 브라우저 측정

작성일: 2026-09-28
측정 코드: `2507ee3`, dirty=false인 성능 전용 production 빌드.

## 환경과 방법

- Windows, Ryzen 9 7900X, 약 32GiB RAM. Node v24.18.1. 브라우저는 Codex in-app browser, viewport 1440×900, DPR·userAgent·locale은 각 JSON metadata에 기록했다.
- DB/API 없이 실제 Canvas를 메모리 fixture로 실행했다. 10개/컬럼5개에서 안정성 확인 후 50개/컬럼10개로 확장했다. 관계 수는 테이블 수와 같다.
- PAN은 화면에 확인한 캔버스 좌표 (800,400)에서 `scrollX=100`, `scrollY=0`인 wheel 입력이다. 모든 표본에서 wheel 이벤트 1개, 문서 fingerprint 불변, 카메라 x만 약 -100px 변경을 확인했다.
- 10개 PAN 3회, 50개 준비 1회 후 reset 기반 반복 5회. MOVE와 EDIT는 각각 10개에서 기능·계측 검증 1회이며 통계적 비교 결과가 아니다.
- UI에 표시된 JSON을 읽어 원시 결과를 `artifacts/performance/2507ee3/`에 저장했다. 이 폴더는 Git 추적에서 제외되어 있으므로 다른 환경으로 옮길 때 별도로 보존해야 한다.

## 결과

| 시나리오 | 표본 | 카드 치수 호출 수/run | 관계 경로 호출 수/run | 검증 |
| --- | --- | --- | --- | --- |
| PAN, 테이블10·컬럼5 | 3 | 230 | 20 | 문서 불변, 손실 없음 |
| PAN, 테이블50·컬럼10 | 준비1 + 측정5 | 5,150 | 100 | 문서 불변, 손실 없음 |
| MOVE, 테이블10·컬럼5 | 1 | 1,150 | 100 | pointermove 4개, t0 x=0→100, y/크기 보존 |
| EDIT, 테이블10·컬럼5 | 1 | 460 | 40 | 컬럼 id→측정용_고객_식별자 저장 |

50개 PAN 반복 5회의 카드 치수 inclusive 누적 시간은 87.2~92.1ms, 관계 경로는 38.4~42.1ms였다. 계측 자체의 호출·표본 저장 오버헤드를 포함하므로 비계측 제품의 실제 응답 시간으로 일반화하지 않는다. 카드 크기 함수에는 치수 계산이 중첩되므로 두 시간을 더하지 않는다.

10개 PAN은 카드 치수 1.2~1.5ms, 관계 경로 2.1~4.1ms였다. 테이블뿐 아니라 컬럼 수도 다르므로 이 두 크기만으로 복잡도나 정확한 확장 비율을 추정하지 않는다.

Collect spans를 끈 50개 PAN 1회에서 summary가 비어 있고 문서 불변·카메라 이동이 유지됨을 확인했다. off 대조군 한 번만으로 계측 오버헤드의 크기를 확정하지 않았다.

터미널 `perf:calculate` 결과는 `artifacts/performance/calculate-1790585608558.json`이다. 컬럼10개 기준 전체 카드 치수 계산 30회 표본의 중앙값/p95는 테이블10개 0.079/0.272ms, 테이블50개 0.407/0.568ms다. 이는 한 번씩 치수를 계산하는 계산 전용 실험이며 브라우저의 반복 호출·관계·렌더 비용을 포함하지 않는다.

## 확인된 원인과 다음 단계

카메라만 변경해도 문서 좌표 카드 치수·관계 경로가 재계산되는 것을 직접 확인했다. 다음 단계는 카메라 변경과 문서 파생 계산을 분리하는 단일 실험이다. 이번 작업에서 최적화는 적용하지 않았다.

`TableRelationsSvg`가 관계 본문·조작 overlay로 나뉘어 호출되는 현재 구조와 관계마다 장애물 카드 크기를 준비하는 경로가 반복 호출 후보다. 이 설명은 코드에 기반한 해석이며, 준비 비용 분리·함수별 의존성 계측으로 추가 확인해야 한다.

## 자동화 범위와 한계

- 지원된 조작: semantic click/fill/press, 좌표 drag/scroll, DOM 결과 읽기. GPU trace·실제 input-to-present·React commit profiling은 수행하지 않았다.
- EDIT에는 편집 모드 진입 더블클릭·한 번 fill·Enter 확정이 포함된다. 개별 키 입력 타이핑 비용과 동일하지 않다.
- 준비 중 화면 좌표가 맞지 않아 측정이 시작되지 않은 조작은 표본에서 제외했다. 최종 MOVE는 관찰된 카드 헤더 좌표에서 수행했다.
- 큰 JSON을 한 번에 읽을 때 도구 문자열 상한으로 잘렸다. 다운로드 완료 대기에서도 30초 시간 초과로 제어 세션이 초기화됐다. 기존 브라우저 탭은 살아 있었고 오류를 앱 crash로 판단하지 않았다.
- 복구 후 화면에 이미 표시된 JSON을 50,000자씩 나눠 읽어 파싱·저장을 완료했다. 동일 다운로드 방식은 반복하지 않았다. 재사용 가능한 `scripts/performance/browser-pan.mjs`에 분할 수집과 PAN 실행 절차를 남겼다. 이 모듈은 Browser 스킬로 확보한 tab을 인수로 받으며 별도 브라우저를 실행하지 않는다.
- 100·300개 브라우저 부하, 12종 전체 매트릭스, 다회 MOVE/EDIT, A/B 개선 비교는 아직 미실행이다. 이번 결과는 최소 도구의 작동 검증 및 첫 기준 관찰이다.

## 결과 수집 도구 검증

- 재사용 PAN helper를 실제 Browser tab으로 실행해 complete, 문서 불변, 치수 5,150회·경로 100회를 다시 확인했다. helper 검증 표본은 위 반복 5개 통계와 분리해 `pan-50-helper.json`으로 저장했다.
- `pnpm format`, `pnpm format:check`, `node --check scripts/performance/browser-pan.mjs`, `git diff --check` 통과.
- 화면 증거는 `artifacts/performance/2507ee3/measurement-screen.png`에 저장했다. 종료 시 테스트 탭과 이번 작업에서 띄운 fixture 서버를 정리한다.
