# 자동 저장 구현 중단 지점

작성일: 2026-09-15
상태: Sol medium 병렬 세션 중단 유지 / 사용자 요청으로 짧은 단위 직접 작업 재개

## 모델과 완료 단위

사용자 지시에 따라 구현은 Sol medium, 읽기 전용 리뷰는 Astra low로 진행했다. 병렬 구현 에이전트와 구현 리드가 모두 `429 Too Many Requests`로 중단되어 모델 변경 없이 작업 상태를 보존한다.

- `0022f47`: 구현 계획 및 모델 역할 반영.
- `3ac2dc6`: 서버 기준 검증 등 구현 안전 계약 보강.
- `9b119b5`: 의미 단위 변경 모델·계약. 담당자 보고 기준 20개 테스트 및 모델·계약 타입 검사 통과, Astra low 리뷰 승인.
- 이후 참조 의존성 보강은 Astra low 리뷰를 통과했다. 사용자 요청으로 직접 검증을 재개해 모델 테스트 18개와 모델 타입 검사를 통과했으며, 해당 단위만 별도 커밋한다.

## 진행 중인 변경

서버 세션, 작업 제출·이력·복원·실행 취소 API, WebSocket, DB 마이그레이션 0005, 기존 쓰기 인증 전환, 웹 자동 저장·IndexedDB 대기열·통합 이력·조합뷰 제약 및 관련 테스트가 작업 폴더에 있다. 전체 기능은 미완료이며 배포 가능한 상태로 검증되지 않았다.

담당자 보고 기준 서버 타입 검사와 실제 PostgreSQL 자동 저장·인증 테스트 2개 파일/4개 테스트가 통과했다. 마이그레이션 0005 적용이 보고됐으며 메타데이터 파일도 작성됐다. 웹 관련 22개 파일/88개 테스트 통과 보고가 있었으나 이후 런타임 재작성 전 결과이며, 당시 웹 타입 오류 3개가 남았다. 최종 변경 상태의 통합 검사나 실제 브라우저 5개 세션 검증은 완료하지 못했다. 이 기록 작성자는 해당 테스트를 재실행하지 않았다.

## 재개 시 우선 확인

1. 서버 리뷰의 마지막 미해결 사항: 삭제 undo를 동일 작업 ID로 재시도할 때 restore/undo 명령 지문 불일치로 409가 발생하는 문제, 참조 누락으로 제외한 관계의 배치 정보 정리. 실제 HTTP 회귀 테스트와 함께 확인한다.
2. 웹 런타임 재작성 상태와 타입 오류를 확인한다. 불변 동기화 기준, 연속 의존 작업, 늦은 ACK의 최신 상태 보호, 시작·종료 중 비동기 콜백, IndexedDB 트랜잭션 완료 후 전송, 만료 전 기존 작업 결과 조회를 행동 테스트로 검증한다.
3. IME·debounce·blur·드래그 종료 저장, 미반영 편집 재적용·복사·폐기, 삭제 복원 및 안전한 undo/redo UI를 확인한다.
4. 기존 저장 버튼 기반 브라우저 검증을 새 흐름에 맞추고, 실제 5개 세션 전파·이벤트 유실·오프라인 새로고침·조합뷰 내용 편집 및 배치 제한을 검증한다.
5. 24시간/7일 경계, 동시 중복 요청, 복원 그래프, 타인 작업 undo 차단, 인증이 적용된 기존 API 회귀 및 마이그레이션 재실행을 확인한다.
6. 수정된 단위마다 Astra low 리뷰와 테스트 후 Sol medium 구현 담당자가 범위를 지정해 커밋한다.

## 커밋 및 기존 변경 보호

공유 의존성 후속 변경의 커밋 요청은 자동 승인 검토 서비스의 429 재시도 한도 때문에 거절됐다. 관련 코드와 서버·웹 후속 작업은 미커밋으로 보존돼 있다. 기존 README·문서 재분류·scripts/document-versions.mjs 변경은 이 작업과 무관하며 함께 커밋하지 않는다. 이 체크포인트는 조정 담당자가 중단 상태를 기록한 문서이며 런타임 구현 변경은 아니다.

## 직접 작업 재개 기록

사용자가 세션 중단 상태를 유지하고 짧은 작업부터 직접 진행하도록 요청했다. 서브에이전트는 재시작하지 않았으며, 위 모델 역할 기록은 기존 병렬 작업에 대한 기록으로 유지한다.

2026-09-15 15:33 KST에 공유 참조 의존성 보강을 직접 검증했다. `node node_modules/vitest/vitest.mjs run packages/model/src/sync.test.ts`는 1개 파일/18개 테스트 통과, `pnpm --filter @ezerd/model typecheck`는 종료 코드 0이었다. FK 참조 키 변경 감지와 무관한 테이블 이름 변경의 충돌 제외를 포함한 기존 리뷰 승인 범위를 확인했다. 이번 커밋은 모델 두 파일과 해당 계획·체크포인트만 포함한다. 서버·웹 미완성 변경과 위 재개 시 우선 확인 목록은 그대로 남는다.

## 서버 구현 재개 결과

2026-09-15에 서버 세션 인증, 객체 단위 작업 저장·조회·이력·복원·실행 취소, WebSocket 전파, 7일 보존용 스키마와 마이그레이션을 다시 검증했다. 삭제 작업 undo는 restore와 같은 `undo` 명령 지문을 사용해 동일 요청 재시도 결과를 반환하며, 유효하지 않은 외부 FK를 복원에서 제외할 때 그 FK의 레이아웃 경로도 함께 제외한다. 실제 요청의 인증 사용자와 다른 사용자가 undo를 시도하는 경우도 거부한다. Astra low 읽기 전용 검토에서 이 범위가 승인됐다.

기존 HTTP 통합 검사는 종료된 전체 문서 PUT 대신 동기화 작업 API로 문서를 준비하도록 전환했다. 동기화 요청에는 최대 1.5 MB인 기준 문서와 최종 문서, 의미 변경 목록이 함께 들어가므로 JSON 전송 한도를 8 MB로 조정했다. 각 문서의 1.5 MB 계약 검증은 그대로 유지한다. 개인 뷰포트가 서버 공유 문서에 저장되지 않는 정책도 회귀 검사에 반영했다.

- `pnpm --filter @ezerd/server build`: 통과.
- `node apps/server/scripts/test-integration.mjs`: 실제 PostgreSQL 2개 파일, 18개 테스트 통과. 만료 baseline의 기존 승인 결과 재조회, 7일 복원 경계, 동시 키 삭제와 FK 생성의 원자적 거부를 포함한다.
- `node node_modules/vitest/vitest.mjs run packages/contracts/src/relational.test.ts apps/server/test/write-auth.test.ts`: 2개 파일, 7개 테스트 통과.
- `pnpm --filter @ezerd/contracts typecheck`: 통과.
- `pnpm --filter @ezerd/server typecheck`: 통과.
- `pnpm --filter @ezerd/server db:migrate`: 기존 적용 상태에서 재실행 통과.
