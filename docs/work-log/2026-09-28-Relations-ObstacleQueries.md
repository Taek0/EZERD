# 관계 경로의 축별 장애물 구간 재사용

작성일: 2026-09-28
기준: `b889777`, `feat/performance-measurement`.

## 변경

- 관계 계산 중 raw/expanded 장애물 집합마다 수평 y·수직 x의 열린 장애물 구간을 지연 생성한다. 같은 좌표의 후보 선분은 구간 배열과 이진 검색을 재사용한다.
- 실제 장애물이나 경로 후보를 제거하지 않고 기존 부등식과 후보 순서·점수를 유지한다. 맞닿은 열린 구간은 합치지 않아 경계 접촉 의미를 보존한다.
- 8개 미만 장애물이나 음수 크기·비정상 좌표는 선형 검사로 처리한다. 인덱스는 관계 계산 한 번에 한정되며 전역/문서 간 캐시는 없다.
- 자동 후보·수동 경로의 clear 검사에 적용했다. A* fallback search와 label 충돌 처리는 기존 구현 그대로다.

## 정확성·검증

- 2,000개 고정 난수 선분과 장애물 경계, 접촉·zero-length·diagonal·비정상 좌표를 기존 선형 검사와 비교했다.
- 수정 전 routing 함수를 테스트 전용 reference로 보존했다. 40개 자동/수동/self/중첩 장면에서 points/path/label/handle 전체를 비교했다. 입력과 경로 의미를 바꾸는 근사화는 적용하지 않았다.
- 전체 `pnpm check` 및 관련 검사 결과와 고정 커밋 실측은 후속 기록한다.
- 미커밋 사전 scale 실행에서 300개 first 약222ms, warm 중앙값197ms로1초 조건과30초 프로세스 제한을 통과했다. 최종 수치는 고정 커밋으로 다시 측정한다.

## 브라우저 결과와 경로 동등성

동일 커밋 production 계측 빌드, in-app browser1440×900, locale ko, zoom1에서100개와300개를 측정했다. 각 EDIT/MOVE 준비1회+반복3회다.

| 크기·조작 | 경로 호출 수 | 경로 누적 시간 범위 |
| --- | --- | --- |
| 100 EDIT | 100 | 36.9~40.2ms |
| 100 MOVE | 400 | 157.1~163.9ms |
| 300 EDIT | 300 | 288.3~295.5ms |
| 300 MOVE | 1,200 | 1219.4~1297.3ms |

100개 기준의 이전 경로 누적 시간 중앙값은 EDIT98.5ms/MOVE429.0ms였고 현재는36.9ms/163.1ms다. 같은 fixture·입력·환경의6개 반복 쌍에서 최종 문서 fingerprint와 SVG paths가 모두 정확히 일치했다. 비교 스크립트가100·300개 파일도 처리하도록 확장했다.

300개는 이전 브라우저 표본이 없으므로 전후 UI 시간 비교를 하지 않는다. 대신300개 fixture의 모든300개 경로(points/path/label/handle)를 원래 알고리즘과 비교하는 테스트를 추가해 통과했다. 실제300개 EDIT/MOVE는 각각 최종 컬럼 이름과100px 이동을 확인했다.

300개 PAN3회는 카드 치수·관계·도메인 geometry 호출0회, 문서 불변을 유지했다. `assertCameraReuse` 통과, 브라우저 error 로그 없음. 원시값·경로·화면은 `artifacts/performance/f775bf4-browser/`에 저장했다. 증거 이미지는 `obstacle-300.png`,100개 비교 요약은 `comparison.json`이다.

## 한계와 다음 작업

- 위 브라우저 시간은 계측된 함수 inclusive 누적값이며 input-to-present나 GPU 지연이 아니다. ABBA 순서와 계측 off 대조를 이번에 추가 수행하지 않았다.
- 후보를 줄이거나 품질을 낮춘 개선은 아니다. 같은 좌표의 충돌 판단을 재사용한 것이다. 시간 절감과 별개로 한 관계 호출 안에서 임시 구간 배열·Map을 사용하며 메모리/GC 변화는 정량 측정하지 않았다.
- 300개 드래그에서는4개의 pointermove마다 모든300개 관계를 계산해 경로 누적 비용이 여전히1초 이상이다. 관계별 변경 영향 범위와 프레임 단위 입력 반영을 다음 우선순위로 둔다.
- 기존 A* fallback, label 충돌, 검색·PNG·동기화 전체 경로는 이번 최적화 범위에 포함하지 않았다. 전체 수동 회귀 검증 완료를 주장하지 않는다.
- 최종 `pnpm check`에서385개 통과·DB 관련25개 skip·타입·포맷·일반 빌드 통과. 300개 전체 경로 동등성 테스트도 포함한다. 성능 전용 빌드와100개 비교 스크립트도 통과했다. 기존 큰 청크 경고는 유지된다.
- 원시 산출물은 Git 제외 대상이다. 로컬 브랜치에 구현과 검증을 커밋하며 원격 push는 수행하지 않는다. 테스트 탭과 이번 fixture 서버는 종료한다.
