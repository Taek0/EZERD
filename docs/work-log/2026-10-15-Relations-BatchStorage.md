# 관계선 자동 정렬: 배치 저장 계약 및 서버 적용

관계선 자동 정렬 결과를 `apply_native_project_changes`의 단일 명령 `batch_upsert_relation_layouts`로 저장하도록 계약과 서버 적용기를 추가했다. 명령은 하나의 `viewId`와 변경된 관계선의 `routes`를 받고, 다른 명령과 같은 작업에 섞지 않는다. 따라서 기존 동기화 트랜잭션, `operationId` 재전송 판별, ACK, 히스토리 되돌리기를 그대로 사용하며 관계선 경로만 한 operation에 기록한다. 서버는 경로와 참조를 검증하고 최적화 계산은 수행하지 않는다.

배치 적용기는 관계·양 끝 카드·좌표·접점을 모두 검증한 다음 문서와 관계선 배열을 각각 한 번만 새로 만든다. 중복 관계 ID, 다른 화면 경로, 존재하지 않는 관계나 카드, 유효하지 않은 좌표를 거절한다. 요청 상한은 관계선 1,000개, 총 경유점 8,192개, 명령 JSON UTF-8 600,000바이트다. 개별 경로의 경유점 128개 한도와 문서 1,500,000바이트 한도도 유지된다. 상한 초과는 전체 명령을 거절한다.

상한 검토용 JSON 측정에서 접점 2개·경유점 2개인 대표 명령은 150개 26.7KB, 1,000개 179.7KB, 2,000개 362.2KB였다. ID 160자와 8,192개 경유점으로 채운 1,000개 명령은 601.6KB였다. 초기 1,000개 경로 제한은 기존 동기화/히스토리의 작업당 1,000개 변경 경로 상한과 일치한다. HTTP JSON 요청 한도는 8MB다.

계약 테스트는 100개 초과 수용, 관계 ID 중복, 경로·경유점·바이트 한도, 화면 혼합 거절을 확인한다. 서버 후보 테스트는 150개 경로의 단일 변경 묶음, 테이블 및 관계 의미 보존, 실패 시 원본 불변, 이동 이후 관계선만 되돌리는 동작을 확인한다. `pnpm build:shared`, 두 집중 테스트, `pnpm --filter @ezerd/server typecheck`가 통과했다.
