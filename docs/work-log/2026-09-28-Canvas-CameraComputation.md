# 카메라 변경의 문서 계산 재사용

작성일: 2026-09-28
구현 기준: `5944f09`, 브랜치 `feat/performance-measurement`.

## 변경

- Canvas의 뷰 노드와 도메인 관계를 `useMemo`로 재사용하고 visibleNodeIds의 참조를 안정화했다.
- TableRelationsSvg에서는 문서·뷰·scope·visibleNodeIds에 의존하는 순수 준비/경로 계산만 memo화했다. 선택·이벤트 callback·drag 상태는 계속 최신 render에서 생성한다.
- TableNodeContent의 치수는 문서·tableId로 memo화했다. Canvas의 카드 style은 이미 산출한 노드 크기를 사용한다.
- 문서가 바뀌면 보수적으로 전체 계산을 무효화한다. 개별 필드 캐시, 관계 본문과 조작 overlay의 공유 캐시, DOM 렌더 생략은 이번 범위에 없다. 언어 변경은 useI18n 구독에 따라 계속 렌더링하며 현재 치수·관계 label 계산은 문서 데이터에 의존한다.

## 구현 검증

- `pnpm check` 통과: 374개 테스트 통과, DB 관련 25개 skip, 전체 타입·포맷·빌드 통과. 측정 전용 빌드도 통과했다. 기존 큰 청크 경고는 유지된다.
- 작은 fixture에서 팬을 수행하면 Canvas render만 계측되고 카드 치수·테이블 경로·도메인 경로 호출은 발생하지 않는 것을 확인했다.
- 컬럼 id를 긴 한글 이름으로 바꾸면 문서 값과 관계 SVG path가 변경되고, 치수 220회·관계 경로 20회가 다시 실행되는 것을 확인했다. 계측기가 꺼져서 팬 수치가 0이 된 것이 아님을 교차 검증했다.
- 기존 계산 알고리즘·장애물 목록·수동 경로 처리·저장 데이터 구조는 변경하지 않았다. 최종 커밋 기준 반복 결과는 아래에 후속 기록한다.
