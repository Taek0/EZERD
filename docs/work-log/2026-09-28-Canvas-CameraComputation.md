# 카메라 변경의 문서 계산 재사용

작성일: 2026-09-28
구현 기준: `5944f09`, 브랜치 `feat/performance-measurement`.

## 변경

- Canvas의 뷰 노드와 도메인 관계를 `useMemo`로 재사용하고 visibleNodeIds의 참조를 안정화했다.
- TableRelationsSvg에서는 문서·뷰·scope·visibleNodeIds에 의존하는 순수 준비/경로 계산만 memo화했다. 선택·이벤트 callback·drag 상태는 계속 최신 render에서 생성한다.
- TableNodeContent의 치수는 문서·tableId로 memo화했다. Canvas의 카드 style은 이미 산출한 노드 크기를 사용한다.
- 문서가 바뀌면 보수적으로 전체 계산을 무효화한다. 개별 필드 캐시, 관계 본문과 조작 overlay의 공유 캐시, DOM 렌더 생략은 이번 범위에 없다. 언어 변경은 useI18n 구독에 따라 계속 렌더링하며 현재 치수·관계 label 계산은 문서 데이터에 의존한다.

## 구현 검증

- `pnpm check` 통과: 374개 테스트 통과, DB 관련 25개 skip, 전체 타입·포맷·빌드 통과. 측정 전용 빌드도 통과했다. 기존 큰 청크 경고는 유지된다.
- 작은 fixture에서 팬을 수행하면 Canvas render만 계측되고 카드 치수·테이블 경로·도메인 경로 호출은 발생하지 않는 것을 확인했다.
- 컬럼 id를 긴 한글 이름으로 바꾸면 문서 값과 관계 SVG path가 변경되고, 치수 220회·관계 경로 20회가 다시 실행되는 것을 확인했다. 계측기가 꺼져서 팬 수치가 0이 된 것이 아님을 교차 검증했다.
- 기존 계산 알고리즘·장애물 목록·수동 경로 처리·저장 데이터 구조는 변경하지 않았다. 최종 커밋 기준 반복 결과는 아래에 후속 기록한다.

## 고정 커밋 반복 결과

실험 커밋 `86f3399`, dirty=false. baseline은 `2507ee3`의 기존 기록이다. 동일 Windows 장비·in-app browser·1440×900 viewport·ko locale, 테이블50·컬럼10·관계50, zoom=1, 화면 좌표 (800,400)에서 wheel x=100을 사용했다. fixture fingerprint는 `69463461`이다. 준비1회 후 reset 기반 5회 측정했다.

| 지표 | baseline, 5회 각각 | 변경 후, 5회 각각 |
| --- | --- | --- |
| tableCardMetrics 호출 | 5,150 | 0 |
| tableCardSize 호출 | 5,100 | 0 |
| relationGeometry 호출 | 100 | 0 |
| layoutDomainRelations 호출 | 1 | 0 |
| Canvas 함수 호출 | 1 | 1 |
| 문서 데이터 | 불변 | 불변 |

변경 후 계측 span은 Canvas 함수 하나뿐이며 0.2~0.3ms였다. baseline의 치수 누적 87.2~92.1ms, 관계 경로 38.4~42.1ms를 다시 실행하지 않았다. 함수 호출 제거는 확인했지만 전체 React·DOM·GPU·입력 지연을 측정한 수치는 아니다. 기준/실험을 교차 실행한 ABBA 실험이나 FPS·메모리 검증은 아니므로 전체 체감 속도 개선율을 계산하지 않는다.

원시 결과: `artifacts/performance/86f3399/pan-50-warmup.json`, `pan-50-0.json`~`pan-50-4.json`. 화면 증거는 같은 폴더의 `optimized-pan.png`다. 산출물은 Git 제외 대상이다.

## 무효화와 회귀 확인

- 10개/컬럼5 fixture에서 동일 100px 드래그 후 t0의 x=0→100, y와 크기 보존, 관계 path 변경을 확인했다. 새 문서가 반영되는 이동 단계에서 관계 계산 80회가 발생했다. 결과는 `move-10.json`이다.
- 컬럼 id→측정용_고객_식별자 변경 후 문서 값과 관계가 갱신되고 경로 계산 20회가 발생했다. 결과는 `edit-10.json`이다. 문서 변경 시 계산이 실행되므로 팬의 0회는 계측 누락 때문이 아니다.
- 브라우저 error 로그는 없었다. 원격 동기화·undo·PNG는 이 메모리 화면에서 추가 수동 실행하지 않았으며 관련 기존 단위 테스트와 문서 전체 참조를 무효화하는 구조로 회귀 범위를 제한했다.
- `assertCameraReuse`를 PAN helper에 추가했다. 계측 활성화·카메라 변화·문서 불변·Canvas 실행을 요구하고 문서 geometry 재계산이 있으면 실패시킨다. 저장된 baseline 표본은 실패, 최적화 5개 표본은 전부 통과하는 것을 실행해 확인했다.

## 남은 범위

- 문서 편집마다 전체 관계 계산을 다시 한다. 다음 조사 후보는 변경된 카드/관계의 의존성 및 관계 본문·overlay 중복 계산이다.
- 카메라 변경 시 React 컴포넌트 렌더와 컬럼 배열 검색 등은 남는다. 이번 변경은 렌더 전체를 생략하는 작업이 아니다.
- memo는 컴포넌트별 현재 결과를 보유하며 메모리 사용량은 별도 측정하지 않았다. 특히 관계별 장애물 배열의 보유 비용을 후속 메모리 조사에 포함한다.
- 로컬 브랜치에 구현과 검증을 커밋했다. 원격 push·main 병합은 수행하지 않는다.
