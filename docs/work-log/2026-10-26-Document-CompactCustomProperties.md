# 빈 customProperties 저장 최적화

## 동작

- Native v2 테이블·컬럼에서 common/logical/physical 세 영역이 모두 빈 객체일 때만 저장 JSON에서 customProperties를 생략한다. 비어 있지 않거나 알 수 없는 구조는 제거하지 않는다.
- 읽을 때 생략된 필드를 기본 빈 구조로 복원한다. 기존 명시적 값과 원본 이름·설명·별칭은 유지한다. v1 데이터는 변경하지 않는다.
- PATCH에서 필드 생략은 기존 메타데이터 유지로 처리한다. 생성/읽기의 기본값 복원이 부분수정에 섞이지 않도록 별도 계약을 유지한다.
- 저장 프로젝트, 서버 발급 baseline, 승인 응답의 문서 스냅샷에 적용한다. 변경 증거·삭제 스냅샷·가져오기 원본 감사 자료는 보존한다.
- 문서 한도는 생략 후 저장 JSON 기준으로 검사한다. 1,500,000바이트 한도 자체와 전체 전송 파일 제한은 높이지 않았다.
- 기존 DB를 일괄 재작성하지 않는다. 재빌드·재시작 후 다음 저장부터 적용되며 DB 마이그레이션은 없다.

## 효과와 검증

- Klassboard version 454 스냅샷: 기존 1,442,486 → 저장 표현 1,353,206바이트. 89,280바이트 절감.
- 자동 관계선 247개 정리 후: 1,506,456 → 1,417,176바이트. 기존 한도 이내로 후보 검증 성공. 실제 프로젝트는 수정하지 않았다.
- 모델/계약 관련 137개, 서버 관련 93개, 추가 MCP/HTTP 8개 테스트 통과.
- 사용자 DB와 분리된 임시 PostgreSQL에서 배치 저장·재조회·ACK 재생·이력 실행취소/복원·파일 가져오기 테스트 58개 통과. 임시 DB는 실행기가 정리했다.
- 공유 패키지·서버 빌드 및 웹 타입 검사 통과. 전체 기본 회귀 검사 282개 파일/3,148개 테스트 통과, DB 조건부 등 29개 파일/500개 테스트는 기본 설정에 따라 건너뛰었다. 위 58개 DB 검증은 별도 실행했다.
