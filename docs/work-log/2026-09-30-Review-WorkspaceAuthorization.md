# 리뷰·알림·개인 상태의 워크스페이스 권한 적용

## 변경 내용

- 리뷰 조회 REST 요청은 세션을 확인하고 사용자 ID를 서비스에 전달한다. 프로젝트의 현재 공간 멤버만 핀 목록·페이지·상세와 개인 상태를 읽을 수 있다.
- 핀 생성·답글·상태 변경·삭제와 알림 갱신은 변경 트랜잭션 안에서 `review` 권한을 확인한다. active 공간의 viewer도 사용할 수 있으며 archived 공간에서는 차단한다.
- 멘션 대상은 프로젝트의 현재 `user_workspaces` 멤버로 제한한다. 중복 멘션을 제거하고 작성자에게 자기 멘션 알림을 만들지 않는다.
- 알림 목록과 페이지는 수신자가 현재 프로젝트 공간 멤버인 항목만 반환한다. 알림 갱신은 수신자 확인 후 현재 멤버십과 공간 상태를 검사한다.
- 개인 상태 조회는 사용자별 저장 행을 조회한다. 변경과 MCP 개인 작업 재실행은 캐시된 결과 조회 전 트랜잭션에서 `personal` 권한을 확인하므로 탈퇴·제거 및 공간 보관 이후 재실행도 차단한다.
- MCP 개인 서비스는 기존 위임 구조를 유지하고 공통 개인 상태 서비스에서 권한을 적용한다. 공유 설계 문서와 개인 상태를 분리하는 기존 검증을 유지한다.
- 리뷰 읽기 계약은 `list(projectId,userId)`, `listPage(projectId,userId,limit,cursor?)`, `getThread(id,userId)`다.

## 검증

- `node node_modules/vitest/vitest.mjs run apps/server/test/review-personal-access.test.ts apps/server/test/write-auth.test.ts`: 2개 파일, 20개 테스트 통과.
- 비멤버 조회 차단, viewer 핀·개인 배치 변경 허용, archived 공간의 리뷰·알림 변경 차단, 현재 멤버 멘션과 중복 제거·자기 알림 제외, 수신자 및 현재 멤버십 알림 조회 조건, 사용자별 개인 상태 조회, MCP 재실행 전 권한 재검사를 검증했다.
- 두 컨트롤러의 인증 실패가 서비스 접근 전에 반환되는지와 세션에서 작성자를 결정하는 기존 검증을 함께 수행했다.
- 변경한 소스와 테스트는 루트 Prettier 설정으로 포맷했다. 전체 포맷·통합 PostgreSQL 검증·빌드는 워크스페이스 도메인 및 나머지 접근 경로 통합 후 수행한다.
- 중간 서버 타입 검사에서 이 범위의 오류는 없었으며, 병렬 구현 중인 공간 컨트롤러 파일과 MCP 공간 변경 입력 타입의 오류가 남아 있었다. 해당 소유자에게 전달했다.
- `docs/EZERD.txt`는 변경하지 않았다.
