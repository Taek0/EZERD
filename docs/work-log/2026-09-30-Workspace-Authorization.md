# 프로젝트와 동기화 워크스페이스 권한 적용

- 프로젝트 목록은 인증 사용자의 user_workspaces에 조인한다. 생성/가져오기는 명시적인 workspaceId를 요구한다. 기존 내보내기 파일은 이름과 설계만 담고 가져오기 요청의 대상 공간과 분리했다.
- 프로젝트 상세/내보내기, 히스토리/이벤트/작업 결과, 리뷰, 개인 상태 조회는 멤버십을 검사한다. 권한과 응답 조회가 같은 REPEATABLE READ 스냅샷에서 실행되도록 보강했다.
- 설계 변경/이관 요청/복원/실행 취소/개인 상태/리뷰 쓰기는 트랜잭션 안에서 권한을 확인한다. 공간 SHARE 잠금과 owner 관리의 UPDATE 잠금으로 역할/보관 변경과 직렬화한다. 캐시 재실행에도 권한 확인을 먼저 적용한다.
- 활성 공간에서 viewer는 설계 쓰기와 프로젝트 생명주기를 사용할 수 없고 핀·댓글 및 개인 상태는 사용할 수 있다. editor는 생성/가져오기/설계/프로젝트 보관·복원, owner는 프로젝트 영구 삭제를 추가로 수행한다.
- 보관 공간은 읽기·내보내기만 허용하며 owner의 공간 복원·멤버/초대 관리는 유지한다. 동기화 기준 POST도 활성 공간의 개인 권한을 요구한다.
- WebSocket 구독과 모든 전송은 멤버십을 검사한다. 변경 이벤트를 수신한 기존 연결에는 workspace-access-changed를 전송하고 즉시 1008로 종료한다. UI는 해당 이벤트로 큐를 정지하고 권한을 다시 로드한다.
- 프로젝트 생성/가져오기/이름·상태 변경/삭제는 공간 감사 기록에 남긴다. 설계 변경은 기존 sync_operations 히스토리에 남기며 기존 보관 기간(7일)을 유지한다. 리뷰/개인 상태는 기존 저장 테이블에 보존한다. 별도 영구 설계/댓글 내용 감사 스냅샷은 추가하지 않았다.
- 사용자 삭제 API는 없다. user_workspaces의 NO ACTION은 모든 멤버의 직접 계정 삭제를 막는다. 향후 계정 삭제는 소유권 이전뿐 아니라 멤버십·초대·리뷰 작성자·sync 작성자 참조를 명시적으로 처리해야 하며, 이번 작업에서는 기존 사용자나 계정을 삭제하지 않았다.

## 검증

- pnpm format, pnpm format:check, pnpm typecheck, pnpm build 통과.
- 일반 테스트 525개 통과(운영 DB 실행 없이 opt-in 통합 테스트 제외).
- 새로 생성한 격리 PostgreSQL에서 기존 API/동기화/MCP와 새 권한·WebSocket·이관 테스트 32개 통과. 별도 공간 도메인 동시성 6개를 함께 실행해 총 38개 통과.
- 검사 중 발견한 조회 TOCTOU, 보관 공간 기준 생성, 캐시 복원 권한, 테스트 정리 잠금 문제를 보완했다. 최종 검사 수치는 전체 이관 결과 기록에서 다시 확정한다.
