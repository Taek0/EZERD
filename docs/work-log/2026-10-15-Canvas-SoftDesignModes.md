# 소프트 세그먼트 설계 모드 적용

- 사용자 선택 A안을 실제 툴바에 반영했다. 물리/논리 두 선택지가 항상 보이며 밝은 선택 배경이 이동한다. 32px 높이·12px 글꼴, ARIA radio·방향키/Home/End 및 reduced-motion을 지원한다.
- 더보기의 논리 설계 켜기/끄기를 제거했다. 읽기 전용 사용자도 보기 모드를 변경할 수 있다.
- generic 프로젝트는 기존 프로젝트를 포함하여 진입 시 논리를 기본으로 사용한다. 다른 DB는 물리를 기본으로 한다. 사용자·프로젝트·DB 문맥 변경만 기본값을 재설정하며 ACK의 sequence/version 변경은 사용자 선택을 유지한다.
- logicalEnabled와 requestedMode가 서로 어긋나지 않게 선택 상태를 통합했다. 모드 변경 콜백도 문맥이 같으면 동일한 참조를 유지한다. 일반 객체·핀 초점 이동에서 강제 물리 모드 전환을 제거했다.
- 선택안함 생성 확인 팝업의 한·영 문구에 논리 기본값을 명시하고 공통/직접 입력 타입과 DDL 제한 안내를 유지했다.
- 설계 데이터 변환·삭제나 서버 기본값 필드를 추가하지 않았다.

## 검증

- 실패를 먼저 재현하고 관련 기본값·토글·팝업 테스트 27개 통과. DB 변경 테스트 기대값 정리 후 관련 4개 파일 81개 통과.
- 프로젝트 전체 검사에서 108개 파일 중 107개 파일이 통과했다(테스트 1,126개 통과, 1개 실패). 유일한 실패였던 폐기된 개인 상태 기대값은 별도 수정·재검증했다.
- 웹 TypeScript, 전체 Prettier, Vite 빌드 통과. 기존 번들 크기 경고는 남아 있다.
- 실제 NativeCanvasToolbar를 별도 React 페이지에서 헤드리스 Chromium으로 렌더링해 A안의 크기·선택 배경·색상을 확인했다. 검증 페이지는 제거했다. 실제 사용자 프로젝트는 열거나 수정하지 않았다.
