# 사용자 PIN 저장 방식 확인

작성일: 2026-09-15

사용자 요청에 따라 PIN 저장과 로그인 경로를 확인했다. WorkspaceController.createUser는 PIN을 SHA-256으로 해시해 pin_hash에 저장하며 SessionService.create도 같은 해시로 비교한다. 클라이언트는 사용자 ID와 세션 토큰만 저장소에 기록하고 로그인 후 PIN 입력 상태를 비운다.

실제 설정된 DB를 읽기 전용 집계로 확인한 결과 사용자 15개 중 네 자리 평문 PIN 형식 0개, 64자리 SHA-256 형식 15개였다. PIN 및 해시 원문은 조회하거나 출력하지 않았다. 이미 요청한 해시 저장이 적용되어 있어 인증 코드를 중복 변경하거나 허용된 DB 전체 초기화를 실행하지 않았다.

검증 범위는 평문 미저장 확인이다. 현재 단순 SHA-256은 salt를 사용하는 비밀번호 전용 해싱과 같지 않으며, 네 자리 PIN의 추측 공간을 확대하지 않는다.
