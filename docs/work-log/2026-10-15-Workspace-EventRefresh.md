# 갤러리 이벤트 중심 갱신

- 로그인한 탭은 사용자 WebSocket 연결 하나를 유지한다. 프로젝트 진입은 같은 연결의 구독 추가, 퇴장은 해당 구독 해제로 처리한다. 기존 native 동기화의 순번 확인·재연결·HTTP 복구는 가상 프로젝트 소켓 어댑터로 유지한다.
- 워크스페이스/초대 15초 및 알림 30초 폴링을 제거했다. 초기 조회, 사용자 구독 ACK, 재연결, 창 포커스/네트워크 복귀, 관련 서버 변경 이벤트에 조회한다. 갤러리 복귀 시 목록을 갱신한다.
- 목록 요청은 짧은 병합 대기와 직렬 처리로 중복을 줄이며 진행 중 invalidation은 후속 조회 한 번으로 반영한다. 사용자/워크스페이스 변경 시 이전 요청을 중단한다.
- 서버는 성공적인 DB 커밋 이후 사용자별 workspaces/invitations/notifications/projects 변경 이벤트를 발행한다. 초대받은 비멤버와 탈퇴/삭제 대상도 명시적인 수신자로 포함한다.
- 사용자·프로젝트별 연결 인덱스, 제한된 이벤트 큐와 전송 버퍼를 사용한다. 갤러리 heartbeat는 프로젝트 DB 조회를 하지 않는다. 세션 재검증과 기존 프로젝트 head 검사는 유지한다.
- 정책 종료 코드 1008은 현재 인증정보로 접근 권한을 재확인한다. 현재 사용자/토큰의 HTTP401에만 로그인 상태를 해제하며 늦게 도착한 이전 세션 응답을 무시한다.
- 초대 만료는 다음 만료 시점의 로컬 타이머로 표시를 갱신하며 HTTP 폴링을 추가하지 않는다.

## 범위와 검증

- 이벤트 전달은 현재 단일 서버 프로세스의 emitter를 사용한다. 다중 서버로 확장할 때에는 별도 공유 이벤트 전달 계층이 필요하다.
- 프로젝트 내용 수정마다 전체 갤러리 미리보기를 실시간 갱신하지는 않는다. 프로젝트 생성·이름/상태 변경·삭제·가져오기는 이벤트 대상이며, 내용 미리보기는 갤러리 진입/포커스 갱신 때 확인한다.
- 사용자별 수신 격리, 비멤버 초대, 롤백 시 미발행, 구독 취소 경합, 세션 만료, 역압, 재연결 및 요청 병합 테스트 통과.
- 전체 회귀 테스트 2,909개 통과 / DB 선택 실행 495개 건너뜀. 타입·빌드·포맷 검사 통과. 실제 다중 사용자 부하/브라우저 측정은 수행하지 않았다.
