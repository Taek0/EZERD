## 변경

명시적 관계선 정리에서 카드의 겹치는 유효 범위에 연결점을 맞추어 직선 연결을 우선한다. 기존 균등 배정을 시작점으로 사용하고 같은 면의 연결점 순서·가능한 최소 12단위 간격을 유지하는 구간 안에서만 이동한다. 대각 배치는 카드 경계에서 실제로 가능한 저비용 경로의 길이와 꺾임으로 면을 고른다. FK source / PK target 규칙은 유지한다.

출발·도착 직선은 보통 tip부터 28 world 단위이며 좁은 통로에서만 줄인다. 직선·L·Z 후보를 먼저 평가하고 충돌 없는 후보는 기존 탐색기를 호출하지 않는다. 내부 꺾임 단순화와 최대 2048개 국소 통로 이동 후보로 불필요한 우회·겹침을 줄인다. 기존 제한 개선 탐색은 문제가 있는 관계선에만 실행한다. 면별 장애물 탐색은 32회에서 8회로 줄이고, 통로 후보 계산과 routing context는 필요할 때만 준비한다.

모든 새 후보는 카드·메모 침범, 직교성, 자기 되짚기, 연결점 방향, 보호된 출발·도착 길이를 검증한다. 내부 경로는 기존 router의 18단위 장애물 여백을 지킨다. 소수 좌표의 연결점 왕복 오차는 renderer와 같은 1e-6 허용 범위를 사용한다. 입력·출력 및 검색 상한은 유지한다.

짧은 유효 저장 경로가 기존 고정 36단위 자동 stub 검사에서 제외되던 재현 문제도 수정했다. 두 anchor와 저장 waypoints가 명시된 경로만 별도 후보로 검증한다. 이 후보는 기존 rawClear/outward/retraces 검증을 통과해야 하며, 잘못된 저장 경로가 자동 fallback 후보를 늘리지 않는다. 자동 경로의 기본 후보·일반 이동 처리에는 새 최적화를 추가하지 않았다.

## 동일 입력 전후 측정

원시 자료: artifacts/performance/2026-10-16-arrange-quality/paired.json, work-counters.json, default-routing.json, adversarial.json. 측정 스크립트와 이전 알고리즘 사본은 같은 artifacts/performance 아래에 보존했다. 워밍업 1회 후 순서를 번갈아 5회 실행한 모델 계산 시간 중앙값이다. renderer 검증 시간은 계산 시간에서 제외했다.

| 입력 | 개선 pass | 이전 ms | 이후 ms | 기존 router 호출 | 탐색 노드 |
| --- | ---: | ---: | ---: | --- | --- |
| 실제 snapshot: 카드 43·메모 15·관계 61 | 0 | 576.5 | 461.7 | 61 → 33 | 82,039 → 73,012 |
| 실제 snapshot | 기본 1 | 1645.1 | 1647.9 | 101 → 73 | 257,040 → 256,505 |
| Hwp: 카드 49·관계 75 | 0 | 276.8 | 30.9 | 75 → 37 | 24,843 → 0 |
| Hwp | 기본 1 | 1128.2 | 1009.9 | 115 → 77 | 107,284 → 105,514 |

기본 실행에서 Hwp 계산은 약 10.5% 빨라졌다. 실제 snapshot은 오차 범위에서 비슷하다. 최초 배치는 빨라졌지만 기본 개선 단계의 탐색 노드 수가 비슷하게 유지되어 전체 계산 감소 폭은 제한적이다. 모든 입력과 기본 pass에서 일률적인 속도 개선을 주장하지 않는다.

| 기본 pass 품질 | 교차 | 겹침 길이 | 간격 위반 | 꺾임 | 총 길이 |
| --- | --- | --- | --- | --- | --- |
| 실제 snapshot | 91 → 119 | 99.2 → 0 | 0 → 0 | 200 → 140 | 235,552.7 → 255,942.8 |
| Hwp | 124 → 117 | 465.1 → 0 | 0 → 0 | 239 → 143 | 198,560.0 → 199,090.4 |

직선·짧은 출발과 꺾임 제거를 우선하면서 실제 snapshot의 교차는 28개 늘고 길이는 약 8.7% 늘었다. 겹침 제거·꺾임 감소와의 교환 관계이며, 무교차 또는 모든 지표 동시 개선을 보장하지 않는다. pass 0은 완성품 기본 동작이 아니며 겹침 제거가 덜 된 초기 결과다.

Hwp의 p→run, run→tbl, tc→p는 waypoints 없이 직선으로 연결한다. tbl→tc는 tbl 아래 면에서 출발하여 tc 오른쪽 면에 한 번 꺾여 연결한다. 전체 75개 관계 문맥에서 확인했다.

## 검증

- 모델 집중 회귀 테스트 14개, 모델 typecheck 통과.
- 정수·소수 좌표의 가로/세로 직선, 대각 면 선택, 메모 우회, 짧은 보호 구간, 30단위 카드 간격의 저장 경로 재현, 잘못된 저장 경로 fallback 동등성, 자기참조·결정성·혼잡 분산·121관계 기존 검사 통과.
- 실제 두 문서의 모든 전후·pass 결과에서 renderer replay 불일치와 카드·메모 침범 각각 0건.
- 고정 난수의 소수 좌표 40 fixture / 320개 경로에서 실패·replay 불일치·카드 침범 0건.
- 일반 자동 routing 기준 사본과 5개 사례(기본·대각·자기참조·메모·잘못된 저장 경로) 결과가 일치한다. 200회 호출의 5회 중앙값은 이전 6.949ms / 이후 6.939ms였다. 해당 작은 측정으로 전체 UI 팬·이동 성능을 단정하지 않는다.

전체 제품 검사는 상위 통합 작업에서 별도 수행한다. 이 변경은 제품 schema, 저장 payload, renderer replay 형식, Worker 수명/취소 계약을 바꾸지 않는다.
