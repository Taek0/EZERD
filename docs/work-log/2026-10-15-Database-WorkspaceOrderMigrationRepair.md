# 워크스페이스 정렬 마이그레이션 복구

## 원인

- 사용자 로그의 빌드·마이그레이션·Nest 시작은 성공했으나 워크스페이스 조회에서 PostgreSQL 42703(sort_order 없음)이 발생했다.
- 0017 journal.when=1792050000000보다 0018.when=1792049759919가 작았다. Drizzle은 파일 번호가 아니라 마지막 적용 시각과 비교하므로 0017까지 적용된 DB에서는 0018이 건너뛰어졌다.
- 이전 검증은 빈 DB에서 전체 적용했으므로 당시 저장 경로는 통과했지만 기존 DB 업그레이드 경로를 놓쳤다.

## 수정·검증

- 공개된 0017/0018 기록과 SQL은 유지하고 0019_repair_workspace_order를 추가했다. 컬럼과 CHECK를 조건부로 추가하여 누락 DB와 이미 적용된 DB 모두 안전하게 복구한다.
- 임시 PostgreSQL DB에서 0017까지만 적용 후 업그레이드하는 실패를 먼저 재현했다. 수정 후 0017 업그레이드, 0018 정상 적용 DB(기존 순서값 보존), 신규 전체 적용, 재실행을 검증했다. 관련 테스트 12개 통과.
- db:migrate 전에 journal timestamp 검사 스크립트를 실행한다. 알려진 0018 역전은 0019 복구가 함께 있을 때만 허용하고 이후 역전/동일 시각을 거부한다.
- 서버 도구 타입 검사, 변경 파일 Prettier, diff 검사 통과.

## 현재 로컬 DB 복구 결과

- 읽기 확인에서 sort_order가 없고 마지막 적용 시각이 0017임을 확인했다.
- 정식 migrator로 0019를 적용하여 integer 컬럼을 확인했다. 사용자·프로젝트·워크스페이스·멤버십 개수 및 기존 프로젝트/멤버십 내용 해시가 전후 동일했다. 초기화하지 않았다.
- 3001 포트는 연결 거부 상태여서 실행 중인 HTTP 서버 검증은 하지 못했다. 서버를 임의로 재시작하지 않았으며 사용자가 pnpm host:start로 재실행할 수 있다.
