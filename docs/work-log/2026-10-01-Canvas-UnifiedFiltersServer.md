# 공유 전체 테이블 캔버스·개인 도메인 필터 서버/MCP 통합

- 기준 계획: [전체 테이블 캔버스와 개인 도메인 필터 통합](../planning/2026-10-01-Canvas-UnifiedDomainFilters.md)
- 작업 범위: `apps/server/src`, `apps/server/test`와 이 기록. 모델·계약·웹 및 부모 담당 `direct-table.integration.test.ts`는 수정하지 않았다. 부모 검토·커밋을 위해 변경 사항은 커밋하지 않았다.

## 변경 내용

- `normalizeServerDocument`에서 모델의 `normalizeSharedTableCanvas`를 사용한다. 프로젝트 조회·입출력·동기화 기준·쓰기·복원·리셋은 동일한 정규화 래퍼를 유지한다. 저장된 과거 작업의 조회·재실행·이벤트·이력 응답 문서도 정규화하며 DB 원본은 읽기만으로 변경하지 않는다.
- MCP 도메인 ID 및 기존 결합 화면 ID 조회는 해당 도메인 소속 테이블을 공유 전체 캔버스 노드에서 선택한다. 노드 ID·좌표·크기와 메모·경로의 `viewId`는 `__tables__`를 그대로 반환한다. 메모는 모든 도메인 필터에서 공유하며 관계는 양쪽 테이블이 보일 때만 반환한다. 필터 메타데이터가 개인 상태에서 온 경우에도 개인 배치·메모·관계선을 공유 투영에 사용하지 않는다.
- 도메인 맵의 `overview` 조회는 유지한다. MCP 배치 진단도 같은 공유 필터를 사용하고, 전체 진단은 도메인 맵과 전체 테이블 배치를 대상으로 한다.
- 소속 테이블의 MCP 생성·수정 placement는 전체 공유 노드를 변경한다. 레거시 도메인 ID를 사용하는 메모 upsert 및 관계 경로 upsert/delete는 전체 캔버스 대상으로 연결한다. 개인 결합 화면 경로에 대한 기존 공유 명령 금지는 유지한다.
- 도메인 테이블·메모 핀 검증은 공유 전체 캔버스 배치와 도메인 테이블 선택을 사용한다. 저장하는 도메인 문맥과 빈 공간 좌표는 유지한다. 기존 개인 핀 조회를 전체 공유 핀으로 자동 변환하지 않는다.
- 개인 상태 API 및 권한은 변경하지 않았다. 뷰어의 개인 카메라 저장은 유지하고 개인 API로 공유 노드를 변경하는 요청은 거부한다. 기존 개인 상태 레코드를 일괄 공유로 이관하지 않는다.

## 실제 DB 재소속 오류 보완

도메인 해제 후 재지정은 `node:<tableId>:<domainId>` 기본 소속 배치를 다시 만든다. 기존 검사에는 nullable 필드 변경까지 객체 생성으로 오인하는 문제가 함께 있었다.

- ID 재사용 금지를 실제 객체 생성 경로로 제한하여 기존 `domainId: null → 도메인` 변경을 허용한다.
- 같은 살아 있는 테이블과 도메인의 기본 소속 배치 노드에 한해 최신 삭제 기록의 ID·객체·화면 쌍과 필드 버전을 모두 확인하면 재생성할 수 있다. 삭제된 엔티티·임의 노드·다른 객체로 재사용하는 요청은 계속 거부한다.
- 삭제 기록이 보존 기간 경과로 없다면 소속 배치에 새 노드 ID를 발급한다. 증거 없는 기존 ID를 재사용하지 않으며 전체 캔버스의 결정적 노드 ID는 변경하지 않는다. 서버가 반환하는 문서와 변경 목록에 새 소속 노드 ID를 반영한다.
- 동기화는 원본 baseline/document의 변경 목록을 먼저 검증한다. 정규화로 위조 변경이 가려지지 않도록 기존 순서를 유지했다.

## 검증

- 공유 메모·관계선 이관의 조회/내보내기/기준/리셋 일치, 정규화 멱등성, 개인 데이터 보존.
- 도메인 및 결합 화면 필터의 전체 좌표·공유 메모·경로 일치, 외부 테이블 제외, 안정적 페이지 조회와 overview 유지.
- 원본 변경 목록 위조 거부, 레거시 메모 수정·전체 관계선 수정의 저장 및 개인 상태 보존.
- 같은 소속 노드 재생성, 삭제 기록 없는 경우 새 ID 발급, 잘못된 삭제 기록·임의 노드·삭제된 엔티티 재사용 거부, nullable 필드 재수정 허용.
- 실제 PostgreSQL 통합 테스트는 부모 소유 파일을 수정하지 않고 실행했다. 도메인 재소속 및 공유 메모·좌표 이관을 포함한 3개 테스트가 통과했다.
- 최종 서버 테스트·타입·포맷 검사 결과는 아래 완료 검증에 기록한다.

## 완료 검증

- 서버 테스트: `pnpm exec vitest run apps/server/test --exclude '**/direct-table.integration.test.ts'` — 19개 파일·120개 테스트 통과, DB opt-in 등 5개 파일·40개 테스트 건너뜀.
- 실제 DB: `$env:EZERD_DIRECT_TABLE_DB_TEST = '1'; pnpm exec vitest run apps/server/test/direct-table.integration.test.ts` — 3개 테스트 통과.
- 서버 타입 검사: `pnpm --filter @ezerd/server typecheck` 통과.
- 담당 파일에 루트 Prettier 설정을 적용했다. 다른 에이전트의 변경 파일을 함께 포맷하지 않도록 담당 경로를 명시했다.
