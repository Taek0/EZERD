# 저장 대기 중 편집 유지

## 변경

- 서버 저장·응답 확인·대기 요청 상태 때문에 전체 편집기를 비활성화하던 정책을 제거했다.
- 후속 저장 의도를 사용자·프로젝트별로 로컬에 보관하고 기존 durable 전송 경로로 직렬 처리한다. 이미 전송된 요청은 같은 ID와 본문으로 결과를 확인한다.
- 처리 거부가 확정된 요청은 원본을 별도 보관해 다음 요청을 막지 않는다. 결과 미확인 상태는 안전하게 복구할 때까지 전송을 기다리지만 입력은 계속 가능하다.
- 대기열은 최대 128개를 보관하며 초과 시 기존 입력을 버리지 않는다. 연속된 동일 요청만 중복을 방지하고 A → B → A 순서는 보존한다.
- 일반적인 대기 상태는 저장 상태로 표시하고 오류·저장소 상태 미확인은 구분한다.
- 원격 수정과 저장 응답이 편집기 포커스·진행 중 드래그를 초기화하지 않도록 조정했다.
- 카드 크기 변경 시 위치까지 함께 전송하지 않아 다른 사용자의 이동을 덮어쓰지 않는다.
- 삭제·권한·DB 컨텍스트·구조 검증 보호와 히스토리 복원 안전장치는 유지한다.

## 범위

- 서버 순서 기준 속성 병합은 [서버 기록](2026-10-07-Sync-ServerConcurrentCommands.md)을 참고한다.
- 네트워크 연결이 끊긴 동안 입력은 이 브라우저에 보관된다. 완전한 오프라인 협업이나 CRDT 도입은 이번 범위가 아니다.
- 실제 Mac 브라우저 수동 검증은 수행하지 않았다.

## 검증

- `pnpm check` 통과: 포맷·전체 타입 검사·테스트 2,795개 통과(506개 조건부 건너뜀)·빌드 성공. 기존 번들 크기 경고는 남아 있다.
- 별도 격리 DB 서버 통합 테스트 130개 통과.
- A → B → A 입력, 이전 ACK 이후 새 입력 유지, 원격 갱신 중 드래그 유지, 카드 크기·위치 비중첩 변경, 응답 유실, 거부 요청 보관, 다른 탭 저장 완료 확인을 회귀 테스트로 검증했다.
- 다른 탭에서 대기 항목이 사라진 것만으로 저장 성공으로 간주하지 않는다. 보관한 원 요청과 서버 ACK를 대조한 뒤 완료한다.
