# MCP 구현 계획 단순화 기록

작성일: 2026-09-17

## 요청과 변경

사용자 요청에 따라 MCP LAN 호스팅 계획을 NestJS 내장 MCP와 사용자별 전용 Bearer 토큰 방식으로 수정했다. 기존 계획 문서에 설계 결정을 먼저 반영한 뒤 이 기록을 작성했다.

- 별도 MCP 프로세스, 공용 내부 계정, 내부 HTTP 호출과 세션 갱신을 제거했다.
- 웹 로그인 후 토큰 발급·목록·폐기, 해시 저장, 90일 만료, 원문 1회 표시와 사용자별 작업자 기록을 정의했다.
- REST와 MCP의 공통 서비스 재사용, 기존 동기화·권한·충돌 규칙 유지와 단계별 커밋을 명시했다.
- HTTPS 프록시에서 사내 대역을 제한하고 NestJS는 loopback에 두도록 네트워크 구성을 일치시켰다.
- Codex Bearer 설정 예시와 실제 연결·폐기·재발급 검증 기준을 반영했다.
- OAuth, 세분화된 권한과 독립 프로세스는 후속 범위로 정리했다.

## 검증

- 기존 정책·설정·운영·구현 단계·검증 기준 전체를 재검토해 공용 계정과 별도 3002 포트를 전제로 한 실행 지침을 교체했다.
- `.prettierignore`에서 `docs/`와 `**/*.md`가 제외됨을 확인했다. 문서만 변경하므로 포맷 적용 및 애플리케이션 테스트는 대상이 아니다.
- Git diff로 변경 범위를 확인했으며 `git diff --check`를 통과했다.
- 실제 MCP 코드·DB·네트워크 설정은 변경하지 않았다. 기존 사용자 작업과 `docs/EZERD.txt`는 수정하지 않았다.
