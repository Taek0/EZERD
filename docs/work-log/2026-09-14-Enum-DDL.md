# ENUM DDL 구현 및 검증

- 작성일: 2026-09-14
- 계획: `../planning/2026-09-14-Editor-Implementation.md`

프로젝트 ENUM 정의를 안정적인 ID로 컬럼에 연결하고, 스키마와 `CREATE TYPE ... AS ENUM`을 테이블보다 먼저 출력한다. ENUM의 이름을 바꾸어도 컬럼의 기존 타입 이름 힌트에 의존하지 않는다. ENUM 배열 및 같은 ENUM ID 사이 FK를 지원한다.

식별자와 값은 각각 안전하게 인용한다. 빈 값은 유효한 ENUM 레이블로 허용하며, 중복 값·NULL 문자·UTF-8 63바이트 초과·중복 타입 이름·테이블 행 타입과의 이름 충돌·누락 ENUM 참조를 차단한다. ENUM 컬럼의 길이/정밀도/스케일은 허용하지 않는다. 기본값은 선언된 레이블의 SQL 문자열 리터럴 또는 NULL만 허용하며 배열 리터럴 기본값은 기존의 보수적 정책대로 차단한다. FK는 양쪽의 배열 여부와 ENUM ID를 검사한다.

검증:

- 새 ENUM DDL 테스트 6개를 먼저 실행하여 4개 실패를 확인했다(RED).
- 구현 후 새 테스트 6개와 기존 DDL 테스트 11개, 총 17개 통과(GREEN).
- `pnpm --filter @ezerd/model build` 통과.
- `node scripts/verify-postgres-export.mjs` 통과. 실제 로컬 PostgreSQL에서 ENUM 생성, 따옴표/역슬래시/빈 레이블 및 순서, 기본값 INSERT, ENUM 배열 UPDATE, ENUM FK 생성, 미등록 레이블 거부를 확인했다. 기존 순환/복합 FK도 함께 검증하고 트랜잭션 롤백 후 검증 스키마가 남지 않음을 확인했다.
