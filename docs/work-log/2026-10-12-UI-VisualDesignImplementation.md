# 승인 목업 시각 디자인 제품 적용 결과

- 기준: c1c992a, 승인된 단색 버튼 목업. 브랜치 codex/apple-ui-review.
- [계획](../planning/2026-10-12-UI-VisualDesignImplementationPlan.md)

## 실제 적용

- 최종 product-design.css를 추가해 단색 버튼에 그치지 않고 전역 헤더·문서 식별 영역·툴바·좌측 탐색·우측 속성·핀·갤러리·메뉴·필드를 같은 시각 체계로 맞췄다.
- 문서명/저장 상태와 작업 도구를 별도 grid 행에 배치했다. 생성 주동작은 차콜 단색, 내보내기는 우측 그룹으로 정렬했다. 항목과 실행 함수는 유지한다.
- 속성 패널은 선택 객체를 강조하고 카드 안에 카드를 쌓는 표현을 줄였다. 비어 있는 캔버스 설정 host의 불필요한 공간을 제거했다.
- 입력·타입 검색·popover·우클릭·워크스페이스 메뉴의 배경·테두리·간격·hover·focus·disabled·오류 표현을 정리했다. 워크스페이스 전용 버튼의 기존 그라데이션도 제거했다.
- 기본 카드 헤더는 밝은 중립색, 제목 20px/본문 14px로 정리했다. 사용자 지정 테이블/도메인 색상은 보존하며 배경에 따라 읽기 좋은 전경색을 선택한다.
- 컬럼 행의 최소 높이와 너비, 관계 포트와 PNG의 글자·행·헤더·footer·색상을 함께 변경했다. 문서의 저장된 좌표·크기·색상 값은 수정하지 않는다.
- 갤러리의 여백과 미리보기 높이를 조정하고 보조 텍스트 대비를 보강했다.
- 우클릭/팝오버 140ms 진입·100ms 종료, 탐색 140ms 진입, 입력/버튼 짧은 피드백을 적용했다. 드래그 좌표에는 CSS 전환을 넣지 않았다. reduced-motion 분기를 유지/보강했다.

## 검증

- format 및 typecheck 통과. 전체 pnpm check에서 234개 파일/2,862개 테스트 통과, DB 통합 등 26개 파일/499개 테스트 건너뜀. 전체 빌드 성공.
- DB에 연결되지 않는 테스트 전용 URL과 EZERD_DB_TEST=0을 해당 검사 프로세스에만 사용했다.
- PNG·관계·카드·색상 보존 테스트를 실행했고, 과거 폰트의 우연한 줄바꿈에 의존하던 테스트는 명시적인 다중 행 샘플로 바꿨다. 데이터 불변 검증은 유지했다.
- 기본 헤더 및 밝고 어두운 사용자 지정 색상의 가독성을 테스트했다. 화면/PNG가 동일한 폰트 토큰과 치수를 사용하는 테스트를 유지했다.
- 실제 NativeProjectView, WorkspacePanel, Notifications, NativeProjectActions를 풍부한 테스트 데이터로 렌더링했다. 1600px iframe에서 비교했다. 목업 HTML을 구현 결과로 대신하지 않았다.
- 실제 컬럼 우클릭에서 컬럼 속성·PK 설정·삭제·추가·관계 연결 항목과 키보드 포커스를 확인했다. 메뉴는 흰색, 13px 텍스트, 224px 폭, 140ms 진입이며 화면 안에 배치됐다.
- 실제 타입 검색 창이 열리는 것을 확인했다. length=-1 입력에서 원문 초안 보존 오류가 표시되고 80 복원 시 오류가 사라지는 흐름을 확인했다. 오류 표현도 색·배경·경계로 구분했다.
- 최종 오류 표현 CSS 추가 후 format:check를 다시 확인했다. 다음 독립 모션 단위 완료 시 통합 검사를 다시 수행한다.

## 다음 단위 및 한계

- 알림 패널의 닫힘 중 재열기 입력과 애니메이션 역전은 다음 독립 단위로 보완한다.
- 데이터·인증·API 응답은 격리 검증용이다. 실제 DB 저장이나 공동 편집 통합 검증을 했다는 뜻은 아니다. 테스트 데이터의 자동 관계 경로를 제품 배치 변경으로 해석하지 않는다.
- 논리 설계/검증 메뉴 위치, 기존 필드·저장·권한·단축키는 유지했다. 모바일 신규 설계는 포함하지 않았다.
- Vite의 번들 크기 경고는 남아 있으며 빌드는 성공했다.
