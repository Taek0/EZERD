## 구성 변경

- 좌측 설계 탐색 영역을 추가했다. 테이블/컬럼 검색, 테이블별 접기·펼치기, 선택 컬럼 표시와 설계 메모 진입점을 제공한다.
- 전역 헤더, 문서명·저장 상태, 생성·보기 도구, 캔버스 범위 표시의 영역을 분리했다. 공통 아이콘·패딩·버튼 높이를 정리했다.
- 우측 편집기는 선택 객체 이름을 중심으로 속성 / 제약·관계 / SQL을 전환한다. 테이블·컬럼·관계 선택에 맞는 내용을 표시한다.
- 관계의 SQL 탭은 선택한 외래 키와 ON DELETE 설정을 사용한다. SQL은 목업용 예시이며 DB에 실행하지 않는다.
- 속성과 핀은 우측 영역을 공유한다. 핀을 열면 속성이 숨겨지고, 대화의 대상 컬럼을 선택하면 해당 속성으로 돌아온다. 캔버스 폭을 유지하는 목적이다.
- 캔버스 카드의 헤더·키 표식·컬럼 행·타입·선택 상태·하단 정보를 정돈했다. 미니맵은 필요할 때 펼치는 컨트롤로 바꿔 카드를 가리는 면적을 줄였다.
- 폼·목록·탭·관계 카드·핀 대화·다이얼로그·갤러리의 표면과 경계를 맞췄다.
- 모바일은 범위 밖이다. 논리 설계와 설계 확인 항목은 기존 더 보기 메뉴 안에 유지했다.

- 1600px와 1440px 데스크톱에서 실제 렌더링 확인.
- 1440px에서 문서 폭 1425px로 가로 넘침 없음. 속성 또는 핀을 표시하는 구성에서 캔버스 폭 약849px 확보.
- 좌측 검색에 price를 입력해 order_items.unit_price와 products.price가 표시되는 것을 확인.
- 검색 결과의 unit_price 선택 → 컬럼 속성 → SQL 전환 시 order_items.unit_price 예시 SQL 표시 확인.
- 제약·관계 탭의 선택 테이블 키·인덱스·관계 목록 확인.
- 핀을 열면 inspectorHidden=true, pinsHidden=false가 되는 것을 확인. 핀 대상 orders.status 선택 시 반대로 전환되는 것을 확인.
- orders → customers 관계를 선택한 뒤 SQL 탭에서 fk_orders_customer와 customer_id 참조 SQL 표시 확인.
- 더 보기 안의 논리 설계 켜기 / 설계 확인 항목 / 보관된 입력 복구 위치 확인.
- 확인한 콘솔 error 로그 없음. Node vm.Script로 3개 스크립트 블록 문법 검사 통과.

## 범위와 한계

- 독립적인 HTML 디자인 목업이며 제품 코드는 변경하지 않았다.
- 기존 레이아웃과 비교 가능한 구성 제안이지 승인된 제품 구현 사양은 아니다.
- 테이블·핀·히스토리·검증 결과는 예시다. 일부 필드는 현재 페이지 메모리에서만 변경되며 제품 API/DB에 저장하지 않는다.
- 관계선은 정해진 샘플 위치에 맞춘 표현이며 실제 ERD 라우팅 엔진이 아니다.
- 기존 분위기 비교는 같은 목업에 과거 스타일 특성을 재구성한 참고 표시다.
- 모든 컨트롤과 입력 조합을 회귀 검증한 것은 아니다. 정적 문법, 관찰한 주요 흐름, 데스크톱 렌더링을 검증했다.
- docs는 Prettier 제외 대상이다. 제품 구현 변경이 없으므로 제품 테스트는 재실행하지 않았다. 산출물 링크와 diff 공백을 확인하고 문서·목업만 커밋한다.
