# MCP 범위별 조회와 응답 크기 개선 계획

## 목표와 우선순위

MCP `get_project`는 설계 문서 전체를 반환한다. 문서 변경 결과와 이력에도 전체 문서가 포함될 수 있다. 클라이언트가 필요한 정보만 조회하도록 도구와 응답을 조정해 MCP 출력 토큰을 줄인다.

1. 프로젝트 요약, 화면별 배치, 테이블 상세 조회를 추가한다. 기존 `get_project`는 전체 스냅샷이 필요할 때 계속 사용한다.
2. `get_project_history`에 페이지 크기와 다음 순서 커서를 추가한다. 기본 응답은 메타데이터와 변경 경로만 반환하고, 변경값·전체 문서·삭제 스냅샷은 요청한 경우에만 포함한다.
3. 문서 변경·실행 취소·삭제 복원 도구의 기본 결과에서 전체 문서를 생략하고, 요청 옵션으로 전체 결과를 받을 수 있게 한다.
4. MCP 초기화 지침에 요약 → 화면/테이블 상세 → 변경 → 필요한 범위 재조회 흐름을 안내한다.

## 설계 결정

- 모든 범위별 조회는 한 번의 현재 프로젝트 스냅샷에서 투영하고 `project.version` 및 `syncSequence`를 함께 반환한다. 여러 호출 사이에 버전이 달라지면 쓰기 전 필요한 범위를 다시 조회한다.
- 화면 조회는 실제 `layout.nodes`의 `viewId`를 기준으로 카드를 선정한다. 결합 화면의 외부 참조 테이블도 포함한다. 도메인 화면에는 소유 테이블 외부 참조가 있을 수 있으므로 소유 관계만으로 필터링하지 않는다.
- 화면 조회의 테이블은 이름·범위 등 카드 요약만 반환한다. 컬럼·키·관계 상세는 `get_table_details`에서 요청한다.
- `get_table_details`의 관계는 해당 테이블에 연결된 관계를 반환한다. 관계 대상의 이름을 읽을 수 있도록 연결 테이블의 짧은 요약을 함께 제공한다.
- 기존 `get_project` 입력과 출력은 유지한다. 이력 및 쓰기 도구는 기본 출력만 축소하고 전체 정보는 옵션으로 요청할 수 있다.
- 이력 페이지네이션은 `sequence > since` 오름차순, 제한 개수에 1건을 더 읽어 다음 페이지 존재 여부를 판단한다. 기존 REST 동기화 API의 응답은 바꾸지 않는다.
- DB는 설계 문서를 JSON 한 행으로 보관한다. 이번 작업은 MCP 전송량과 모델 입력 토큰을 줄이며 DB의 문서 읽기 비용은 후속 과제다.

## 검증

- MCP SDK로 등록 도구의 입력·출력, 빈/존재하지 않는 화면과 테이블, 결합 화면의 외부 참조, 이력 페이지 경계, 전체 문서 옵션을 확인한다.
- 기존 쓰기 동시성·재시도·작업자 규칙이 유지되는지 단위 및 가능하면 통합 테스트로 확인한다.
- 루트 Prettier 형식 검사, 타입 검사와 관련 테스트를 실행한다.
