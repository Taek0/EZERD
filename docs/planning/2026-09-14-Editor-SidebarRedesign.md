# 편집기 사이드바 재구성 계획

기록일: 2026-09-14

대상: 프로젝트를 연 이후의 편집기 화면(도메인 맵 뷰 · 도메인 내부 테이블 뷰). 랜딩 화면과 프로젝트 갤러리는 이번 범위가 아니다.

근거: 사용자 피드백 "공통 컴포넌트를 가져왔지만 사용성이 좋지 않다. 랜딩과 대시보드는 괜찮고, 프로젝트 선택 이후 도메인 뷰부터 난잡하다. 사이드바 구성 위주로 봐 달라."

이 문서는 [편집 워크플로우 개선 결정 사항](./EDITOR_WORKFLOW_DECISIONS.md)의 기능 결정을 유지한 채 **배치와 정보 구조만** 바꾸는 계획이다. 기능을 제거하지 않는다.

## 1. 현재 구조의 문제

속성 패널(`aside.inspector`)은 선택 상태에 따라 네 가지 화면을 통째로 교체한다.

| 상태 | 렌더링되는 내용 |
| --- | --- |
| 테이블 선택 | `TableInspector` 아코디언 7개 |
| 도메인 · 텍스트 선택 | 이름/설명/색상/연결 관계/위치·크기/삭제 |
| 도메인 맵 · 선택 없음 | 아코디언 3개 + disclosure 1개 |
| 도메인 내부 · 선택 없음 | `TableWorkspaceTools` 아코디언 4개 |

여기서 확인한 구체적인 문제는 다음과 같다.

1. **고정된 뼈대가 없다.** 카드를 선택하면 생성 도구가 사라지고, 선택을 해제하면 속성이 사라진다. 패널 안에서 지금 무엇을 보고 있는지 알려 주는 고정 영역이 없다.
2. **접힘 컴포넌트가 세 종류 섞여 있다.** `Accordion`(`<details>`), `DisclosureButton`+`Collapse`, 일반 섹션이 같은 화면에 나란히 쌓여 서로 다른 모양으로 보인다.
3. **중첩이 3단까지 내려간다.** 컬럼 생성·편집 → 개별 컬럼 → 사용자 정의 메타데이터 → 텍스트 영역 3개. 들여쓰기 단서가 없어 어느 단계인지 읽히지 않는다.
4. **패널 안에서 가로 스크롤이 생긴다.** `.table-create-grid`가 `min-width:570px`인데 패널 폭은 280–520px이다. `.table-column-create`가 `overflow:auto`라 사이드바 안에 가로 스크롤바가 나타난다.
5. **장식용 표기가 공간을 차지한다.** 패널 제목의 `02 / INSPECTOR`는 마케팅 화면의 번호 표기이며 도구 패널에서는 의미가 없다.
6. **같은 명령의 입구가 흩어져 있다.** 표시 모드는 툴바 아래 별도 줄과 `TableWorkspaceTools`에 중복 정의되어 있고, 새 도메인 관계는 우클릭 메뉴 · 도메인 속성 · 관계 폼 세 곳에 있다.
7. **현재 화면의 목록을 볼 방법이 없다.** 테이블이 많아지면 테이블 검색 아코디언을 펼쳐 이름을 입력하는 것이 유일한 탐색 수단이다.
8. **툴바가 비대칭이다.** `＋ 도메인`은 도메인 맵에만 있고, 도메인 내부에는 테이블 생성 버튼이 없어 사이드바 아코디언 안에 숨어 있다.
9. **위치·크기 숫자 입력 4개**가 도메인·텍스트 속성의 상단부를 차지한다. 사용 빈도에 비해 노출이 과하다.

## 2. 설계 원칙

- 패널은 **고정 머리말 + 스크롤 본문**의 항상 같은 뼈대를 유지한다. 선택이 바뀌어도 뼈대는 바뀌지 않는다.
- 접기 UI는 **한 종류**만 쓴다.
- **직접 조작 대상(생성)은 캔버스 툴바**, **선택 대상의 세부 정보는 사이드바**로 나눈다.
- 기존에 제공하던 기능을 없애지 않는다. 위치만 옮기고 옮긴 위치를 문서에 남긴다.
- 결정 문서에서 확정한 동작(자동 배치는 빈 캔버스 우클릭으로만 실행, 복합 UNIQUE, FK 확인 단계, 물리명 상단·논리명 하단)은 그대로 둔다.

## 3. 새 사이드바 구조

```text
aside.inspector
  머리말 (고정)
    현재 위치     도메인 맵 또는 도메인 이름
    선택 표시     선택한 객체의 종류와 이름, 선택 해제
    탭            속성 | 목록
  본문 (스크롤)
    속성 탭
      선택 없음   현재 뷰 요약 + 생성 폼(접힘)
      도메인      이름 · 설명 · 색상 · 연결된 관계 · 위치와 크기(접힘) · 삭제
      텍스트      내용 · 위치와 크기(접힘) · 삭제
      테이블      기본 | 컬럼 | 키·관계 | 고급 구역 이동 후 해당 구역만 표시
    목록 탭
      검색 입력 (고정)
      도메인 맵   도메인 목록 · 도메인 관계 목록
      도메인 내부 이 화면의 테이블 · 다른 도메인 테이블(참조 추가) · 테이블 관계
```

### 탭을 두 개로 두는 이유

지금 고른 것과 이 화면에 무엇이 있는지는 서로 다른 질문이다. 지금은 두 질문의 답이 같은 자리에서 번갈아 나타나서 한쪽을 보는 동안 다른 쪽을 볼 수 없다. 탭으로 나누면 선택을 바꾸지 않고도 목록을 훑을 수 있고, 목록에서 항목을 고르면 자동으로 속성 탭으로 이동한다.

### 기능 이동표

| 기존 위치 | 새 위치 |
| --- | --- |
| 사이드바 새 도메인 생성 아코디언 | 툴바 `＋ 도메인`과 속성 탭 빈 상태의 이름 지정 생성 폼 |
| 사이드바 새 테이블 생성 아코디언 | 툴바 `＋ 테이블`과 속성 탭 빈 상태의 이름 지정 생성 폼 |
| 사이드바 프로젝트 ENUM 아코디언 | 툴바 `ENUM` 버튼이 여는 대화상자 |
| 사이드바 테이블 검색 아코디언 | 목록 탭의 검색 입력과 테이블 목록 |
| 사이드바 외부 테이블 참조 아코디언 | 목록 탭 다른 도메인 테이블 구역의 행별 참조 동작 |
| 사이드바 연결된 관계 검색 아코디언 | 목록 탭의 검색 입력과 강조 대상 선택 |
| 사이드바 도메인 관계 목록 아코디언 | 목록 탭의 관계 목록 |
| 툴바 아래 표시 모드 별도 줄 | 툴바의 논리 / 물리 / 함께 세그먼트 하나로 통합 |
| 속성의 위치·크기 입력 4개 | 접힌 위치와 크기 구역 |

자동 배치는 결정 문서대로 빈 캔버스 우클릭 메뉴에만 둔다. 툴바 버튼을 추가하지 않는다.

## 4. 테이블 속성의 중첩 완화

테이블 속성은 항목별로 접고 펼 수 있어야 한다는 결정을 유지하되, 한 화면에 7개 아코디언을 동시에 쌓지 않는다.

| 구역 | 포함 항목 |
| --- | --- |
| 기본 | 적용 범위, 논리 특성, 물리 특성 |
| 컬럼 | 컬럼 추가 표, 컬럼 목록과 개별 편집 |
| 키·관계 | PK / UNIQUE, 테이블 관계, FK 출발 컬럼 |
| 고급 | 사용자 정의 메타데이터, 테이블 삭제 |

구역 안에서는 기존처럼 개별 항목을 접을 수 있다. 중첩은 최대 2단으로 제한하고, 2단에는 왼쪽 세로선으로 단계를 표시한다.

컬럼 추가 표는 고정 `min-width`를 없애고 패널 폭에 맞춰 접히는 격자로 바꾼다. 사이드바 안에서 가로 스크롤이 생기지 않게 한다.

## 5. 유지할 것

- 뉴모피즘과 스위스 디자인 토큰, Apple SD Gothic Neo 굵기 규칙, 파랑 강조색.
- 패널 폭 드래그·키보드 조절(기본 320px, 280–520px)과 좁은 폭에서 아래로 배치하는 동작.
- 접힌 콘텐츠를 키보드·접근성 트리에서 제외하는 처리와 움직임 줄이기 설정 대응.
- 댓글 패널, 자유 텍스트, 알림, DDL 내보내기 동작.

## 6. 검증 기준

- [ ] 선택을 바꿔도 패널 머리말과 탭이 그대로 남는다.
- [ ] 도메인 맵과 도메인 내부 모두에서 생성·검색·목록·참조 기능에 도달할 수 있다.
- [ ] 사이드바 안에서 가로 스크롤이 발생하지 않는다.
- [ ] 접기 컴포넌트가 한 종류로 통일되고 중첩이 2단을 넘지 않는다.
- [ ] 자동 배치는 여전히 빈 캔버스 우클릭에서만 실행된다.
- [ ] 타입 검사와 테스트가 통과한다.
