# 테이블 자동 배치 Undo와 로컬 fixture 이력 일치

## 문제와 범위

테이블 자동 배치 후 Undo가 배치 작업 전체를 한 번에 복원하는지 확인한다. 실제 캔버스는 배치 좌표 명령을 한 번의 `saveCommands` 호출로 넘기고 서버는 한 작업의 모든 변경 경로를 이력으로 저장한다. 따라서 모델·저장 큐의 묶음과 fixture의 이력 분류를 함께 검증한다.

성능 fixture는 현재 Undo 작업에 서버의 `deletionSnapshot.nativeHistory` 메타데이터를 담지 않는다. 이로 인해 실제 서버와 달리 이미 취소된 원본과 Undo 작업이 모두 새 Undo 후보로 보일 수 있다.

## 작업

1. 테이블 배치 명령 전체가 하나의 저장 작업으로 들어가고 한 번의 역변경으로 모든 노드 좌표가 돌아오는 회귀 테스트를 추가한다.
2. fixture 이력 응답과 중복 Undo 처리를 실제 서버의 보상 작업 메타데이터에 맞춘다.
3. 대상 테스트, 타입 검사 및 포맷 검사를 수행한다. 제품 화면이나 실제 서버의 Undo 의미는 브라우저 재현 결과에 따라 별도 판단한다.
