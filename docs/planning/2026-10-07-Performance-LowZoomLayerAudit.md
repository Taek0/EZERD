# 저배율 표시 이상 후속 조사 계획

- 첨부 검토 의견에 따라 이전 관찰과 원인 가설을 분리한다. 히트 테스트 성공은 pointer-events:none 덮개를 배제하지 않으며, DOM 표시 상태는 픽셀 노출을 보증하지 않는다.
- lab 결과 textarea가 문서 스크롤을 만드는 교란 요인을 제거하고 동일 viewport/카메라에서 상위·형제·가상 요소 및 카드 내부 경계를 기록한다.
- 카메라 참조/effect/측정·가시성 경로를 소스와 DOM 상태로 확인한다. 패닝 이동량을 zoom으로 나누지 않는다.
- 브라우저 원본 캡처와 DOM 감사 기록은 같은 카메라 상태에서 비교하고 브라우저 연결 실패를 제품 오류로 해석하지 않는다.

## 추가로 확인된 제품 좌표 문제

- body scroll을 제거한 상태에서도 초기 화면에서 11.2157%까지 축소하면 surface.scrollTop=138, scrollHeight=1219, clientHeight=1081이 관찰됐다.
- 패닝 후 scrollTop=0으로 줄어 카메라 y delta -300px와 실제 카드 이동 -162px가 불일치했다.
- 카메라 기반 viewport에서 native 스크롤이 개입하지 않도록 native surface의 overflow를 clip으로 바꾼 뒤 동일 경로·포커스·배율에서 검증한다. 카드 내부/속성 패널의 스크롤은 유지한다.
