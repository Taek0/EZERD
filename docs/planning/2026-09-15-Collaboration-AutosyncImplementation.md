# 자동 저장·동기화 구현 계획

작성일: 2026-09-15
상태: 구현 진행 중

## 구현 범위

확정된 자동 저장·객체 속성 동기화 설계를 현재 React, NestJS, PostgreSQL 애플리케이션에 적용한다. 편집 쓰기는 전체 문서 PUT에서 작업 명령 제출로 전환하고, 서버 승인 순서와 속성 버전을 기준으로 모든 참여자가 같은 문서를 구성하게 한다.

## 구현 계약

- 클라이언트는 사용자 동작마다 UUID `operationId`와 `groupId`, 안정적인 `clientId`, 마지막 서버 `baseSequence`, 서버가 발급한 마지막 성공 동기화 기준과 변경 전후 문서를 보낸다. 클라이언트 시각이나 클라이언트가 선언한 온라인 상태를 신뢰하지 않는다.
- 초기 구현의 원자적 작업 표현은 구조 검증이 끝난 변경 전후 문서다. 서버는 주장된 경로를 신뢰하지 않고 ID 기반 의미 차이를 계산한 뒤, 현재 잠금 문서에 변경 속성만 적용하고 전체 결과를 검증한다. 배열 인덱스를 변경 식별자로 쓰지 않으며 위치·타입·키·순서 이동 묶음은 하나의 원자적 의미 단위로 처리한다.
- 서버가 확인한 실시간 연결 기준의 온라인 작업은 동일 속성의 최신 서버 승인 우선으로 적용한다. 재접속 작업은 서버가 발급한 마지막 성공 동기화 기준으로부터 24시간 이내이며 각 기준 속성 버전이 유지된 경우에만 적용한다. 재접속이나 재전송이 기존 대기 작업의 기준 시각을 갱신하지 않는다.
- 서버는 프로젝트 순서, 작업 ID와 요청 지문, 변경 전후 값, 변경 주체, 속성 버전, 삭제 스냅샷을 7일간 보존하고 실제 정리 작업을 수행한다. 동일 작업 ID의 결과 조회는 만료 검증보다 먼저 수행하여 동일 지문이면 기존 결과를 반환하고 다른 지문이면 거부한다. 삭제 표식 정리 뒤에도 오래된 생성·수정이 부활 경로가 되지 않게 프로젝트 기준 순서와 동기화 기준을 함께 검증한다.
- 사용자 등록 응답에서 서버 세션 토큰을 발급한다. 프로젝트와 핀·답글을 포함한 모든 쓰기, 이력·복원 및 WebSocket 경로는 세션과 프로젝트 활성 상태를 같은 잠금 순서로 확인하며 현재는 모든 사용자에게 같은 권한을 준다.
- WebSocket은 프로젝트 구독 후 승인 이벤트와 현재 순서를 전달한다. 주기적인 서버 머리 순서 확인으로 마지막 이벤트 하나만 유실된 경우도 감지한다. 순서 누락은 REST 변경 조회로 보완하고, 보존 범위를 벗어나면 최신 스냅샷을 다시 받는다.
- 클라이언트는 화면에 먼저 반영한 뒤 전송 전에 IndexedDB에 작업을 기록한다. 서버 확인 전 작업은 최신 서버 문서 위에 순서대로 재적용한다. 마지막 성공 동기화 기준이 24시간을 넘긴 작업이나 서버가 충돌로 거부한 작업은 자동 전송하지 않고 미반영 편집으로 보관한다. 7일 만료와 저장 실패·만료 예정을 화면에 표시한다.
- 실행 취소와 다시 실행은 사용자의 승인 작업에 대한 역작업과 기대 속성 버전·구조 의존성을 기록해 수행한다. 아직 승인 여부를 모르는 전송 작업은 작업 결과를 먼저 조회하며, 원격 변경을 포함한 전체 스냅샷으로 역작업을 만들지 않는다.
- 통합 이력은 변경, 삭제, 미반영 편집을 한 패널에서 구분한다. 삭제 복원은 서버가 새 ID를 발급해 유효한 내부 구조를 원자적으로 생성한다.
- 조합뷰에서는 내용 편집을 허용하고 카드 및 관계선 배치 변경은 막는다. 개인 뷰 선택과 화면 위치는 동기화 작업에서 제외한다.

## 구현 단위

1. 공유 변경 명령, 이벤트, 이력, 세션 계약과 순수 문서 차이·재적용 모델을 구현하고 단위 테스트한다.
2. PostgreSQL 스키마와 서버 트랜잭션, 세션, 작업 제출·조회·복원 API 및 WebSocket 브로드캐스트를 구현한다.
3. 웹의 IndexedDB 대기열, 낙관적 문서 재구성, 자동 저장 상태, 재접속, 작업 단위 실행 취소 및 통합 이력 UI를 구현한다.
4. 기존 저장 버튼과 전체 PUT 편집 경로를 제거하고, 댓글 쓰기에도 서버 세션을 적용한다.
5. 단위·통합·브라우저 검증으로 중복, 같은 속성 경합, 삭제 우선, 재접속 보호, 5개 세션 전파를 확인한다.

## 에이전트와 파일 소유권

- 공유 모델·계약: `packages/model/src/sync*`, `packages/contracts/src/sync*`와 해당 테스트.
- 서버: `apps/server/src/sync*`, DB 스키마·마이그레이션·통합 테스트.
- 웹: `apps/web/src/sync*`, `App.tsx`, 관련 UI·스타일·테스트.
- 구현 세션은 모두 Sol medium을 사용한다. Astra low는 읽기 전용 검토에만 사용한다.
- 구현 리드가 교차 영역 연결, 검증, 작업 기록과 범위별 커밋을 담당한다.

## 검증 기준

- 동일 작업 재전송은 한 번만 저장되고 같은 승인 결과를 반환한다.
- 서로 다른 속성은 오래된 기준에서도 병합되고, 동일 속성의 온라인 변경은 서버 승인 순서대로 수렴한다.
- 마지막 성공 동기화 후 24시간 이내 재접속 작업은 기준 속성이 유지된 경우만 적용되며 오래되거나 충돌한 작업은 미반영으로 남는다.
- 삭제 뒤의 수정은 객체를 부활시키지 않으며 삭제 이력 복원은 새 ID를 사용한다.
- 서버 이벤트 순서 누락을 조회로 복구하고 새로고침 뒤 IndexedDB 작업을 유지한다.
- 승인된 실행 취소·다시 실행은 다른 사용자의 후속 변경을 덮어쓰지 않으며 승인 여부가 불명확한 작업은 결과 조회 후 처리한다.
- 저장 버튼 없이 편집 확정 시 자동 저장 상태가 전송 중, 동기화됨, 연결 끊김, 확인 필요로 구분된다.
- 5개 브라우저 세션에서 승인된 변경이 1초 안에 전파되는지 측정한다.
