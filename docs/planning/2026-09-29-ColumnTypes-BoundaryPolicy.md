# 타입 저장 정책 및 매개변수 검증 통일

- REAL, DOUBLE PRECISION, NUMERIC 및 기존 숫자 타입은 유지한다. 운영 DB 컬럼 변환이나 데이터 일괄 변경은 하지 않는다.
- 별칭은 입력으로 허용하되 API·MCP·가져오기·저장 경계에서 대표 이름으로 정규화한다. ENUM 이름은 변경하지 않는다.
- 길이·정밀도·소수 자릿수·배열의 타입별 조합을 공통 검증으로 분리해 계약과 DDL에서 공유한다. NUMERIC의 음수 scale 및 precision보다 큰 scale처럼 유효한 기존 조합은 유지한다.
- 변환된 parse 결과가 실제 저장과 동기화에 사용되는지 확인한다. 기존 문서 읽기와 부분 수정·동시 편집 호환성도 검토한다.
- 공통 모델·계약과 서버 경계 작업을 분리해 진행하고, 잘못된 조합의 저장 거부 및 별칭 정규화 회귀 테스트를 추가한다.
