# 기존 로컬 데이터 마이그레이션 계획

- 현재 연결 대상이 로컬 PostgreSQL인지 확인하고 적용된 Drizzle 이력 및 테이블별 건수를 조회한다. 비밀번호·세션·토큰·설계 원문은 출력하지 않는다.
- 새 스키마 변경 전에 복구 가능한 DB 백업을 만든다. 0014 및 미적용 이력을 검토하고 정규 마이그레이션으로 적용한다.
- 오류가 발생하면 원인과 적용 상태를 먼저 확인하고 데이터를 초기화하거나 이력을 임의로 건너뛰지 않는다.
- 이후 DB 준비 검사와 기존 프로젝트·사용자·워크스페이스·댓글 등 데이터 보존, 새 프로필 필드 및 기존 설계 문서 읽기 호환성을 확인한다.
- JSON 설계 문서의 별도 네이티브 업그레이드는 스키마 마이그레이션과 구분한다. 현재 구현이 요구하는 경우에만 데이터 보존·리비전·이력 정책을 검토해 진행한다.
