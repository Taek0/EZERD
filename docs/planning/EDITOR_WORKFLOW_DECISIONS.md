사용자 제공 `EZERD.txt`, 검토 질문에 대한 사용자 답변, 마지막 자동 배치 메뉴 결정을 통합했다. 원문과 후속 답변이 다르면 후속 답변을 우선한다. 구현 현황은 [구현 진행 기록](../work-log/IMPLEMENTATION_PROGRESS.md), 기존 출시 기준은 [첫 출시 범위](./RELEASE_SCOPE.md)를 함께 확인한다.

## 1. 핵심 선택 결과

| 항목 | 결정 |
| --- | --- |
| ENUM | 프로젝트 공통 PostgreSQL ENUM으로 관리하고 DDL 생성 지원 |
| FK 생성 | 대상 테이블을 클릭한 다음 참조할 PK/UNIQUE와 컬럼 대응을 확인한 후 생성 |
| UNIQUE | 체크한 컬럼들을 하나의 복합 UNIQUE로 생성 |
| 도메인 자동 배치 | 도메인 관계 흐름을 기준으로 배치 |
| 테이블 자동 배치 | 현재 화면의 테이블과 외부 참조를 테이블 관계 흐름에 따라 배치 |
| 자동 배치 실행 | 두 뷰 모두 **캔버스 빈 공간 우클릭 → 자동 배치**를 선택할 때만 실행 |
| 도메인 필터 | 관련 도메인·관계 강조, 나머지는 흐리게 표시 |
| 참조 기호 | 까마귀발 표기법 사용 |
| 카드 내부 편집 시작 | 셀 더블클릭 |
| 테이블 이름 순서 | 함께 보기에서 **물리명 상단, 논리명 바로 아래** |

원문의 ‘논리 테이블명 최상단, 바로 아래 논리 테이블명’ 중복 표기는 최신 답변에 따라 위 순서로 정리했다. 이 선택은 이름 표시 우선순위에 관한 결정이며, 기본 보기 모드를 물리 보기로 바꾸라는 결정은 아니다. 논리·물리 단독 보기에서는 기존처럼 해당 이름을 표시한다.

## 2. 도메인 맵 뷰

### 선택한 카드가 없는 상태

오른쪽 패널에 다음 항목을 제공하며 기본 상태는 모두 접힘이다.

- 새 도메인 생성
- 새 도메인 관계 생성
- 연결된 관계 검색
- 연결된 관계 목록

### 도메인 카드와 선택

- 도메인 카드의 기본색은 회색으로 한다. 기존에 지정한 개별 색상을 일괄 덮어쓰는 요구는 없다.
- 도메인 이름 글꼴을 현재보다 키운다. 구체적인 크기와 회색 값은 구현 시 화면 검증으로 정한다.
- 좌클릭하면 오른쪽 패널에서 도메인 이름, 설명, 연결된 관계와 새 관계 생성 항목을 확인한다.
- 같은 도메인 쌍 사이에도 여러 관계를 생성할 수 있다.
- 연결된 도메인을 골라 보면 해당 도메인과 관계를 강조하고 나머지는 흐리게 한다. 필터는 객체를 삭제하거나 저장된 배치를 바꾸지 않는다.

### 우클릭 메뉴

| 위치 | 제공할 명령 |
| --- | --- |
| 캔버스 빈 공간 | 새 도메인, 자동 배치, 새 도메인 관계 |
| 도메인 카드 | 새 도메인 관계, 도메인 직접 연결하기 |

- 새 도메인 관계 명령은 오른쪽 패널의 생성 기능으로 연결한다.
- 직접 연결하기는 출발 도메인을 정한 뒤 목표 도메인을 클릭하여 관계 화살표를 만드는 흐름이다.
- 원문의 ‘도메인 카드 정렬’은 단순 격자 정렬이 아닌 **관계 흐름 기반 자동 배치**로 확정했다.

## 3. 테이블 뷰

### 카드 표시와 이름

- 테이블 카드의 기본 형태는 현재 구성을 유지한다.
- 기본 컬럼 정보는 다음 구조로 표시한다.

| PK·FK 여부 | 속성 | 타입 | NULL 여부 | 코멘트 |
| --- | --- | --- | --- | --- |

- PK이면서 FK인 컬럼은 두 역할을 함께 표현할 수 있어야 한다.
- 함께 보기의 테이블 제목은 물리명 위, 논리명 아래 순서다.
- 논리명·물리명·각 컬럼 값은 카드 내부에서 편집할 수 있다.
- 셀 더블클릭으로 편집을 시작한다.
- 컬럼 영역 오른쪽 아래의 `+`로 바로 컬럼을 추가할 수 있게 한다.
- 테이블 관계에 표시 이름과 설명을 제공한다. 이름 패턴은 `{출발테이블}.{속성}:{도착테이블}`이다.
- 관계선에는 까마귀발 표기법을 적용한다.
- 테이블 관계선을 우클릭하면 삭제 메뉴를 제공한다.

### 선택한 테이블이 없는 상태의 오른쪽 패널

다음 항목을 기본적으로 접어서 제공한다.

- 테이블 생성
- ENUM 생성
- 테이블 검색

### 테이블 선택 상태의 오른쪽 패널

각 항목을 개별적으로 접고 펼칠 수 있게 한다.

- 물리 특성
- 논리 특성
- 컬럼 추가
- UNIQUE 생성
- 테이블 관계 추가

컬럼 추가는 표 형태로 구성한다.

| PK 여부 | 속성 | 타입 | NULL 여부 | 코멘트 |
| --- | --- | --- | --- | --- |
| 기본 미선택 | 입력 | 선택·입력 | 기본 NOT NULL | 입력 |

신규 컬럼의 기본값을 바꾸는 결정이다. 기존 저장 컬럼의 NULL 허용 값을 일괄 변경하지 않는다. 논리적 필수 여부와 물리적 NULL 허용 여부는 계속 독립적인 값으로 관리한다.

### 키와 FK 생성

- UNIQUE 생성에서는 컬럼 체크박스를 세로로 나열한다.
- 여러 컬럼을 체크하면 **하나의 복합 UNIQUE**를 만든다. 컬럼별 개별 UNIQUE를 자동으로 여러 개 만드는 의미가 아니다.
- 테이블 관계 추가에서는 출발 컬럼, 대상 테이블, 카디널리티를 선택한다.
- 컬럼 우클릭의 FK 추가에서도 대상 테이블 클릭 후 **PK/UNIQUE 선택과 양쪽 컬럼 대응 확인** 단계를 거친다.
- 단일 PK라도 대상 테이블 클릭만으로 FK를 즉시 자동 확정하는 방식은 선택하지 않았다.
- 복합 키를 참조할 때에는 대응할 출발 컬럼들과 순서를 확인할 수 있어야 한다.

## 4. 자동 배치

실행 경로는 두 뷰 모두 **캔버스 빈 공간 우클릭 → 자동 배치**다.

| 현재 뷰 | 배치 대상 | 기준 관계 |
| --- | --- | --- |
| 도메인 맵 | 현재 맵의 도메인 카드 | 도메인 관계 |
| 테이블 뷰 | 현재 화면에 배치된 테이블과 외부 참조 카드 | 테이블 관계 |

- 메뉴를 선택했을 때만 실행한다. 객체·관계를 편집할 때마다 자동 실행하지 않는다.
- 외부 참조 카드의 위치가 바뀌어도 원본 테이블의 소유 도메인이나 다른 화면의 배치를 바꾸지 않는다.
- 현재 뷰를 넘어서 프로젝트 전체의 모든 ERD를 자동 배치하는 기능으로 확대하지 않는다.
- 배치 알고리즘·방향·간격은 아직 선택하지 않았다. 순환 관계와 연결되지 않은 카드의 처리도 구현 설계에 포함한다.
- 모든 관계선의 교차를 제거한다고 보장하지 않는다. 별도의 전체 실행 취소·이력 복원 기능을 이번 결정으로 추가한 것은 아니다.

## 5. 프로젝트 공통 ENUM과 DDL

- 프로젝트에서 공통으로 사용할 ENUM을 정의한다.
- 생성 입력은 ENUM 이름과 값 목록이다.
- 생성된 ENUM 이름을 컬럼 타입 선택에 제공한다.
- 실제 PostgreSQL ENUM을 지원하고 생성 DDL에 타입 정의를 포함한다. 선택 목록만 추가하는 기능이 아니다.
- 기존 후속 범위였던 사용자 정의 타입 지원 중 **ENUM에 한해 이번 구현 대상으로 앞당긴다.** 다른 사용자 정의 타입까지 일괄 포함하지 않는다.
- 현재 저장 모델과 DDL 생성기는 아직 ENUM 정의·참조를 지원하지 않는다. 타입 정의 저장, 컬럼 참조, 검증과 내보내기를 함께 확장해야 한다.

## 6. 유지하는 기존 원칙

- 논리·물리는 안정적인 동일 객체 ID로 관리하며 각자의 이름·특성을 독립적으로 편집한다.
- 도메인 업무 관계를 만들었다고 물리 FK를 자동 생성하지 않는다.
- 다른 도메인의 테이블은 원본 참조를 사용한다.
- 사용자가 별도로 요청하지 않은 기존 홈 화면·공통 파란색 테마·폰트·댓글·자유 텍스트 기능은 이번 기획으로 제거하거나 재설계하지 않는다. 도메인 카드 기본 회색은 공통 강조색 파랑과 구분한다.
- 실시간 공동 편집, 전체 실행 취소·이력 복원, DDL 가져오기·실제 DB 연결·변경 SQL은 계속 후속 범위다.

## 7. 검토 제안과 남은 상세 설계

아래는 검토 중 제안했거나 추가 설계가 필요한 사항이다. **사용자가 명시적으로 확정한 선택과 구분하며, 새로 확정된 요구로 간주하지 않는다.**

| 사항 | 검토 방향 / 남은 결정 |
| --- | --- |
| 메뉴와 접힌 패널 | 생성 명령을 선택하면 해당 섹션만 자동으로 열고 작성 중 내용을 보존하는 방식을 권장. 선택 전환 시 펼침 상태 규칙은 구체화 필요 |
| 직접 연결 취소 | 임시선 표시와 Esc 취소를 권장. 직접 연결 후 관계 이름을 입력·확정하는 시점은 구체화 필요 |
| 셀 편집 확정 | Enter/Tab 또는 포커스 이동으로 확정, Esc 취소를 제안했으나 확정된 시작 방식은 더블클릭뿐. 세부 키 동작은 구현 전에 정리 |
| 컬럼 표의 밀도 | 코멘트 말줄임·전체 보기, 최소 폭·스크롤 정책 필요. 함께 보기에서 속성·타입·코멘트를 어떻게 배치할지도 구체화 |
| 복합 PK | 여러 PK 체크를 하나의 복합 PK에 반영하는 방식 권장. 키 순서를 편집하는 UI 필요 |
| 관계 이름 | 표시용 이름과 실제 FK 제약 이름 분리 권장. 복합 컬럼 표시, 이름 변경 추적과 수동 수정 규칙 필요 |
| 까마귀발 | 양끝의 최소·최대 개수와 선택성을 표현할 모델 필요. 논리 표기와 실제 UNIQUE/NOT NULL 제약의 연동 규칙은 아직 확정하지 않음 |
| ENUM 상세 | PostgreSQL 스키마·이름 중복·값 순서·사용 중 삭제·값 변경 및 기존 문서 호환 정책 필요. 안정적인 참조를 유지하는 구조 권장 |

현재 결정에서 FK 선택만으로 컬럼을 자동 생성하거나, 1:1 선택만으로 UNIQUE를 자동 추가하거나, N:M 선택만으로 연결 테이블을 자동 만드는 기능은 승인된 것으로 해석하지 않는다.

## 8. 새 구현 검증 항목

아래는 이번 기획을 위한 추가 기준이며 아직 완료 표시하지 않는다.

- [ ] 두 뷰의 선택 없는 패널이 기본 접힘 상태로 시작한다.
- [ ] 도메인 기본 회색과 확대된 이름 표시를 적용한다.
- [ ] 빈 캔버스·도메인 카드·컬럼·테이블 관계선의 우클릭 메뉴가 구분된다.
- [ ] 도메인 직접 연결과 같은 도메인 쌍의 복수 관계를 지원한다.
- [ ] 관련 도메인 필터가 강조·흐림으로 작동하고 설계 원본을 변경하지 않는다.
- [ ] 도메인·테이블 뷰의 자동 배치가 빈 캔버스 우클릭 명령으로만 실행된다.
- [ ] 테이블 자동 배치에서 외부 참조의 소유권과 다른 화면 배치를 유지한다.
- [ ] 프로젝트 공통 ENUM을 컬럼에서 선택하고 CREATE TYPE을 포함한 DDL을 검증한다.
- [ ] 컬럼 표, 신규 NOT NULL 기본값, 복합 UNIQUE, 확인 단계를 거치는 FK를 지원한다.
- [ ] 물리명 상단·논리명 하단과 더블클릭 셀 편집을 지원한다.
- [ ] 까마귀발 관계 표기와 관계선 우클릭 삭제를 지원한다.
