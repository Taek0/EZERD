# Native signed integer 검증 변환

- 기준: 루트 AGENTS, [구현 명세](2026-10-01-Database-CapabilitySpecification.md), [타입·기능 표](2026-10-01-Database-TypeFeatureMatrix.md), [진행 상태](../work-log/2026-10-01-Database-ImplementationProgress.md). 담당 파일은 실제 `packages/model/src/database/conversion.ts/test`, 새 conversion-rules/helper/test, `apps/server/src/workspace/project-database.service.ts` 및 전용 tests, 이 계획/작업 기록이다. main index/validation/policy/history/cancellation/UI는 수정하지 않는다. git add/commit/full check/build는 main 담당이다.
- PostgreSQL18/MySQL8.4 signed SMALLINT16, INTEGER/INT32, BIGINT64만 exact integer stored-value domain을 검사한다. 실제 PG18.6/MySQL8.4.11 임시 QA DB에서 min/max/0/-1/1 및 양방향 문자열 roundtrip, 양쪽 overflow rejection을 검증한 뒤 engineVerified registry로 등록한다. SQL 문자열 치환이나 numeric widening/coercion equivalence를 주장하지 않는다.
- PG namespace는 empty/public만 MySQL current database로, MySQL current는 PG public으로 명시 변환한다. source namespace 원문은 source-map/audit로 유지한다. MySQL table은 InnoDB만, 대상 InnoDB 옵션만 만든다. 명시 charset/collation 및 기타 table/column 옵션은 미검증으로 차단한다. 한 문서의 물리 identifier 충돌/DB별 길이/엔진 검증은 source와 candidate를 각각 검사한다.
- array/enum/legacy/deprecated/unsigned/default(null 포함)/generation/ON UPDATE/nonempty index/check/FK/deferrability/특수 namespace/SQLite는 affected objectId+path 진단으로 차단한다. 첫 단위에서는 physical PK/UNIQUE도 key NULL/name/deferrability 조합의 추가 검증을 피하기 위해 차단한다. logical-only mandatory physical payload도 삭제·무시하지 않고 같은 mapping 제한을 적용한다.
- 원래 objectId/order/domain/logical/layout/customProperties/comments/nullability/명명은 유지한다. structured type/namespace/options와 DB context만 registry 범위 안에서 변환한다. MySQL comment 제한은 Banach의 실제 mysql-physical-policy helper를 소비한다. 아직 검증되지 않은 환경/문자 표현은 차단한다.
- engineVerified와 live usable을 분리한다. mapping candidate/source-map/changedPaths는 preview 준비 결과이며 신규 target write는 실제 `validateDatabaseDocument(...,{mode:'write'})` 및 catalog coverage로 판단한다. previous/candidate grandfathering, injected coverage/verified flag를 허용하지 않는다. coverage=false이면 candidate가 존재해도 service apply는 차단한다. 빈 물리 구경로, read preview 및 row lock→replay→새 manage/design 권한→재계산→원자 commit→WS notification은 유지한다.
- 실제 프로젝트+document/version/sequence/revision update, baseline reset, field version, source-map audit는 기존 transaction 경로를 확장한다. 서버 full shape/raw budget은 candidate도 검증한다. positive enabled conversion API는 gate activation 뒤 main이 실제 통합 재검증해야 하며 현재의 실제 empty apply/blocked integer apply와 구분하여 기록한다.
