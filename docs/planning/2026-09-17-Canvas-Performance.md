# 테이블 증가에 따른 성능 개선 제안

작성일: 2026-09-17
상태: 기존 탐색·배치 개선은 구현됨. 이 계획의 성능 기준 측정과 추가 최적화는 미착수이며 개선 효과는 아직 정량 검증하지 않았다.

검토 기준: 2026-09-17 로컬 `main`의 `4b0091b` 및 깨끗한 작업 트리. 원격 저장소를 새로 조회한 결과는 아니다. 이번 보완은 현재 코드와 기존 작업 기록을 대조해 구현 상태·측정 대상·선행 조건을 갱신한다. 아래 성능 목표 수치는 실측 결과가 아닌 검토용 목표다.

## 목표

테이블이 많아져도 카드 편집·이동·줌·사이드바 스크롤이 원활하도록 한다. 설계 데이터는 유지하면서 화면 표시와 계산 비용을 줄인다.

| 순서 | 개선 후보 | 목적 |

| 4 | 드래그·줌 입력을 프레임당 한 번 반영 | 고빈도 입력의 중복 갱신 감소 |

## 적용 원칙

- 화면에서 생략한 객체도 관계선 연결·자동 배치·검색·내보내기에 필요한 데이터는 유지한다.
- 화면 밖 카드와 연결된 선의 표시, 선택·편집·키보드 포커스가 유지되는지 확인한다.
- 배율별 표시 간소화는 데이터나 저장된 카드 크기를 변경하지 않는다.
- 계산 캐시는 관련 데이터가 변경되면 갱신하며, 동기화·실행 취소 후에도 일관성을 유지한다.
- 관계선의 `visibleNodeIds`는 현재 뷰의 의미상 표시 대상이다. 이를 화면 안에 마운트한 카드 ID로 대체하면 화면 밖 연결과 장애물이 누락되므로, 전체 뷰 노드와 DOM 표시 대상을 분리한다.
- PNG 내보내기는 전체 뷰의 카드·관계·이름을 포함하도록 별도 전체 렌더 또는 내보내기 중 표시 제한 해제 방식을 먼저 결정한다. JSON·DDL의 데이터 보존과 PNG의 시각적 보존을 각각 검증한다.

## 측정 및 진행 순서

테이블 50·100·300개와 서로 다른 컬럼 수·관계 밀도의 테스트 데이터를 준비한다. 관계선 계산 시간, 카드 갱신 횟수, 입력 처리 비용을 비교한다. 사용자 보고에 따라 브라우저 자동화는 사용하지 않고 계산 벤치마크와 계측 테스트부터 진행한다. 실제 프레임 속도와 체감 반응성은 별도 수동 프로파일링으로 확인한다.

반복 검색·불필요한 갱신 제거를 먼저 적용하고, 측정 결과에 따라 화면 밖 카드 생략·배율별 간소화·목록 가상화를 진행한다. 구체적인 성능 목표와 간소화 배율 기준은 측정 후 결정한다.

## 기준 측정 설계

### 데이터와 환경

- 테이블 수 50·100·300개 각각에 컬럼 수 10·30개, 관계 수 테이블당 평균 1·3개를 조합한 12개 고정 데이터셋을 준비한다. 컬럼 수는 테이블당 개수, 관계 수는 전체 관계 수를 테이블 수로 나눈 값이다.
- 데이터 생성 시드, 테이블 배치, 관계 연결, 카드 크기를 고정하고 데이터셋 식별자를 기록한다. 동일한 데이터로 변경 전후를 비교한다.
- 전체 구조를 보는 배율과 일부 카드만 보이는 배율을 각각 측정한다. 실제 배율·뷰포트 크기·화면 내 카드 수를 기록한다.
- 현재 지원하는 10%·100% 배율을 화면 측정의 시작 조건으로 삼는다. 이는 간소화 전환 기준이 아니다. 단일 도메인과 여러 도메인을 포함한 도메인 뷰를 구분하고 도메인 맵의 관계 이름 배치도 별도 시나리오로 측정한다.
- 기준 커밋, OS, CPU·메모리, 브라우저·런타임 버전, 빌드 모드, 계측 방법을 기록한다. 시간 비교에는 같은 장비와 빌드 모드를 사용하고 수동 화면 측정은 production 빌드를 기준으로 한다.
- 계산 벤치마크는 동일 시나리오를 5회 준비 실행 후 30회 측정하는 것을 시작 기준으로 삼는다. 초기 실행 비용은 별도로 기록하며, 캐시가 있는 반복 실행과 섞지 않는다. 노이즈가 크면 반복 수를 늘리고 변경 전후 모두 같은 절차로 재측정한다.

| 시나리오 | 고정할 동작 | 기록할 지표 |
| --- | --- | --- |

| 단일 컬럼 편집 | 같은 카드의 이름 또는 타입 변경 | 관련 계산 시간, 카드별 렌더 횟수, 관계 경로 재계산 수 |

| 팬·줌 | 동일 시작 위치와 배율에서 같은 입력 적용 | 프레임당 상태 반영 수, 표시 카드·DOM 수, 입력 처리 시간 |

우선 계측 범위는 `tableCardMetrics`/`tableCardSize`, 테이블 관계 입력 자료 준비와 `relationGeometry`, `layoutDomainRelations`, 도메인 뷰 묶음 배치다. 렌더 함수에 섞인 입력 자료 준비는 동작을 유지하는 최소 추출 후 측정한다. 단일 경로 함수만 측정하고 실제 반복 검색 비용을 제외하지 않는다. 도메인 시나리오는 12개 테이블 데이터셋과 별도로 도메인 수·선택 수·이름 길이를 기록한 고정 fixture를 준비한다.

계산 시간은 중앙값과 p95, 반복 횟수를 함께 기록한다. p95는 측정값을 정렬한 뒤 `ceil(0.95 × 표본 수)`번째 값을 사용한다. 계산 계측으로 확인할 수 없는 DOM 수·렌더 횟수·실제 프레임 간격은 별도 화면 계측 또는 수동 프로파일링 항목으로 구분하고, 확인하지 못한 항목은 미측정으로 남긴다. 계산 벤치마크 결과만으로 화면 반응성 개선을 주장하지 않는다.

## 개선 성공 기준

아래 수치 기준은 기준 측정 이후 확정할 잠정 목표다. 목표를 변경하면 구현 전에 근거와 적용 시나리오를 이 문서에 기록한다.

| 구분 | 잠정 목표 또는 필수 조건 |
| --- | --- |
| 주요 병목 | 기준 측정으로 선정한 병목 시나리오에서 대상 계산의 p95를 20% 이상 줄인다. 전체 동작 시간도 함께 기록한다. |
| 다른 시나리오 | 동일 조건에서 시간 지표의 p95가 10% 넘게 악화되면 재측정한다. 반복해서 악화되면 원인을 해결하거나 적용 범위를 축소한다. |
| 부분 갱신 | 단일 카드 편집에서 관련 없는 카드의 추가 렌더와 불필요한 관계 경로 재계산을 제거한다. 테이블 크기나 장애물 배치 변화로 영향을 받는 관계는 재계산 대상에 포함한다. |
| 입력 병합 | 각 입력 처리 경로의 고빈도 이동·줌 상태 반영은 프레임당 최대 1회로 병합한다. 입력 종료 시 마지막 위치·배율은 반드시 반영한다. |
| 화면 밖 카드 생략 | 같은 뷰포트에서 전체 테이블 수가 늘어도 마운트 카드 수는 가시 영역·여유 영역·편집 유지 대상에 의해 제한된다. 절감 전후 DOM 수를 기록한다. |
| 수동 반응성 | 60Hz 환경의 팬·줌·이동에서 프레임 간격 p95 16.7ms 이하를 초기 목표로 검토한다. 실제 주사율, 측정 구간, 지연 프레임 비율을 함께 기록한다. 미달 시 계산 개선과 화면 목표 달성을 별도로 보고한다. |
| 정확성 | 검색·선택·편집·포커스·관계선·자동 배치·내보내기·동기화·실행 취소에서 기존 동작을 유지한다. 성능 목표를 만족하더라도 정확성 회귀가 있으면 완료로 판단하지 않는다. |

기준 시간이 측정 노이즈와 비슷한 짧은 작업은 개선율만으로 판단하지 않는다. 절대 시간과 반복 측정 편차, 계산·렌더 횟수를 함께 사용한다.

## 단계별 진행 및 완료 조건

각 구현 단계는 작은 독립 커밋으로 나누고, 기준 커밋과 해당 변경의 측정 결과를 work-log에 남긴다. 아래 단계 0~4는 성능 계획으로서 미착수다. 이미 구현된 탐색·배치·기능 테스트 자산은 기준선과 회귀 검증에 재사용한다.

| 단계 | 수행 내용 | 완료 조건 |
| --- | --- | --- |
| 0. 기준 측정 | 고정 데이터와 계산 계측을 준비하고 수동 화면 측정 범위를 정한다. | 12개 데이터셋의 계산 기준값, 재현 절차, 미측정 항목을 기록하고 우선 해결할 병목과 성공 기준을 확정한다. |
| 1. 조회·부분 갱신 | 기존 Map을 재사용하고 테이블별 컬럼·키, 뷰별 노드, 관계 쌍, 카드 치수와 캐시 의존성을 정리한다. | 대상 병목의 전후 수치와 갱신 횟수를 비교하고 동기화·실행 취소 후 캐시 일관성을 확인한다. |
| 2. 입력 병합 | 측정에서 고빈도 입력 비용이 확인되면 프레임 단위 반영을 적용한다. | 입력 폭주·종료·취소 시 마지막 상태와 저장 결과를 확인하고 반영 횟수 및 수동 반응성을 기록한다. |
| 3. 화면 표시 제한 | 먼저 전체 뷰 노드와 DOM 표시 대상을 분리하고 전체 상세 PNG 내보내기를 보존한다. 이후 화면 밖 카드 생략, 낮은 배율 표시 간소화, 사이드바 가상화를 각각 검토한다. | 각 기법을 별도로 측정하고 DOM·렌더 비용 절감, 화면 밖 연결·장애물·PNG 보존과 아래 회귀 확인을 완료한다. 필요하지 않은 기법은 보류 사유를 기록한다. |
| 4. 종합 확인 | 같은 데이터·환경에서 적용한 변경들을 함께 재측정한다. | 성공 기준 충족 여부, 수동 확인 결과, 남은 병목·제약을 기록한다. 수동 검증이 남아 있으면 화면 성능 검증 미완료로 표시한다. |

후보 목록의 순서는 초기 검토 우선순위다. 실제 적용 순서는 기준 측정 결과로 결정하며, 모든 기법을 적용하는 것을 목표로 삼지 않는다.

## 회귀 확인 항목

- 화면 밖 카드와 연결되는 관계선, 화면을 가로지르는 관계선, 이동한 카드 때문에 경로가 바뀌는 관계선을 확인한다.
- 편집 중인 카드가 화면 밖으로 이동해도 입력과 키보드 포커스가 유실되지 않도록 유지 정책을 정한다. 검색 결과로 이동한 카드와 선택된 객체의 표시도 확인한다.
- 낮은 배율의 간소화 경계와 화면 가장자리에서 표시가 반복 전환되거나 카드가 깜빡이지 않는지 수동 확인한다. 전환 배율과 여유 영역은 측정 후 확정한다.
- 가상화된 사이드바에서 검색·선택·키보드 이동으로 화면 밖 항목에 접근할 수 있는지 확인한다.
- 표시 생략·간소화 전후로 카드 크기, 원본 데이터, 내보내기 결과가 바뀌지 않는지 확인한다.
- 원격 동기화, 삭제·복원, 실행 취소·다시 실행 후 오래된 캐시나 관계선이 남지 않는지 확인한다.
- 최근 추가된 도메인 묶음 간격·내부 상대거리·overview 위치 누락 시 대체 배치, 관계 이름 비중첩·순서 독립성과 이동된 이름의 PNG 포함을 유지한다.
- 컬럼 타입·기본값 변경과 자동 증가 선택의 연동을 유지한다. 카드 치수 캐시는 컬럼 이름·타입·설명, enum 표시, 테이블 표시 옵션·저장 크기의 변경도 반영해야 한다.
