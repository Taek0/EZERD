# 관계선 자동 정렬 구현 계획

상태: 사용자가 구현 착수를 승인함. 2026-10-15부터 격리 워크트리에서 단계별 구현·검증을 진행한다.
기준: performance-lab에 반영된 main 2efbbd5 및 [코드 조사 결과](../work-log/2026-10-15-Relations-AutoArrangeInvestigation.md).

## 1. 목표와 적용 범위

- 테이블 배치는 주로 사용자가 MCP를 통해 계층 관계에 맞춰 위→아래로 구성한다. 자동 정렬은 테이블·메모 위치와 관계 의미를 변경하지 않고 관계선만 정리한다.
- 복잡한 전체 최적화는 사용자가 관계선 자동 정렬을 명시적으로 실행할 때만 수행한다. 이동, 줌, ACK, 재렌더링, 서버 충돌에서 전체 최적화를 자동 재실행하지 않는다.
- 전체 테이블 화면이며 도메인 필터가 해제된 상태에서만 실행한다. 도메인 화면에서는 비활성화한다. viewport 밖 객체도 계산에 포함한다.
- 현재 논리/물리 모드의 관계선 전체를 대상으로 하며 수동 경로도 교체한다. 현재 모드에서 표시되지 않는 관계는 삭제하거나 경로를 덮어쓰지 않는다. 모드 간 경로가 공유된다는 기존 저장 의미를 유지한다.
- 사용자 용어: PK 쪽이 출발, FK 쪽이 도착. 내부 sourceTableId/sourceAnchor는 FK, targetTableId/targetAnchor는 피참조 PK/UNIQUE이다. 내부 식별자·관계 의미를 뒤집지 않고 UI와 DTO 경계에서 명확히 대응한다.
- 기존 도메인·전체 테이블 화면은 __tables__ 경로를 공유하므로 전체 화면에서 정렬한 결과가 도메인 화면에도 보일 수 있다.

## 2. 배치 규칙

1. 관계 의미와 양 끝 테이블을 보존하고 테이블 내부 침범을 방지한다.
2. 실제 상대 위치와 주변 공간을 기준으로 네 면의 연결점을 선택한다. 위→아래 배치에서 상하 연결을 우선 후보로 삼되 강제하지 않는다.
3. 컬럼 행 위치에 연결점을 고정하지 않는다. 같은 면의 연결점은 모서리 여백 안에서 균등 배치한다.
4. 연결이 많으면 간격을 줄이고, 면의 공간이 부족하면 다른 면으로 분산한다. 모든 카드에 동일한 절대 간격을 강제하지 않는다.
5. 상대 테이블 위치를 기준으로 연결점 순서를 정해 카드 근처 교차를 줄인다. 출발/도착 역할 때문에 특정 면을 강제하지 않는다.
6. 선 중첩과 평행 구간의 간격 위반, 교차, 꺾임, 과도한 우회를 줄인다. 이들을 모두 동시에 완전히 제거할 수 있다고 보장하지 않는다.
7. 카드 직후 일정 길이의 직선 구간을 강제하지 않는다. 다만 관계 기호의 표시 공간과 직교 연결의 유효성은 유지한다.
8. 혼잡 구간은 유효한 최선 경로를 선택한다. 품질을 위해 테이블을 임의로 이동하지 않는다. 유효한 경로를 만들지 못한 경우 결과 전체를 적용하지 않고 기존 배치를 보존한다.
9. 동일 입력의 결과가 결정적이고 재실행 시 불필요하게 흔들리지 않도록 안정적 정렬과 탐색 순서를 사용한다.

## 3. 계산 및 중복 작업 최소화

- Web Worker에서 계산한다. 기존 model의 순수 기하·장애물 판정·경로 단순화·탐색을 재사용하되, React 컴포넌트를 Worker로 import하지 않는다.
- 준비 단계에서 카드 크기·월드 좌표·메모 경계·관계·라벨/기호에 필요한 정보를 한 번 계산해 직렬화 DTO로 전달한다.
- 카드별 연결 목록과 장애물 검색 구조를 한 번 생성하고 공유한다. 연결 면/순서/간격 배정 후 경로를 생성한다.
- 첫 전체 해 이후에는 중첩·간격 문제가 있는 선만 제한적으로 재탐색한다. 시간/탐색 횟수 상한과 최선의 유효 결과를 유지한다.
- 장기 캐시는 최초 버전 필수 범위에서 제외한다. 실행 내부 재사용부터 측정하고 필요할 때 동일 입력 캐시를 검토한다.
- Worker 프로토콜은 jobId, 입력 기준 정보, 단계별 progress, result, error를 갖는다. 취소는 Worker 종료 또는 협력적 분할 계산으로 즉시 처리 가능해야 한다. 동기 계산 중 취소 메시지만 보내는 방식에 의존하지 않는다.
- 중간 경로는 화면에 적용하지 않는다. 완료 결과를 한 번에 로컬 반영한다. 큰 결과의 복사·검증·저장·React 갱신도 별도 측정한다.
- 동시에 하나의 정렬 작업만 실행한다. 중복 실행을 차단하고 unmount/프로젝트 전환 시 Worker를 정리한다.

## 4. 계산 중 편집 처리

| 변경 | 처리 |
| --- | --- |
| 테이블·메모 이동 | 즉시 로컬 문서와 화면에 반영한다. Worker는 시작 시점 입력으로 계속 계산한다. 객체별 최종 위치만 추적한다. |
| 완료 시 이동 누적 | 최신 좌표에서 기존 경로 처리로 한 번 보정한다. 이동 이벤트를 순서대로 재실행하거나 전체 최적화를 반복하지 않는다. |
| 카드 크기 변경 | 작업 취소, 기존 경로 유지, 재실행 안내. |
| 테이블·관계 추가/삭제, 연결 컬럼 변경 | 작업 취소, 기존 경로 유지. 오래된 결과를 먼저 적용한 뒤 구조 변경을 재생하지 않는다. |
| 직접 관계선 편집 | 계산 중 비활성화한다. |
| 모드·필터·화면 전환 버튼 | 계산 중 비활성화한다. 실제 화면 이탈은 취소 처리한다. |
| 원격 변경 | 같은 분류를 적용하고 결과 반영 직전에도 기준 정보를 비교한다. |

- 카메라 이동과 줌은 허용하며 결과 무효화 조건이 아니다.
- 단순 문서 버전 변화와 배치 입력 변화는 구분한다. 이름 변경도 카드 크기/라벨 폭을 바꾸면 무관한 변경으로 간주하지 않는다.
- 이동 후 원래 최적 품질이 일부 감소할 수 있다. 자동 재최적화 없이 사용자가 필요할 때 다시 실행한다.
- 결과 완료와 새 편집의 경쟁을 막기 위해 현재 상태 검증과 로컬 결과 등록 사이에 원자적인 적용 경계를 둔다.

## 5. 메뉴와 진행 안내

- 캔버스 우클릭의 자동배치를 호버/클릭하면 테이블 배치·관계선 배치 두 행을 연다. 기존 항목과 동일한 크기/스타일을 재사용하고 오른쪽 공간 부족 시 반대쪽으로 연다.
- 기존 테이블 배치 액션은 유지한다. 하위 메뉴의 방향키·Escape·포커스 복원·바깥 클릭 처리를 추가한다.
- 모든 안내는 우측 하단 손/커서·배율 박스 왼쪽에 겹쳐 표시한다. 배율 박스와 비슷한 높이를 기본으로 하고 문장 길이에 따라 너비 또는 두 줄을 허용한다. 캔버스 레이아웃을 밀지 않는다.
- 계산 중에는 progress 커서와 스피너, 관계선 정리 중…, 취소를 표시한다. 짧은 작업의 깜빡임을 막도록 지연 표시하되 계산 안내는 종료까지 유지한다. 나머지는 잠시 표시 후 사라진다.
- 완료: 관계선을 정리했어요 + 실행 취소. 구조 변경: 연결 구조가 변경되어 정리를 중단했어요. 공간 부족: 주문 외 2개 테이블 주변 공간이 부족해요 등의 문구를 사용한다.
- 공간 부족은 확인된 혼잡 근거가 있을 때만 표시한다. 탐색 상한 도달을 공간 부족으로 단정하지 않는다. 미해결 구간 수는 표시하지 않는다.
- 알림은 한 위치에서 교체/우선순위 처리해 쌓이지 않게 한다. 상태 알림은 접근성 live region으로 전달한다. 표시 시간/애니메이션 세부 수치는 구현 시 기존 스타일과 검증 결과로 정한다.
- 계산 완료와 서버 저장 완료를 구분한다. 저장은 기존 상태 UI와 연결하고 ACK 때문에 편집 재개를 대기시키지 않는다. 계산 중 제한은 로컬 적용 완료 시 해제한다.

## 6. 100개 초과 관계선의 일괄 저장

- 제안 명령명: batch_upsert_relation_layouts. 하나의 viewId와 변경된 routes 배열을 전달한다. 명칭은 구현 시 확정한다.
- 기존 요청당 100개 명령 제한은 유지한다. 전용 명령 내부에 관계선 수·총 경유점 수·요청 바이트 상한을 별도로 둔다. 수치는 대표/대규모 문서 측정 후 확정한다.
- 관계별 100개씩 단순 분할 전송하지 않는다. 한 트랜잭션에서 전체 적용하고 한 operation/history 단위로 기록한다.
- 기존 anchor/waypoints 저장 형식과 검증을 재사용한다. 서버는 권한·문서 버전·관계 존재 여부·중복 ID·좌표·용량을 검증하고 최적화 알고리즘은 실행하지 않는다.
- 로컬에서도 문서 복제/상태 통지를 관계선마다 반복하지 않고 한번에 적용한다. 변경 없는 경로는 전송하지 않는다.
- 상한 초과 시 최초 버전에서는 부분 적용 없이 안내한다. 임시 업로드 후 최종 확정 프로토콜은 후속 확장으로 남긴다.
- 기존 groupId만 같게 주는 것으로 여러 요청의 원자성/단일 undo를 가정하지 않는다.

## 7. 로컬 표시와 작업 상태

- 서버 확인 문서 위에 해당 작업의 관계선 결과를 임시 적용하는 계층을 둔다. 작업 ID, 계산 기준, 변경 전/후 경로, 전송 상태를 보존한다.
- 준비 → 계산 → 최신 상태 보정/검증 → 로컬 기록·표시 → 서버 저장 대기 → 확정 순서다. 계산 취소/입력 무효화/저장 충돌/통신 미확정 상태를 구분한다.
- 기존 native-save-intents 및 durable queue/ACK 처리를 재사용한다. relation layout 로컬 projection 지원과 로컬 접수/서버 확정 신호 분리는 추가한다.
- ACK 도착 시 이미 보이는 동일 경로를 불필요하게 다시 생성하지 않고 임시 계층을 확정 문서로 넘긴다.
- 저장 실패 처리에서 계산 전 문서 전체를 복원하지 않는다. 해당 작업 결과만 제거하고 사용자 이동 및 다른 편집을 보존한다.

## 8. 서버 충돌 및 재시도

| 분류 | 처리 |
| --- | --- |
| 배치 입력과 무관한 변경 | 최신 버전에 맞춰 저장 재시도. |
| 테이블·메모 이동 | 최신 위치에서 기존 경로 처리로 보정 후 재시도. 전체 최적화 재실행 금지. |
| 카드 크기·연결 구조 변경 | 작업 결과 적용 중단. 최신 문서 보존, 재실행 안내. |
| 다른 사용자의 관계선 수정 | 정렬 결과 적용 중단, 상대방 최신 경로 보존. |
| 권한 상실·문서 삭제 | 저장 중단과 상태 안내. |
| 응답 유실·일시 통신 장애 | 저장 여부 확인 후 동일 요청 재전송. 명시적 충돌과 구분. |

- 서버의 문서 버전 불일치만으로 무조건 폐기하지 않는다. 시작/요청 기준과 최신 상태의 배치 관련 입력을 비교한다.
- 충돌에 대한 자동 보정·재시도는 1회까지다. 다시 충돌하면 중단하고 다시 정리를 안내한다. 통신 미확정 요청의 동일 ID 재전송은 이 보정 횟수와 구분한다.
- 응답 유실은 같은 operationId와 동일 payload로 확인/재전송해 중복 적용을 방지한다. 명시적 거절 후 내용을 보정한 요청은 새 operationId를 사용한다. 원래 요청이 미확정이면 새 ID로 보내지 않는다.
- 실패 시 해당 정렬 작업의 임시 결과만 제거한다. 더 나중의 사용자 관계선 편집이나 다른 로컬 작업을 덮어쓰지 않는다. 안전한 재적용이 불가능한 후속 작업은 보류하고 명시적으로 안내한다.
- 재시도 중 최신 변경사항을 반영해 저장 중…, 구조 충돌 시 연결 구조가 변경되어 정리를 적용하지 못했어요, 원격 경로 변경 시 관계선이 수정되어 최신 배치를 유지했어요를 표시한다.
- 네트워크 미확정 상태에서는 연결되면 정리 결과를 저장할게요를 표시하고 기존 durable 복구 정책을 이용한다.

## 9. 실행 취소

- 자동 정리로 변경된 관계선만 복원한다. 작업 중/이후의 테이블·메모 이동은 복원하지 않는다.
- 서버 확정 전은 임시 작업 취소, 확정 후는 해당 저장 operation의 관계선 변경 되돌리기로 구분한다.
- 전송 중 취소는 화면에서 지우는 것으로 완료 처리하지 않는다. 기존 취소/작업 조회 프로토콜로 서버 반영 여부를 확인하고 필요 시 관계선 복원 작업을 수행한다.
- 이후 다른 편집이 변경한 경로를 무조건 덮어쓰지 않는다. 경로별 변경 전후와 현재 상태를 검사하고 충돌은 안내한다.

## 10. 구현 단계 및 완료 조건

각 단계는 별도 작업·커밋으로 수행한다. 알고리즘·저장·Worker/충돌 처리와 UI는 소유 파일을 구분해 병렬 구현하고 통합 검증한다.

1. 계약과 상태 설계: 입력 DTO, 입력 변경 분류, 대량 명령 한도, 로컬/서버 완료 신호, 단일 undo와 취소 정의. 현재 필터 없음 판정 및 모드별 대상 명세 확정.
2. 순수 알고리즘: 공통 geometry 입력/장애물 재사용, 포트 배정, 경로/통로 분리, 제한 탐색과 결과 검증. 제품 UI에 연결하기 전 fixture 품질 확인.
3. 일괄 저장: contracts/model/server 적용기, 원자성·권한·중복 작업 방지, 로컬 projection, 히스토리와 충돌 복구. 새 저장 컬럼 필요 여부 재검증.
4. Worker 통합: 취소·진행·오래된 결과 차단, 이동 누적 최종 상태 보정, 화면 수명 관리.
5. UI 통합: 두 행 하위 메뉴, 비활성 조건, 작업 안내, 컬럼 강조, 완료·공간 부족·충돌 안내, 실행 취소.
6. 실제 문서 검증: 전체 제품 검사와 기능별 브라우저 검증, 성능 계측. 기존 이동/줌 성능 회귀가 없어야 한다.

## 11. 검증 계획

- 알고리즘: 네 면 연결점 균등 간격/혼잡 분산, 자기참조·복합 FK·다중 관계·긴 계층 건너뛰기, 메모 장애물, 결정성·재실행 안정성, 유효하지 않은 결과 적용 금지.
- 품질 지표: 선 중첩 길이, 교차 수, 간격 위반, 꺾임/우회율. 모든 지표가 동시에 최적이라는 기준을 요구하지 않는다.
- 수명/변경: 이동 중 완료, 완료 직전 구조 변경, 카드 크기 변경, 원격 편집, 화면 이탈, 취소 직후 늦게 도착한 결과.
- 저장: 100개 초과, 중복 ID/용량 상한, 전체 성공 또는 전체 실패, 동일 작업 재전송, ACK 유실·중복 ACK, 충돌 보정 1회, 권한 변경, 관계선만 undo, 전송 중 취소, 후속 편집 보존.
- UI: 필터/도메인 화면 비활성, 키보드 하위 메뉴, 계산 중 줌/팬, 접근성 알림, 알림 중첩·깜빡임 방지, 저장 중 편집 재개.
- 성능: 입력 준비, Worker 계산, 메시지 복사, 로컬 기록/적용, 프레임 정지, 서버 검증/저장/ACK 각각 측정. 100개 초과를 포함한 실제 규모별 fixture로 회귀 비교.
- 성능 예산, 포트 최소 여백, 탐색 상한, 대량 요청 상한은 미측정 수치를 확정값으로 제시하지 않고 측정 후 정한다.
