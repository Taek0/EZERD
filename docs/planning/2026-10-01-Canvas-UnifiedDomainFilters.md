# 전체 테이블 캔버스와 개인 도메인 필터 통합 계획

## 채택한 정책

- 프로젝트는 전체 테이블 캔버스를 기본 화면으로 연다. 도메인 테이블 화면과 기존 도메인 뷰의 진입 UI를 도메인 필터로 통합한다.
- 필터는 현재 사용자의 화면에만 적용한다. 다른 협업자의 필터·확대·화면 위치를 강제로 변경하지 않는다.
- 테이블 위치·크기·이름·색상·컬럼·관계·메모·관계선은 하나의 공유 전체 캔버스 상태를 편집한다. 필터 전환으로 배치나 객체 ID를 바꾸지 않는다.
- 도메인 맵은 별도 업무 흐름 화면으로 유지한다. 도메인을 열면 전체 캔버스에 해당 도메인 필터를 적용한다.
- 한 도메인 필터에서 생성하면 자동 소속시킨다. 전체 또는 여러 도메인 필터에서는 미지정 생성이 기본이다.
- 필터에 표시된 양쪽 테이블의 관계만 표시한다. 미소속 테이블도 선택해서 볼 수 있다.
- 웹에서 개인 도메인 뷰를 새로 만들거나 개인 배치·메모·관계선 수정 경로로 연결하지 않는다. 기존 개인 기록은 호환용으로 보존하며 운영 DB의 여러 사용자 개인 데이터를 일괄 공유로 이관하지 않는다.
- 기존 도메인 ID와 함께 보기 ID를 사용하는 링크·핀·조회는 새 전체 캔버스의 필터로 연결한다. 공유 도메인 화면의 기존 메모·관계선은 전체 캔버스에서 이어 사용할 수 있는 정규화 규칙을 마련한다.

## 구현 단위

1. 웹 캔버스와 도메인 필터·공유 권한·로컬 필터 회귀 테스트.
2. 모델의 공유 뷰 정규화와 서버/MCP·레거시 핀·조회 호환.
3. 복사/붙여넣기·테이블 생성과 제목 개선 통합, 실제 브라우저·API·포맷·타입·테스트·빌드 검증.

서로 다른 소유 파일의 웹 및 서버 작업은 사용자가 허용한 `gpt-6.1-sol` high 서브에이전트로 진행한다. 주 작업은 모델·통합·검증과 작업 단위별 커밋을 담당한다.

## 구현 상태

채택한 정책으로 구현하고 두 캔버스의 독립 필터·공유 편집, 실제 DB/API와 전체 검사를 완료했다. 상세 내용은 [완료 기록](../work-log/2026-10-01-Canvas-UnifiedFiltersCompletion.md)을 참조한다.
