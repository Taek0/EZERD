# 캔버스 이동 부드러움 비교 계획

## 목표와 제약

2026-10-02. 기존 편집기의 시각적 품질과 편리한 조작을 Native 캔버스에 재도입하되 화면 이동의 부드러움을 유지한다. UI 삭제를 최종 해결책으로 삼지 않는다. React가 주원인이라는 가설을 검증하며 미리 결론 내리지 않는다.

## 측정

- 최신 main을 반영한 격리 lab에서만 실행한다. 운영 API/DB/사용자 문서는 사용하지 않는다.
- 동일한 결정적 v1 fixture와 이를 v2로 무손실 변환한 fixture를 사용한다. 테이블·컬럼·관계·배치, 화면 크기와 배율을 맞춘다. 실제 카드 내부 표시 차이는 기록한다.
- production profiling React 빌드의 Profiler로 subtree render duration/commit 수를 기록한다. 함수 span은 포함 시간이며 합산하지 않는다.
- rAF 간격, Long Animation Frame/longtask를 수집한다. LoAF는 50ms 초과 프레임만 포착하며 paint/GPU 전용 시간을 제공하지 않으므로 잔여 시간을 paint로 단정하지 않는다.
- 동일한 프레임 간격의 휠 이벤트 재생은 synthetic paced replay로 명시한다. 브라우저 실제 휠 입력도 별도 검증한다.
- 기존 baseline/Native baseline을 먼저 비교한 뒤 기존 카드 상세 제거, 관계선 제거, 시각 효과 제거, leaf React 재사용을 각각 독립 조건으로 비교한다. 모든 조건을 조합해서 원인을 섞지 않는다.
- DOM 노드 수, transform 변화, 문서 불변, frame/React 표본 유효성을 확인한다. 설정 변경은 remount 후 warm-up하며 측정 중 harness React 상태를 갱신하지 않는다.

## 후속 판단

카드/관계선 leaf 재렌더를 막은 상태에서도 외형을 유지하며 개선되면 UI 보존형 최적화를 우선한다. 효과 제거에서만 개선되면 paint/합성을 후속 추적한다. baseline 1회 준비 실행 후 최소 3회 반복하고 중앙값을 비교한다. 시간 예산에 따라 50테이블을 먼저 측정하고 필요시 100테이블로 확장한다.

진단용 leaf 캐시는 읽기 전용 pan 비교에만 사용하며 콜백 동일성 무시를 제품 구현으로 반영하지 않는다. 제품 최적화는 독립적인 입력·편집·선택 회귀 검증 이후 별도 커밋한다. 운영 앱 전체, 실시간 협업, 저장, 접근성 동등성은 이 측정만으로 보증하지 않는다.
