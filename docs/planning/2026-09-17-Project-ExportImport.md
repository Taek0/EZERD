# 프로젝트 내보내기·가져오기 제안

작성일: 2026-09-17
상태: 문서화만 진행. 기능·API·파일 형식은 아직 구현하지 않았으며 아래 내용은 제안이다.

## 목적

프로젝트 설계 데이터를 파일 하나로 백업하거나 다른 EZERD 환경으로 옮긴다. 이미지 내보내기나 DB 생성용 DDL과 달리, 가져온 후 다시 편집할 수 있는 설계 데이터 보존을 목표로 한다.

## 제안 범위

UTF-8 JSON 파일에 프로젝트 이름과 설계 문서를 담는다.

- 도메인, 테이블, 컬럼, 프로젝트 ENUM.
- PK·복합 UNIQUE·FK, 컬럼 대응 및 ON UPDATE/ON DELETE 등 관계 설정.
- 도메인 관계, 메모와 설명.
- 카드 위치·크기·색상, NULL/comment 표시 설정, 관계선 배치.
- 프로젝트 문서에 저장된 도메인 뷰와 참조 구성.
- 내보내기 파일 형식 버전 및 설계 문서 스키마 버전.

개인 도메인 뷰·카메라·개인 관계 경로처럼 브라우저나 현재 세션에만 있는 상태는 서버 설계 문서와 구분해야 한다. 이를 자동으로 포함한다고 약속하지 않으며, 저장된 프로젝트 뷰와 개인 뷰의 포함 경계는 구현 전에 확정한다.

## 제외 제안

- 사용자 계정, PIN 및 PIN 해시, 세션 토큰 등 인증 정보.
- 동기화 대기열, 클라이언트 기준 문서, 내부 동기화 순번.
- 핀 대화·멘션·알림·변경 히스토리: 사용자 참조 및 복원 의미가 연결되므로 첫 설계 데이터 이동 범위에서는 제외하고 별도 검토한다.

따라서 이 기능은 프로젝트 **설계 데이터**의 이동·백업이며 서비스 DB 전체 백업을 대체하지 않는다.

## 사용 흐름 제안

### 내보내기

1. 갤러리의 프로젝트 메뉴에서 내보내기를 선택한다.
2. 내보낼 설계 문서와 프로젝트 이름을 하나의 일관된 스냅샷으로 확보한다.
3. 파일 형식 버전과 내보낸 시각을 포함한 JSON 파일을 다운로드한다.

기본안은 서버에 반영된 최신 문서를 내보내는 것이다. 동기화 중이거나 오프라인 편집이 남은 경우의 대기·안내·로컬 사본 지원은 미정이다. 저장되지 않은 내용을 포함한 것처럼 표시하지 않아야 한다.

### 가져오기

1. 갤러리에서 JSON 파일을 선택한다.
2. 파일 형식·버전·설계 구조·객체 간 참조를 검증하고 프로젝트 이름과 객체 수를 보여준다.
3. 새 프로젝트로 생성한다. 기존 프로젝트를 덮어쓰거나 병합하지 않는 방식을 권장한다.
4. 생성에 성공하면 갤러리에 추가하고 편집 화면으로 이동할 수 있게 한다.

검증 실패 시 새 프로젝트나 부분 데이터가 남지 않도록 원자적으로 처리한다. 가져온 프로젝트는 새 프로젝트 ID와 새 동기화 기준을 사용한다. 문서 내부 객체 ID의 유지 또는 일괄 재발급 정책은 실제 식별자 범위를 확인한 뒤 결정하며, 어떤 방식이든 모든 내부 참조를 일관되게 보존해야 한다.

## 파일 구조 초안

| 필드 | 용도 |
| --- | --- |
| `format` | EZERD 프로젝트 파일임을 식별 |
| `formatVersion` | 내보내기 파일 형식 버전 |
| `exportedAt` | 내보내기 시각 |
| `project.name` | 새 프로젝트 이름의 기본값 |
| `document` | 문서 스키마 버전을 포함한 설계 데이터 |

필드명·확장자·파일명 규칙은 최종 규격이 아니다. 사용자명과 기존 프로젝트 ID, 서버 운영 메타데이터는 필수 백업 항목으로 취급하지 않는다.

## 검증 및 수용 기준 제안

- JSON 파싱, 지원 파일 버전, 파일 크기 및 객체 수 제한을 검사한다.
- 기존 공통 계약과 모델 검증을 재사용해 누락 참조·잘못된 키/관계·비정상 좌표 등을 거부한다.
- 지원하지 않는 미래 버전은 명확한 오류를 표시하며 임의로 누락 필드를 버리지 않는다.
- 내보내기 → 가져오기 후 설계 내용·배치·메모·ENUM·관계 설정이 동등하다.
- 같은 파일을 반복해서 가져와도 기존 프로젝트는 변하지 않는다.
- 작성 중 실패하면 일부 프로젝트만 생성되는 상황이 없다.
- 가져온 프로젝트에서 편집·자동 저장·협업이 새 프로젝트 기준으로 동작한다.
- 파일에 인증 정보나 사용자 개인정보가 포함되지 않는다.

## 구현 전에 확정할 사항

1. 개인 도메인 뷰와 개인 관계 경로의 포함 여부.
2. 핀 대화와 히스토리를 향후 별도 백업 범위로 지원할지 여부.
3. 동기화 중·오프라인 상태에서 내보낼 스냅샷의 기준.
4. 프로젝트명 중복·보관 상태 처리와 문서 내부 ID 정책.
5. 파일 크기 제한, 확장자, 버전 호환 및 마이그레이션 규칙.

사용자의 현재 요청은 이 제안을 문서로 남기는 데 한정한다. 구현이나 DB 변경, 실제 데이터 내보내기·가져오기는 진행하지 않는다.
