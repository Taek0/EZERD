# 기존 캔버스 전체 UI와 동작 복구 계획

## 요청과 기준

- 사용자가 기존 코드 전체를 확인하고 현재 Native 버전에서도 시각 효과와 세부 요소를 완전하게 복구하도록 지시했다.
- 기준은 현재 main의 기존 Canvas.tsx와 연결된 TableEditor, domain/relations, 공통 UI, shared/editor, 스타일, App 편집 shell이다. 원격 PR #2의 부분 복원을 출발점으로 삼는다.
- 기존 UI와 상호작용을 유지한다. DB별 Native 모델, capability, 서버 검증, durable 저장/ACK와 개인 상태 격리는 보존한다. Native 문서를 v1 물리 타입으로 축소하지 않는다.

## 작업 단위

1. 기존 렌더/스타일/이벤트/메뉴/키보드/패널을 대조해 항목별 차이를 기록한다.
2. 카드·행·도메인·메모·관계선·empty state·툴팁과 모션을 기존 표현과 공통 컴포넌트에 맞춘다.
3. 속성/목록·생성/제약조건·필터·이력·공유/리뷰 등 패널과 shell의 세부 요소를 복구한다.
4. 선택/다중 선택·그룹 이동·우클릭·복사/붙여넣기·삭제·연결·레이아웃·보기·단축키를 실제 Native 명령과 저장 경로에 연결한다.
5. 의미 있는 회귀, 전체 format/type/test/build, 격리 환경 저장 검증과 브라우저 상호작용/모션/접근성/reduced motion을 확인한다.

## 진행 방식

- 이미 허용된 내부 병렬 작업을 파일 범위별로 나눈다. 부모는 캔버스 조작과 통합/최종 검증을 담당한다.
- 작은 논리 단위마다 결과 문서와 독립 커밋을 남기고 전체 요청 완료까지 같은 턴에서 이어간다.
- 기존 데이터와 다른 변경을 보존한다. docs/EZERD.txt는 수정하지 않는다. 검증은 별도 fixture/프로젝트를 사용한다.
- 항목별 원본과 현재 연결을 증명하며, 정지 화면이나 순수 helper만으로 실제 조작·저장 완료라고 보고하지 않는다.
