# 보드 자동 저장 및 객체·속성 단위 동기화

작성일: 2026-09-15
상태: 합의 사항 및 구현 기술 기준안 문서화 완료 / 구현 시작 전

확정 사항은 저장 버튼 제거, 편집 확정 시 자동 저장, 객체·속성 단위 동기화, 동일 속성의 마지막 서버 승인 우선, 삭제 우선, 오프라인 로컬 보관 및 재접속 시 충돌 없는 작업만 자동 반영하는 정책이다. 구체적인 기술 선택·프로토콜·구현 단계는 이를 실현하기 위한 기준안이며, 추가 확정이 필요한 항목은 11절에 구분했다.

## 1. 목표

여러 사용자가 같은 보드를 편집할 때 저장 버튼이나 일반적인 충돌 안내창 없이 작업을 이어갈 수 있도록 한다. 변경은 먼저 내 화면에 반영하고, 편집 동작이 확정되면 자동 저장한다. 서버가 승인한 변경은 WebSocket으로 다른 참여자에게 전달한다.

문서 전체를 새로 불러오거나 덮어쓰지 않고 변경한 객체와 속성에만 반영한다. 다른 사람의 변경을 받아도 내 입력, 커서, 선택과 화면 위치를 가능한 한 유지한다. 연결이 끊겨도 작업을 로컬에 보존하고 안전하게 복구한다.

이번 요청은 결정 사항과 기술·목표의 문서화다. 런타임 코드 변경, 패키지 설치, DB 변경 및 동기화 기능 구현은 진행하지 않는다.

## 2. 합의한 제품 동작

### 저장 버튼 제거 및 자동 저장

| 편집 동작 | 자동 저장·공유 시점 |
| --- | --- |
| 카드 이동·크기 조절·관계선 조절 | 드래그를 놓았을 때 |
| 이름·업무 설명·comment 입력 | 약 500ms 입력이 멈추거나 입력칸을 벗어났을 때 |
| 색상·타입·NULL 등의 선택 | 선택을 확정한 즉시 |
| 컬럼 순서 변경 | 드롭한 즉시 |
| 객체 생성·삭제·관계 생성 | 동작 확정 즉시 |
| 핀·답글 | 전송 즉시 |

500ms는 초기 기본값이며 사용성 검증으로 조정할 수 있다. 한글 IME 조합 중에는 전송하지 않는다. 입력 조건을 충족하지 못한 중간값은 로컬 초안으로 유지하고 해당 입력 위치에서 상태를 표시한다. 조합 종료·blur·debounce가 겹쳐도 같은 변경을 중복 생성하지 않는다.

상단 저장 버튼은 작은 동기화 상태 표시로 대체한다. 서버 확인을 받은 경우에만 동기화됨으로 표시한다. 전송 중, 연결 끊김, 복구 대기 상태를 구분하며 일반적인 다른 사용자 변경 때문에 모달을 띄우지 않는다.

### 공유 대상과 개인 상태

| 공유할 내용 | 개인별 유지할 내용 |
| --- | --- |
| 도메인·테이블·컬럼·키·관계·ENUM의 설계 속성 | 줌·화면 이동·현재 열린 도메인 |
| 카드 위치·크기, 관계선 배치 | 선택 객체·편집 초점·텍스트 커서 |
| 카드의 NULL/comment 표시 설정 | 사이드바 너비·열림 상태·탭 선택 |
| 컬럼 순서, 핀·답글 | 도메인 뷰 체크 상태·표시할 도메인 선택 |

테이블 원본 배치와 도메인 간 관계는 공유한다. 개인 도메인 뷰는 공유 원본 배치에서 파생해 표시하며, 개인 뷰 선택 때문에 다른 사람의 화면이 전환되지 않도록 한다. 개인 조합뷰에서의 카드 이동·관계선 조절을 원본 배치에 반영할지 별도 배치로 둘지는 구현 전에 확정할 세부사항이다.

## 3. 변경과 원자적 작업 단위

객체는 기존 고유 ID로 식별한다. 배열 인덱스나 이름으로 변경 대상을 찾지 않는다.

| 대상 | 변경 단위 |
| --- | --- |
| 도메인 | 이름, 업무 설명, 색상 |
| 테이블 | 이름, 위치, 크기, 표시 설정 |
| 컬럼 | 이름, 타입 설정, NULL 허용, comment |
| 컬럼 순서 | 컬럼 ID와 기준 컬럼 ID를 사용하는 이동 명령 |
| 키·관계 | 생성·삭제·정의 변경, 관계선 경로 |
| ENUM | 생성·삭제, 이름, 값 목록 |

함께 의미를 갖는 속성은 한 단위로 취급한다.

- 위치의 x·y, 크기의 width·height.
- 타입 이름·배열 여부·길이·정밀도·소수 자릿수·ENUM 참조.
- 복합 키의 컬럼 ID 목록과 순서, 복합 FK의 대응 컬럼 목록.
- FK 컬럼 자동 추가와 관계 생성.
- 객체 삭제와 이에 종속된 키·관계·참조 정리.

저장 버튼 단위의 큰 묶음 대신 사용자 동작 단위로 트랜잭션을 구성한다. 의존성이 있는 한 묶음은 전부 성공하거나 전부 실패한다. 독립적인 다른 작업 묶음은 별도로 진행할 수 있다.

## 4. 온라인 충돌 규칙

- 서로 다른 객체 또는 서로 다른 속성의 변경은 모두 반영한다.
- 같은 객체의 같은 속성 묶음은 서버가 마지막으로 승인한 편집을 최종 값으로 사용한다. 클라이언트 시계는 우선순위 기준으로 사용하지 않는다.
- 텍스트는 초기 범위에서 필드 전체를 하나의 값으로 취급한다. 글자 단위 병합은 도입하지 않는다.
- 내가 입력 중이거나 서버 확인을 기다리는 동일 속성이 있으면 내 화면에는 로컬 값을 유지한다. 수신한 서버 값은 확인된 기준 상태에 반영하고 로컬 변경을 그 위에 재적용한다.
- 미확인 로컬 변경은 해당 작업의 서버 확인을 받았을 때만 제거한다. 뒤이어 입력한 변경까지 함께 지우지 않는다.
- 객체 삭제는 해당 객체에 대한 수정보다 우선한다. 뒤늦게 도착한 수정이 삭제된 객체를 자동으로 부활시키지 않는다.
- 삭제로 적용하지 못한 내 편집은 로컬 복구함에 보존한다. 명시적으로 복구할 때는 새 ID를 가진 객체로 생성하고 키·관계도 다시 검증한다.
- PK·FK·ENUM 참조 등 구조적 조건을 만족하지 못하면 해당 작업 묶음을 원자적으로 거부한다. 화면 전체를 막는 대신 해당 편집 위치에 오류를 표시하고 초안을 보존한다.

마지막 승인 우선은 동일 속성의 모든 의도를 동시에 보존한다는 뜻이 아니다. 이전 값과 변경 주체를 이력에 남겨 사후 확인·복구할 수 있게 한다.

## 5. 연결 끊김과 재접속 — 합의한 보호 정책

연결이 끊겨도 편집은 계속 허용한다. 미전송·미확인 작업과 복구 대기 작업을 IndexedDB에 보관한다. 페이지 새로고침이나 브라우저 종료 후에도 복원할 수 있도록 한다.

재접속 시 흐름:

1. 최신 서버 상태 또는 누락된 변경 기록을 받는다.
2. 이미 서버에 적용된 작업 ID를 확인해 중복 전송·적용을 방지한다.
3. 오프라인 작업이 기준으로 삼은 객체·속성 버전과 최신 버전을 비교한다.
4. 해당 속성과 구조적 의존성이 바뀌지 않은 작업 묶음만 자동 반영한다.
5. 다른 사람이 변경했거나 삭제한 대상과 충돌하는 묶음은 덮어쓰지 않고 복구함으로 보낸다.

독립 작업끼리는 일부가 적용되고 일부가 복구함에 남을 수 있지만, FK 생성 같은 한 원자적 묶음 내부를 쪼개 적용하지 않는다. 확인 메시지만 유실된 경우에는 기존 작업 ID로 서버의 처리 결과를 재조회하며 이미 성공한 작업을 새 작업으로 다시 제출하지 않는다.

정상 온라인 편집의 마지막 승인 우선 규칙과, 재접속 시 오래된 작업을 보호하는 조건부 적용 규칙을 구분한다. 이 구분과 기준 버전 검사는 서버에서도 검증할 수 있어야 한다.

복구함은 비차단 UI로 제공한다. 충돌한 작업이 존재한다는 상태는 알리되 매번 선택을 요구하는 모달을 띄우지 않는다. 저장 공간 부족·권한 만료 등 작업 보존이 보장되지 않는 경우까지 조용히 숨기지는 않는다.

## 6. 실행 취소와 변경 이력

현재 문서 전체 스냅샷 기반 Ctrl+Z를 사용자 작업 단위의 실행 취소로 변경한다.

- 아직 전송되지 않은 내 변경은 로컬 대기열에서 취소하거나 축약한다.
- 이미 서버가 승인한 내 작업은 보상 작업으로 되돌린다.
- 이후 다른 사람이 수정한 속성을 과거 값으로 덮어쓰지 않는다. 현재 속성 버전과 의존성을 확인한다.
- 독립적으로 되돌릴 수 있는 작업만 처리하고, 원자적 작업 묶음은 부분적으로 되돌리지 않는다.
- 되돌리지 못한 내용은 이력·복구함에서 확인할 수 있게 한다.
- 원격 변경 수신을 내 실행 취소 이력에 넣지 않는다. redo도 다른 사람의 후속 변경을 보호한다.

## 7. 사용할 기술과 역할

아래는 합의한 동작을 구현하기 위한 기술 기준안이다. 제품 동작은 위 합의 사항을 따르며 세부 라이브러리 버전은 구현 시작 시 호환성을 확인해 고정한다.

| 기술 | 역할 |
| --- | --- |
| 기존 React·TypeScript | 즉시 화면 반영, 확인된 서버 상태와 로컬 대기 변경의 분리, 속성별 재적용 |
| 기존 NestJS | 프로젝트별 변경 검증·순서 확정·접근 확인·저장 처리 |
| WebSocket + 서버 ws 라이브러리 | 프로젝트 채널의 변경·확인·재접속 메시지 전달. 브라우저는 기본 WebSocket API 사용 |
| 기존 REST API | 최초 문서 조회, 스냅샷 재동기화, 기존 사용자·프로젝트 API 유지 |
| 기존 PostgreSQL JSONB + Drizzle | 현재 보드 상태, 변경 순서·이력·작업 ID·삭제 표식·속성 버전의 영속 관리 |
| 기존 Zod 계약 | 변경 명령·서버 이벤트·확인 응답·복구 요청 검증 |
| IndexedDB | 사용자·프로젝트별 로컬 초안, 전송 대기열, 복구함 저장 |
| Vitest + 실제 PostgreSQL 통합 테스트 + 브라우저 테스트 | 병합·경합·재접속·실행 취소·여러 세션의 화면 일관성 검증 |

초기 병합 방식은 서버가 순서를 정하는 객체·속성 단위 변경 명령과 로컬 재적용이다. Yjs·Automerge·OT를 초기 필수 의존성으로 추가하지 않는다. 긴 텍스트의 글자 단위 공동 편집이 필요해질 때 해당 필드에 한정한 CRDT 도입을 다시 검토한다.

초기 서버는 단일 인스턴스를 기준으로 한다. 여러 서버로 확장할 때는 PostgreSQL 변경 알림 또는 공유 메시지 계층이 추가로 필요하다. Redis를 초기 필수 구성으로 두지는 않는다.

## 8. 프로토콜·저장 구조 기준안

변경 요청에는 최소한 다음 정보가 필요하다.

- projectId, 안정적인 operationId, clientId와 사용자 동작 묶음 ID.
- 서버가 확인한 사용자 세션 및 변경 주체.
- 기준 프로젝트 순서와 변경 대상 속성의 기준 버전.
- 객체 ID, 변경 명령 종류, 변경 값과 구조적 선행 조건.

서버는 프로젝트별 순서를 부여하고 검증·현재 상태 반영·이력 기록·중복 방지 결과 저장을 같은 트랜잭션에서 처리한다. 커밋 이후에만 확인 응답과 WebSocket 이벤트를 전달한다. 저장 실패를 성공 이벤트로 보내지 않는다.

커밋 이후 이벤트 전송이 실패하더라도 변경 기록과 마지막 수신 순서를 이용해 복구할 수 있게 한다. 서버 재시작·이벤트 유실·순서 누락에는 재조회/재동기화 경로를 제공한다. 기록 보존 범위를 벗어난 클라이언트는 최신 스냅샷을 받고 로컬 대기 작업을 보호 정책에 따라 다시 평가한다.

객체 삭제 표식과 속성별 마지막 변경 버전을 관리해 오래된 수정의 부활을 막는다. 중복 operationId는 동일한 저장 결과를 반환하며 같은 작업을 다시 수행하지 않는다. 동일 ID의 다른 요청 내용은 거부한다.

현재의 보드 전체 PUT과 객체 단위 변경 처리가 동시에 전체 문서를 덮어쓰는 두 개의 쓰기 경로로 남지 않도록 전환한다. 핀·답글의 기존 API도 저장 성공 이후 이벤트를 발행하는 흐름에 맞춘다.

사용자 ID만 클라이언트가 임의로 전달한 값을 변경 주체로 신뢰하지 않도록 현재 이름/PIN 접속을 서버 발급 세션과 연결한다. 구체적인 세션 방식과 프로젝트 역할 정책은 별도 설계하되, 최소한 읽기/쓰기 및 보관·삭제 상태의 검사는 모든 쓰기 경로에서 일관되게 수행한다.

## 9. 구현 단계

1. 변경 명령과 원자적 묶음, 속성 버전, 삭제·이동·실행 취소 규칙을 순수 모델과 테스트로 정리한다.
2. 서버의 원자적 변경 처리·중복 방지·변경 기록과 프로젝트별 WebSocket 채널을 구현한다.
3. 클라이언트의 서버 기준 상태·낙관적 편집·확인 대기열을 분리하고 자동 저장 타이밍을 연결한다.
4. IndexedDB 보존과 재접속 재동기화·복구함을 구현한다.
5. 사용자 작업 단위 undo/redo, 개인 화면 상태 분리, 핀·답글의 이벤트 반영을 통합한다.
6. 여러 실제 브라우저 세션에서 네트워크 지연·단절·동시 수정·삭제 경합을 검증한다.

UI는 Astra가 담당한다. 중요한 저장·병합 정합성은 주 에이전트가 직접 검토하고, 독립 영역은 서브에이전트로 분담한다. 테스트를 먼저 추가하고 논리적 작업 단위마다 검증·작업 기록·커밋한다.

## 10. 완료 기준

- 저장 버튼 없이 각 편집 동작이 정해진 시점에 자동 저장되고 다른 참여자에게 반영된다.
- 서로 다른 객체·속성의 동시 변경이 모두 유지된다.
- 동일 속성의 최종 서버 값은 참여자에게 일치하며 내 입력 중 커서나 값이 불필요하게 튀지 않는다.
- 관계 생성/삭제 등 원자적 작업의 일부만 저장되는 상태가 없다.
- 삭제된 객체가 늦게 도착한 변경으로 부활하지 않는다.
- 오프라인에서 저장한 초안이 새로고침 후에도 복원되고, 상대가 수정한 속성을 재접속 시 조용히 덮어쓰지 않는다.
- 확인 응답 유실·중복 전송·서버 재시작 후에도 작업이 중복 생성되지 않고 최신 상태로 복구된다.
- 실행 취소가 다른 사람의 후속 수정을 덮어쓰지 않는다.
- 원격 변경으로 개인 줌·선택·사이드바·도메인 뷰 체크 상태가 바뀌지 않는다.
- 일반적인 동시 편집이나 재접속 때문에 충돌 선택 모달이 반복되지 않는다.
- 기존 문서·컬럼 순서·PK/FK·ENUM·핀·이미지 내보내기 기능의 회귀가 없다.

## 11. 추가로 정할 세부사항

합의된 규칙을 바꾸지 않는 범위에서 구현 전에 다음을 구체화한다.

- 개인 도메인 조합뷰에서 배치 편집을 허용할 범위와 공유 원본 좌표로의 매핑.
- 서버 변경 이력·삭제 표식·중복 요청 결과·로컬 복구함의 보존 기간과 용량.
- 객체 복구 시 종속 관계의 복원 범위와 복구함 상세 UI.
- 세션 발급·갱신 방식과 프로젝트 접근 역할.
- 예상 동시 사용자·보드 크기·네트워크 조건 및 이를 기준으로 한 지연·메모리 검증 수치.
