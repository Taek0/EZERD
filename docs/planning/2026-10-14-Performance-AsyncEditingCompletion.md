# 비동기 저장 및 로컬 편집 확장 계획

1. 저장 큐의 로컬 투영을 컬럼 속성, 테이블 속성, 객체 삭제, 관계 생성·수정으로 확장한다. 서버와 동일한 모델 삭제·타입·관계 규칙을 사용하며 실패한 배치는 부분 적용하지 않는다.
2. 오프라인·재시작·거절·리비전 변경·중복 ACK를 검증한다. 원본 요청과 복구 기록을 보존하고 실제 저장 완료와 로컬 표시 상태를 구분한다.
3. 연속된 ACK에 변경 집합을 적용하는 선택적 경량 응답을 추가한다. 구형 응답과 순서 누락은 기존 전체 문서/재조회 경로로 복구한다. 서버 변경 버전 기록은 일괄 저장한다.
4. 삭제 이후에도 동일 ID의 객체 참조를 유지하도록 ACK 구조 공유를 개선한다. 기존 UI/애니메이션과 캔버스 world 합성 설정을 유지한다.
5. 성능 워크트리에서 회귀·측정 후 제품 커밋을 로컬 main에 통합하고 전체 검사 및 원격 동기화 확인 후 push한다. 계측 자료는 lab에 보관한다.

완료 기준: 지원 편집이 ACK 전에 표시되고, 저장 실패가 입력 유실로 이어지지 않으며, 연속 경량 ACK와 전체 ACK의 결과가 같고, 실제 측정 결과와 검증 한계를 기록한다.
