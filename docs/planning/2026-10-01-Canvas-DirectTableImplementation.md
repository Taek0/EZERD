# 전체 테이블 캔버스와 테이블 색상 구현 계획

## 범위

[설계 제안](2026-09-30-Canvas-DirectTableMode.md)에 따라 도메인 없는 테이블 생성과 전체 테이블 캔버스, 도메인 지정·해제, 테이블별 공유 색상을 구현한다. 도메인 생성 후 테이블을 작성하는 기존 흐름도 유지한다.

## 구현 정책

- 도메인 미소속은 `domainId: null`로 표현한다. 기존 문자열 소속은 유지한다.
- 전체 캔버스는 예약 ID `__tables__`를 사용한다. 기존 `overview`는 도메인 맵이다.
- 테이블·컬럼·키·관계는 같은 ID를 유지하고, 전체/도메인 화면의 배치는 독립적이다.
- `Table.color`는 선택적인 HEX 공유 속성이다. 표시 우선순위는 테이블 색상, 도메인 색상, 중립 색상이다.
- 빈 프로젝트는 전체 캔버스로 진입하고 기존 도메인 프로젝트는 도메인 맵 진입을 유지한다. 사용자가 두 화면을 자유롭게 선택할 수 있다.
- 기존 문서는 문자열 도메인과 기존 배치를 계속 수용한다. 전체 배치 정규화는 결정적으로 수행하고 동기화 후보 검증과 저장이 같은 기준을 사용하도록 연결한다.
- 문서 버전 1의 추가 필드·허용값으로 확장한다. 서버와 웹을 함께 배포하는 것이 지원 경계이며 구버전 클라이언트는 새 nullable 소속을 지원하지 않는다.

## 작업 단위

1. 모델·계약: 선택 소속, 전체 배치, 색상 검증, 기존 문서 호환, 회귀 테스트.
2. 서버·MCP: 전체 뷰와 미소속 테이블, 공유 저장·개인 viewport, 파일 입출력·동기화 대응.
3. 웹: 캔버스 이동·직접 생성·도메인 지정/해제·색상 선택, 복사/붙여넣기와 관계 표시 통합.
4. 통합 검증: 포맷, 타입 검사, 단위 테스트, 빌드와 가능하면 브라우저 주요 작업 흐름 확인.

서로 겹치지 않는 서버와 웹 작업을 `gpt-6.1-sol` high 서브에이전트로 병렬 진행하고 모델과 통합은 주 작업에서 맡는다. 각 논리 단위의 결과는 work-log에 기록하고 커밋한다.

## 변경 경계

- 기존 Notion 포트폴리오 문서는 수정하거나 커밋하지 않는다.
- `docs/EZERD.txt`는 수정하지 않는다.
- 운영 데이터 이관·배포·push는 이번 범위에 포함하지 않는다.

## 구현 상태

모델·계약·서버·웹 구현을 완료하고 단위 테스트, 실제 PostgreSQL·HTTP와 브라우저 작업 흐름을 검증했다. 상세 결과와 지원 경계는 [완료 기록](../work-log/2026-10-01-Canvas-DirectTableCompletion.md)을 참조한다.
