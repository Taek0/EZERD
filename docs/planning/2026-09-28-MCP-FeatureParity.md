# MCP 편집 기능 보강 계획

## 목표

웹 앱의 ERD 편집·관리 기능 중 MCP에서 빠진 기능을 순차적으로 제공한다. 기존 `apply_project_changes`의 원자적 변경, 최신 버전·동기화 순서 검사, 작업 ID 재시도 및 작업자 기록을 그대로 사용한다.

## 구현 순서

1. `apply_project_changes`에 결합 화면과 ENUM의 생성·수정·삭제 명령을 추가한다. 기존 모델 함수를 재사용해 참조 무결성과 연쇄 삭제 규칙을 유지한다.
2. 노드 배치 변경, 화면 위치·확대율, 테이블 참조 추가·제거, 관계선 경로 설정·삭제 명령을 추가한다. 객체 자체와 화면상의 참조를 구분하고 노드 ID로 특정 배치를 수정한다.
3. 도메인·테이블·컬럼·노트·관계·키·결합 화면·ENUM의 부분 수정 명령을 추가한다. 필드별 엄격한 스키마를 사용하고 기존 모델의 수정 함수를 거쳐 검증한다. 변경 대상이 없으면 생성하지 않는다.
4. MCP 진단에 같은 화면의 카드 겹침과 40px 미만 간격을 추가한다. 카드 내용 잘림은 서버에서 글꼴 렌더링을 재현할 수 없으므로 명확히 계산 가능한 최소 크기 위반만 진단하고, 결과를 자동 수정·쓰기 거부의 조건으로 사용하지 않는다.
5. 프로젝트·리뷰 목록에 페이지네이션을 제공하고 리뷰 목록과 답글 상세를 분리한다. `get_project_view`에는 화면 배치 전체가 필요한 작업을 위해 기존 출력을 유지하되 경량 메타데이터 조회와 부분 상세 옵션을 검토한다. 동시 변경을 감지할 수 있도록 버전과 커서를 반환한다.
6. 프로젝트 가져오기·내보내기와 개인 알림 조회·읽음 상태 변경을 MCP 도구로 제공한다. 이미 검증된 서비스와 토큰 작업자 신원을 사용한다.

## 주요 계약

- 기존 명령과 전체 조회 도구는 유지한다. 새 입력은 `type`으로 구분되는 엄격한 명령 스키마를 사용한다.
- 배치 변경은 `nodeId`와 좌표·크기 패치를 받는다. 참조 추가에는 `tableId`, `viewId`, 위치를, 참조 삭제에는 `nodeId`를 사용한다.
- 관계선 경로는 기존 `relationLayoutSchema`를 사용한다. 삭제는 해당 화면·관계 쌍의 경로만 제거한다.
- 부분 수정은 필드별 허용 속성만 받고 최소 한 필드가 필요하다. 중첩 속성은 필요한 단위로만 교체하며, ID·소유 ID는 임의 변경하지 않는다.
- 목록 응답은 기본 50건, 최대 100건으로 제한한다. 정렬 키와 커서 비교 규칙을 일치시킨다.
- 가져오기는 문서 계약과 구조 진단을 통과해야 한다. 알림 조회·변경은 인증 사용자 자신의 항목으로 제한한다.

## 검증

- 명령별 성공·잘못된 참조·동시성·재시도·작업자 경계 테스트를 추가한다.
- 실제 MCP HTTP 및 격리 PostgreSQL 통합에서 새 도구와 변경 명령을 확인한다.
- Prettier, 타입 검사, 단위·통합 테스트를 수행하고 기능 단위마다 작업 기록과 커밋을 남긴다.
