# 고스트 드래그·Worker 드롭 구현 계획

[검증 결과](https://github.com/Taek0/EZERD/blob/6bd481f/docs/work-log/2026-10-27-Canvas-GhostDragValidationResult.md)에 따라 성능 워크트리에 제품 연결을 구현한다.

- 테이블 카드 포인터 드래그에서는 원본 위치/관계선·문서를 유지하고 단순 고스트만 RAF로 이동한다. 다중 선택의 상대 위치·줌·잡은 위치·기존 저장 한도를 유지한다.
- release의 마지막 좌표로 순수 장면 라우팅 입력을 준비하고 Worker에서 기존 일반 경로 알고리즘을 실행한다. 고비용 관계선 자동 정리 알고리즘은 호출하지 않는다.
- Worker 계산 동안 마지막 고스트와 진행/취소 표시를 유지한다. 준비된 geometry를 재사용해 메인 스레드에서 동일한 경로를 다시 계산하지 않고 최종 카드/관계선을 교체한다.
- 저장은 최종 placements/commands를 직접 사용해 기존 로컬 초안·비동기 저장·한 번 실행 취소·실패 복구를 유지한다. 서버 ACK 대기 때문에 고스트를 불필요하게 유지하지 않는다.
- scope/사용자/뷰/관련 문서 변경·권한 회수·Escape·capture 취소·unmount는 Worker와 프리뷰를 정리하며 오래된 결과를 저장하지 않는다. drop의 의도적 capture 해제는 계산을 취소하지 않는다.
- 키보드 이동·리사이즈·도메인 배치는 기존 동작을 유지한다. world 강제 GPU 승격은 추가하지 않는다.

순수 장면 준비/라우팅 분리와 UI 통합을 파일별로 병렬 진행하고 루트에서 검토 후 단위 커밋한다. 기존 장면과 Worker 결과 동등성, 실 React 드래그/취소/저장 회귀, version407 복제본 및 전체 검사·제품 빌드로 검증한다. 실제 문서와 main 서버는 변경하지 않는다.
