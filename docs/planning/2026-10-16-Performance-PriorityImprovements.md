# 성능 우선 개선 계획

기준: origin/main f318b8e를 performance-lab에 병합한 3ca3357. 정적 조사 결과는 2026-10-16-Quality-CodebaseAudit.md를 참조한다.

## 범위와 우선순위

1. 캔버스 그룹 이동의 중복 scene 계산 제거와 위치 변경 간 콘텐츠 치수 재사용.
2. DB 검증의 테이블별 컬럼·키 인덱스 재사용. 진단 결과와 기존 오류 허용 규칙 보존.
3. 갤러리 목록의 전체 문서 전송·가공 축소. 접근 권한과 미리보기 정확성 보존.
4. 댓글 목록의 N+1 조회 제거 및 불필요한 문서 로딩 축소. API 의미와 순서 보존.
5. 인증 세션 lastSeenAt 쓰기 빈도 제한. 매 요청 만료·폐기 확인 유지.

각 영역을 독립 파일 소유권으로 병렬 구현한다. 서버·모델은 6.1 Sol high, UI는 Astra low를 사용한다. 에이전트는 직접 커밋하지 않고 루트에서 범위 확인 후 단위별 커밋한다.

## 검증

행동 불변성과 쿼리/계산 횟수 회귀 테스트를 우선한다. 영역별 테스트 후 전체 형식·타입·테스트·제품 빌드를 확인한다. 측정하지 않은 지연 개선 수치를 주장하지 않는다. 원본 문서와 실행 중인 main 서버는 수정하지 않는다.

## 제외

미사용 코드·의존성 삭제, 일반 드래그 라우팅 예산 재설계, 저장 프로토콜 변경은 이번 단위에 포함하지 않는다. 결과와 한계는 work-log에 기록한다.

## 갤러리 방식 확정

SQL에서 미리보기를 추출하는 실험은 큰 문서에서 DB 처리 비용 증가가 측정되어 채택하지 않았다. 현재 멤버십과 프로젝트 head를 매번 조회하고, head가 동일한 미리보기만 제한된 캐시에서 재사용한다. cache miss는 같은 repeatable-read/read-only snapshot 안에서 16개씩 문서를 읽는다. 캐시는 미리보기만 최대 256개·직렬화 크기 1MiB로 제한하며 버전·sequence·DB context가 바뀌면 재계산한다. 스키마 변경은 없다. 첫 조회와 캐시 적중 조회의 비용을 구분해 검증한다.
