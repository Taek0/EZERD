# 캔버스 저장 충돌 복구 UX 개선안

## 확인한 현재 동작

- `NativeProjectView`는 durable 대기 요청이 있거나 복구 중이면 `editorBusy`를 전체 편집기에 전달한다.
- `확인 필요`는 실제 충돌 외에도 응답 미확인, 저장 오류, 로컬 저장소 상태 미확인을 포함한다.
- 거부된 요청도 입력 보존과 안전한 복구를 위해 유지된다. 따라서 안내만 보고 원인과 다음 행동을 알기 어렵다.

## 권장 방향

1. 저장 중 / 응답 확인 중 / 변경 충돌 / 로컬 저장소 오류를 구분하고 안내에서 복구 화면으로 바로 이동한다.
2. 응답 미확인은 기존 operationId로 결과를 자동 조회한다. 이미 전송한 요청의 ID와 본문은 변경하지 않는다.
3. 저장 전송은 직렬화하되 사용자 입력은 임시 변경으로 계속 보존한다. 미전송 상태의 동일 객체 이동만 마지막 위치로 합친다.
4. 최신 상태와 겹치지 않는 필드 변경은 검증 후 재적용한다. 같은 필드 충돌은 내 변경과 현재 값을 비교해 사용자가 선택한다.
5. 객체 삭제, 권한 변경, DB 종류·버전 변경처럼 재적용 안전성이 보장되지 않는 경우는 명시적인 해결 절차를 유지한다.

## 단계

- 먼저 상태별 안내, 결과 자동 확인, 복구 접근성을 개선한다.
- 다음 단계로 임시 입력과 전송 큐를 분리하고 영향받지 않은 객체의 편집을 허용한다.
- 현재 작업에서는 원인 분석과 제안만 수행한다. 전체 잠금을 단순 제거하거나 대기 요청을 자동 삭제하지 않는다.
