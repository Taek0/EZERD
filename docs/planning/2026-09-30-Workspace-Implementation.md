# 워크스페이스 구현 및 기존 프로젝트 이관 계획

## 확정 요구사항

- 로그인 사용자는 이름(최대 64자, 중복 허용)으로 UUID 공간을 생성한다. 공간과 최초 owner는 동일 트랜잭션에서 생성한다.
- 역할은 owner/editor/viewer다. 모든 멤버는 조회·내보내기·개인 상태 및 핀/댓글을 사용할 수 있다. active 공간에서 owner/editor는 프로젝트 생성·가져오기·설계 변경·프로젝트 보관/복원을 할 수 있다. 프로젝트 영구 삭제는 owner만 가능하다.
- archived 공간에서는 설계·프로젝트·리뷰·개인 상태 쓰기를 차단한다. owner는 공간 복원과 멤버/초대 관리를 계속할 수 있다. 공간 삭제는 프로젝트가 없어야 한다.
- 앱 내부 사용자명 초대와 수락/거절/취소/만료를 구현한다. 초대 수락 전에는 멤버십을 만들지 않는다. 외부 이메일은 발송하지 않는다.
- 공간 행 잠금을 통해 마지막 owner 제거/강등과 초대 수락을 직렬화한다. 쓰기 트랜잭션은 같은 공간 잠금과 권한 확인을 공유한다.
- REST, 모든 MCP, WebSocket 구독/전송 및 기존 연결에 권한 변경을 반영한다. 멘션과 알림은 프로젝트의 현재 공간 멤버로 제한한다.
- 사용자 삭제 API는 현재 제공되지 않는다. owner 멤버십은 NO ACTION으로 직접 사용자 삭제를 제한하고, 향후 계정 삭제는 소유권 이전 후 수행해야 한다.
- 화면 검증에서 계정 메뉴에 로그아웃이 없음을 확인했다. 다른 계정으로 초대를 확인/수락하는 정상 로그인 흐름을 위해 현재 세션 폐기 API와 한국어/영어 로그아웃 메뉴를 추가한다. 폐기된 세션의 실시간 연결도 종료하고 사용자별 미전송 큐는 보존한다.
- 공간/멤버/초대/이관 감사 이벤트를 기록한다. 기존 프로젝트 설계 히스토리와 개인 상태를 보존한다.

## 작업 분담과 검증

1. 공간 스키마, 계약, 초대 API, 공통 권한 서비스 및 마이그레이션을 구현한다.
2. 프로젝트/동기화/리뷰/개인 상태/MCP에 권한을 적용한다. UI는 Astra가 한국어/영어 및 기존 파란색 버튼 스타일을 유지한다.
3. 격리 PostgreSQL 데이터로 타 공간 접근, viewer 쓰기/리뷰, owner 동시성, 초대 중복 수락, 연결 취소 및 이관 보존을 검증한다.
4. 연결된 MCP 토큰의 소유자를 안전하게 확인하고 프로젝트 ID와 이름을 재검증한다. Edusync에 klassboard-backend, TY에 ezerd/monya를 재실행 가능한 트랜잭션으로 이관한다. DB 초기화, 전체 사용자 삭제 및 git push는 수행하지 않는다.
5. 논리적 단위별 결과를 work-log에 기록하고 커밋한다. Prettier, 타입 검사, 테스트, 빌드를 수행한다.
