# GitHub 보안·브랜치 관리 목록 작성 계획

- 목적: 사용자가 요청한 보안 기능과 main 보호 설정을 하나의 실행 목록으로 정리한다.
- 방법: 이전 점검의 저장소 상태와 GitHub 공식 문서를 기준으로 바로 적용할 설정, CI 준비 후 적용할 설정, 병합 운영 방식을 구분한다.
- 범위: 목록과 문서 인덱스만 작성한다. 실제 GitHub 설정 변경, workflow 구현, 원격 push는 수행하지 않는다.
- 보존: 폰트 유지·MIT 선택·내부 주소 정리 결정을 반영하고 다른 제품 작업과 `docs/EZERD.txt`를 수정하지 않는다.
- 검증: 새 문서와 관련 기록의 상대 링크·diff 공백을 확인하고 독립 커밋한다.
