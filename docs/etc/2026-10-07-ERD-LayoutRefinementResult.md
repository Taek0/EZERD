- 사용자 추가 피드백(세로로 긴 배치)을 반영한 최종 결과다. 중간 배치보다 최종 `balanced-*` 산출물을 기준으로 확인한다.

## 최종 배치

- 상단은 공간·인증·프로젝트, 하단은 리뷰·동기화로 구분했다.
- 각 업무 영역을 2~3열로 구성하고 메모 6개를 각 영역 옆으로 이동했다. 기존 도메인 노드와 메모도 함께 갱신하여 구형 배치가 남지 않게 했다.
- 부모 테이블은 각 업무 영역의 왼쪽, 종속 테이블은 오른쪽에 배치했다. 동기화 테이블은 같은 계층의 3열 묶음이다.
- 개인 결합 화면의 기존 17개 테이블 배치가 별도로 남아 있었음을 확인했다. 두 신규 테이블을 추가하고 19개 테이블과 28개 관계를 공유 화면과 같은 배치로 갱신했다. 화면 이름은 `전체 ERD · 업무별 계층`이다.
- 개인 결합 화면과 공유/도메인 화면의 카메라 위치·확대율을 새 좌표에 맞췄다.
- native 카드 크기와 실제 `relationGeometry` 렌더러로 검증했다. 공유 노드의 저장 크기만 비교했던 이전 검증을 보완했다.

- 도메인 검증은 해당 테이블과 기존 도메인 메모를 함께 포함한 보수적 검사다. native 도메인 필터의 메모 표시 정책 자체는 변경하지 않았다.
- 전체 관계를 한 화면에 유지하므로 영역 사이 직각 교차 20곳은 남는다. 동일 선분을 겹쳐 사용하는 구간과 도메인 내부 교차는 제거했다.
- 앱의 SVG 내보내기 렌더러로 전체/도메인 미리보기를 생성하고 브라우저에서 전체 및 프로젝트 영역을 시각 확인했다. 실제 서비스 UI에 접속한 검증은 아니다.
- 재조회한 공유·개인 상태에 대해 검증 스크립트 통과.
- `pnpm --filter @ezerd/model build` 통과. 별도 작업에서 공용 카드 계산 함수가 이동해 런타임 참조를 갱신하는 데 사용했다.
- `pnpm format:check`는 병행 작업의 `apps/server/src/mcp/mcp-server.ts` 형식 문제로 실패했다. 해당 파일은 이번 작업에서 수정하거나 커밋하지 않았다. 이번 작업의 문서/artifacts는 `.prettierignore` 대상이다.
- DB 스키마는 변경하지 않았다. `docs/EZERD.txt`도 수정하지 않았다.
