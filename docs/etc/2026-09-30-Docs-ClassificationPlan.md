# 문서 분류 정리 계획

- 제품 기능·코드 개선·QA·아이디어·설계 의사결정은 기존 planning/work-log에 유지한다.
- Git 작업, 로컬 도구 장애, 문서 정리, 외부 소개 자산, 제품을 이용한 예시 ERD 생성·배치 등 보조 작업은 docs/etc로 이동한다.
- 제품 개발 재현에 필요한 버전 기준·의존성 목록, 기능 검증이 포함된 환경 검증, 제품 호스팅 안내와 포맷 도구 도입은 기존 분류에 유지한다. Drizzle 학습 안내는 etc로 이동한다.
- 파일명만으로 판단하지 않는다. Docs 이름의 기능 아이디어·QA 문서와 Workspace ERD의 실제 기능 설계 문서는 유지한다.
- etc의 날짜 기반 기존 문서는 Plan/Result 접미사로 단계를 구분해 이름 충돌을 방지한다. 이동만 하는 기존 문서의 날짜와 본문은 보존하되 경로 참조는 갱신한다.
- AGENTS.md와 docs/README.md에 세 폴더의 기준·예시·혼합 문서 판단법을 기록한다.
- 이동 목록, 파일 수·내용 보존, 상대 링크와 이전 경로 잔존 여부, 포맷·diff 검사를 확인하고 결과를 etc에 기록한다.
- 진행 중인 캔버스 공유·내보내기 코드 및 계획은 수정하거나 커밋에 포함하지 않는다. docs/EZERD.txt는 수정하지 않는다.
