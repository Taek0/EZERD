# native 진행 커밋 원격 반영 계획

- 요청: 지금까지 진행된 작업을 원격 main에 push한다.
- 제품 기준점: `f5480bf7ce64906eb0f28c19a82cd72ab4b8706f`. 요청 시점의 로컬 main 전용 커밋은 38개다.
- 원격 기준점: `11bc472fb5e5c114187a9879df569b216938fccb`. 최신 fetch에서 원격 전용 커밋은 없으므로 이력 병합 없이 일반 push할 수 있다.
- 방법: 계획만 독립 커밋한 뒤 그 커밋의 격리 checkout에서 frozen lockfile 설치·예시 환경 준비·포맷/타입/테스트/빌드를 검증한다. 검증 결과와 실제 원격 HEAD 확인을 기록한다.
- 보존: 미커밋 테스트·진행 기록·QA 스크립트·증거 파일과 사용자 관리 `docs/EZERD.txt`는 이번 반영에 포함하지 않는다. 작업 중 새 제품 커밋은 별도 후속 대상으로 남긴다. force push와 기존 이력 재작성은 하지 않는다.
- 완료: 검증한 커밋과 결과 기록을 일반 push하고 원격 HEAD를 대조한다. 로컬 main이 계획 이후 그대로일 때만 문서 추가의 fast-forward로 맞추고 미커밋 작업을 보존한다.
- 검증 후 추가: 커밋된 validation.test.ts의 단일 들여쓰기 오류만 격리 checkout에서 Prettier로 정리하고 별도 커밋한다. 의미 변경이 없음을 whitespace-ignore diff로 검증한다. 다른 미커밋 변경은 포함하지 않는다.
