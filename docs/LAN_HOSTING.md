# 사내 Wi-Fi 호스팅

호스팅 PC에서 웹 화면과 API를 같은 포트로 제공합니다. username으로 입장하며 계정 인증과 역할 구분은 없습니다. 공유할 사내 네트워크에서 실행합니다.

## 실행

```powershell
pnpm setup
pnpm db:up
pnpm host:start
```

`host:start`는 빌드, DB 마이그레이션, LAN 서버 실행을 순서대로 수행합니다. 이미 빌드와 마이그레이션이 끝났으면 `pnpm host:serve`로 다시 실행합니다. 실행 중인 개발 API와 포트가 겹치면 먼저 종료하거나 `.env`의 `PORT`를 변경합니다. 기본 포트는 3001입니다. 터미널을 열어 두어야 하며 Ctrl+C로 종료합니다.

출력된 LAN candidate 중 실제 Wi-Fi 어댑터의 IPv4 주소를 사용합니다. VPN·가상 어댑터 주소도 출력될 수 있으므로 `ipconfig`에서 확인합니다. 다른 PC·태블릿에서 같은 Wi-Fi에 연결한 뒤 `http://호스팅PC주소:3001`을 엽니다. DHCP 주소가 바뀌면 새 주소를 공유합니다.

## 연결 확인

- 호스팅 PC에서 `http://localhost:3001/api/health/ready`가 ready인지 확인합니다.
- 다른 기기에서 서비스 주소를 열고 username을 설정하고 저장된 프로젝트를 확인합니다.
- 호스팅 PC에서는 열리지만 다른 기기에서 실패하면 사내 네트워크의 기기 간 접근 제한과 Windows 방화벽의 해당 TCP 포트 인바운드 허용을 관리자와 확인합니다. 실행 스크립트는 방화벽을 수정하지 않습니다.

개발 PostgreSQL 포트는 기존 Compose 설정대로 127.0.0.1에만 바인딩합니다. 브라우저는 웹/API 포트에만 접속합니다. `.env`와 `.data`는 웹 정적 파일 경로에 포함되지 않습니다.

## 데이터와 종료

프로젝트는 PostgreSQL의 `.data/postgres`에 저장됩니다. 댓글·답글·멘션 알림은 별도 테이블에 저장되어 설계 문서를 다시 저장해도 유지됩니다. 앱 종료는 DB 파일을 지우지 않습니다. 백업은 운영 절차에 맞게 PostgreSQL 도구로 별도로 수행합니다.

## 검증 범위

자동 통합 테스트는 실제 PostgreSQL을 사용하는 HTTP API, 정적 웹 페이지 제공, 댓글 분리 저장과 멘션 트랜잭션을 확인합니다. 호스팅 PC 자신의 LAN 주소로 접속하는 검사는 다른 Wi-Fi 기기에서 접속하는 검증을 대신하지 않습니다. 최종 Wi-Fi 접속 확인은 실제 다른 기기에서 수행해야 합니다.
